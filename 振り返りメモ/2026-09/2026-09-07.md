# while文の到達不能コード判定はdo-whileには効かない

## 何が起きるか

```java
while (false) {
    System.out.println("x");
}
```

これはコンパイルエラーになる。

```
エラー: この文に制御が移ることはありません
```

一方、次のコードは問題なくコンパイルでき、`x`が出力される。

```java
do {
    System.out.println("x");
} while (false);
```

同じ`false`という条件なのに、`while`と`do-while`とで結果が違う。

## なぜそうなるか

`while (false) { ... }`は、条件が最初からfalseと確定しているため、ループ本体が**絶対に一度も実行されない**。Javaの到達不能コード検出はこれをコンパイルエラーとして弾く。

`do { ... } while (false);`は構造が逆で、本体が条件判定より**先に最低1回実行される**。だからこの本体は「絶対に到達しないコード」ではなく、コンパイラは問題視しない。

さらに注意点として、この到達不能コードの判定は**演算子だけで構成された式**にしか適用されない。

```java
while ("a".equals("b")) {
    System.out.println("x");
}
System.out.println("done");
```

このコードは`"a".equals("b")`が人間には明らかに`false`だと分かるが、これは**メソッド呼び出し**を含む式なので、コンパイラの目には「値が確定していない式」として映る。到達不能コードとは判定されず、普通にコンパイル・実行できて`done`だけが出力される(ループ本体には一度も入らない)。

## ポイント

- 判定基準は「見た目で真偽が明らかかどうか」ではなく、言語仕様上の**コンパイル時定数式**に当てはまるかどうか
- `while(false)`はアウト、`do...while(false)`はセーフ、`while(メソッド呼び出しの結果)`(結果がfalse相当でも)はチェック対象外
