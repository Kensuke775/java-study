# TreeSetの重複判定はequals()ではなくcompareTo()で決まる

## 何が起きるか

`record`(`Client`)は`equals()`/`hashCode()`を全フィールドから自動生成してくれる。しかし`TreeSet`はこの自動生成された`equals()`を一切見ていない。あくまで`Comparable`(または渡した`Comparator`)の比較結果だけで重複を判定している。

```java
record Client(String name, int age) implements Comparable<Client> {
    @Override
    public int compareTo(Client o) {
        return this.name.compareTo(o.name); // 名前だけで比較
    }
}

Set<Client> set = new TreeSet<>();
set.add(new Client("Bob", 20));
set.add(new Client("Bob", 30));
set.add(new Client("Alice", 25));
System.out.println(set);
System.out.println(set.size());
```

`compareTo`を名前だけで比較する実装にすると、`("Bob", 20)`と`("Bob", 30)`は名前が同じなので比較結果が`0`になり、**後から追加した方は「既存要素と等しい」とみなされて弾かれる**。`size()`は`2`。

`compareTo`を年齢だけで比較する実装(`this.age - o.age`)に変えると、3人とも年齢が違うので誰も重複せず`size()`は`3`になり、年齢の昇順で並ぶ。

## ポイント

- `equals()`が「全フィールド一致で真」と定義されていても、`TreeSet`にとってはノータッチ
- `TreeSet`の世界における「同じ要素」の定義は、常に`compareTo()`(または`Comparator`)が`0`を返すかどうかだけ
- `HashSet`(`equals()`/`hashCode()`ベース)と`TreeSet`(`compareTo()`ベース)とで、重複判定の基準そのものが違うという対比が重要
