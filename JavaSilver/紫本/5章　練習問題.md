### 5-1：final だけ初期化が必要か

メンバ変数については、その通りです。


| 種類                               | 初期化しないと                                                 |
| -------------------------------- | ------------------------------------------------------- |
| finalでないフィールド                    | デフォルト値が入るのでOK（`int` は0、参照型は `null`、`boolean` は `false`） |
| finalのフィールド（`static` でもインスタンスでも） | コンパイルエラー                                                |
| ローカル変数（finalかどうかに関係なく）           | 使う時点でコンパイルエラー                                           |


- **finalでないフィールド**：`public static long value;` はコンパイルが通ります。実行結果は `0 null false 0` でした。
- **finalのフィールド**：エラーは「変数valueは、デフォルト・コンストラクタで初期化されていません」です。`static { value = 1L; }` を書けば通ります。インスタンスのfinalなら、コンストラクタで代入します。
- **ローカル変数**：`int n; System.out.println(n);` は「変数nは初期化されていない可能性があります」でエラーになります。宣言だけして使わなければOKで、後から `n = 3;` と代入するのもOKです。

3行目の `var num2 = 10;` はフィールドでは使えず、「'var'はここでは許可されません」になります。

### 5-12：static に変えると `this.x` も static の x を指すか

はい。`this.x` は「このクラスのフィールド x」を指すので、static に変えれば static の x を指します。C に直したコードで `6:9` が出力されました。

- コンストラクタの引数 `x` がフィールドを隠しているので、`this.x` と書いてフィールドのほうを指定しています。
- static のフィールドはクラスに1つだけです。`new Main(1, 2)` のあとに `new Main(3, 4)` を作ると、どちらのインスタンスから見ても `3:4` になります。
- static のフィールドを `this.x` と書いてもコンパイルは通りますが、`-Xlint:static` を付けると「static 変数は式ではなく型名Mainで修飾する必要があります」という警告が出ます。本来は `Main.x = x;` と書きます（こちらも `6` が出力されました）。

### 5-14：引数なしで呼んだ `s.length` はどういう値を見て0になるのか

引数なしで `bar()` を呼ぶと、コンパイラが空の配列（`new String[0]`）を作って渡します。`s` は `null` ではなく、要素が0個の `String[]` を参照しています。`s.length` は、その配列の要素数の0です。

```
1    bar();

```

```
s == null : false
s.length  : 0
型        : String[]

```

`s` が `null` になるのは、`bar((String[]) null);` のように、自分で `null` を渡したときだけです。この場合は `s.length` の時点でNPEになります。
