### 問1

```java
 1: import java.io.IOException;
 2: class Loader {
 3:     String kind() {
 4:         return "base";
 5:     }
 6:     void load() {
 7:         System.out.println(kind());
 8:     }
 9: }
10: class FileLoader extends Loader {
11:     String kind() {
12:         return "file";
13:     }
14:     void load() throws IOException {
15:         System.out.println(kind());
16:     }
17: }
18: public class Main {
19:     public static void main(String[] args) {
20:         Loader l = new FileLoader();
21:         l.load();
22:     }
23: }
```

このプログラムをコンパイルして実行したときの結果はどれか。

- A. `base` と表示される
- B. `file` と表示される
- C. 行14 でコンパイルエラーになる
- D. 行21 でコンパイルエラーになる

<br><br><br><br><br>

**正解: D**

行14の `load()` は親の `void load()` をオーバーライドしようとしているが、`throws IOException` を追加している。オーバーライドで `throws` を広げることはNG（親が宣言していないチェック例外は追加できない）。これはコンパイルエラーになる。

さらに行21では `Loader` 型の参照 `l` から `load()` を呼んでいるが、`Loader.load()` は `throws` 宣言がないのでチェック例外を宣言しているメソッドは呼び出し側から見えない。

| 状況 | ルール |
|---|---|
| オーバーライドの `throws` | 親より広げてはNG |
| 参照型でのメソッド呼び出し | コンパイル時は参照型のシグネチャで判定 |

### 問2

```java
 1: class Clock {
 2:     static String region = "Asia";
 3:     static String label() {
 4:         return region + "/Tokyo";
 5:     }
 6: }
 7: public class Main {
 8:     public static void main(String[] args) {
 9:         Clock c = new Clock();
10:         c = null;
11:         System.out.println(c.label());
12:     }
13: }
```

- A. 行11 で NullPointerException がスローされる
- B. `null/Tokyo` と表示される
- C. 行11 でコンパイルエラーになる
- D. `Asia/Tokyo` と表示される

<br><br><br><br><br>

**正解: D**

`label()` は `static` メソッドなので、`c.label()` はコンパイラが `Clock.label()` に置き換える。`c` が `null` でも参照先をたどらないため NPE は起きない。`region` も `static` なのでクラス側の `"Asia"` が使われる。

| 呼び出し | null の扱い |
|---|---|
| `static` メソッド | NPE なし（型で解決） |
| インスタンスメソッド | NPE（参照先をたどる） |

### インターフェースの default と Object メソッド

`Object` が持つメソッド（`toString`, `equals`, `hashCode` など）はインターフェースの `default` で上書きできない（コンパイルエラー）。`abstract` 宣言はOK。

```java
interface Label {
    default String toString() { return "label"; }  // ❌ コンパイルエラー
    abstract String toString();                     // ✅ OK
    default String myLabel() { return "label"; }   // ✅ OK（Objectにないメソッド）
}
```

| メソッド | `default` | `abstract` |
|---|---|---|
| `toString()` / `equals()` / `hashCode()` | ❌ | ✅ |
| Object にないメソッド | ✅ | ✅ |

### オーバーロード解決の優先順位

同じメソッド名で複数の候補があるとき、以下の順で解決される：

| 優先度 | 変換の種類 | 例 |
|---|---|---|
| 1 | **拡大変換**（ボクシングなし） | `char → int`, `int → long` |
| 2 | **オートボクシング** | `char → Character`, `int → Integer` |
| 3 | **可変長引数** | `int...` |

```java
static void take(int v)       { System.out.println("int"); }
static void take(Character v) { System.out.println("Character"); }
static void take(Object v)    { System.out.println("Object"); }

char c = 'x';
take(c);  // → int（拡大変換が最優先。Characterはボクシング必要なので後回し）
```

### インポート優先順位とFQNアクセスのまとめ

同じ単純名のクラスが複数パッケージにある場合のアクセス方法：

```java
import draft.*;
import press.*;
import press.Note;  // 単一型インポートが優先される

public class Main {
    public static void main(String[] args) {
        Note n = new Note();           // press.Note（単一型インポートが勝つ）
        System.out.println(n.level);   // 2

        System.out.println(new draft.Note());  // FQNで別パッケージのクラスを使う
        press.Note pN = new press.Note();      // FQNで型宣言もできる
    }
}
```

| 書き方 | 解決されるクラス |
|---|---|
| `Note n` | `press.Note`（単一型インポート優先） |
| `new draft.Note()` | `draft.Note`（FQNで直接指定） |
| `press.Note pN` | `press.Note`（FQNで型宣言） |

- FQNでのインスタンス生成: `new パッケージ名.クラス名()`
- `draft.Note.new Note()` はNG（無効な文法）

### 問2

```
 1: public class Letters {
 2:     public static void main(String[] args) {
 3:         String word = "code";
 4:         int n = 0;
 5:         for (char c : word) {
 6:             n++;
 7:         }
 8:         System.out.println(n);
 9:     }
10: }
```

このプログラムをコンパイルして実行したときの結果として正しいものはどれですか。

- A. 行5 でコンパイルエラーになる
- B. 4 と出力される
- C. 0 と出力される
- D. 実行時に例外がスローされる

<br>
<br>
<br>
<br>
<br>

**正解: A**（回答: 不正解）

拡張forのコロンの右側に書けるのは**配列**か**`Iterable`を実装した型**（`List`など）だけ。`String`はどちらでもないので行5でコンパイルエラー（「for-eachは式のタイプに使用できません」）。JavaScriptの`for...of`は文字列を回せるが、Javaでは回せない。1文字ずつ扱いたいときは次のどちらか。

```java
for (char c : word.toCharArray()) { }          // 配列に変換して拡張for
for (int i = 0; i < word.length(); i++) {      // 配列にせず、普通のforとcharAt
    char c = word.charAt(i);
}
```

### 問3

```
 1: public class Report {
 2:     static String join(String... parts, String tail) {
 3:         String s = "";
 4:         for (String p : parts) {
 5:             s = s + p;
 6:         }
 7:         return s + tail;
 8:     }
 9: 
10:     public static void main(String[] args) {
11:         System.out.println(join("a", "b", "!"));
12:     }
13: }
```

このプログラムをコンパイルして実行した結果はどれか。

- A. 行2 で可変長引数の宣言が引数リストの最後になっていないため、コンパイルエラーになる
- B. `ab!` と表示される
- C. `abnull` と表示される
- D. 行11 で可変長引数に値を3個渡しているため、コンパイルエラーになる

<br>
<br>
<br>
<br>
<br>

**正解: A**（回答: 不正解）

可変長引数は**引数リストの最後に1つだけ**置ける。行2 は`String... parts`のうしろに`String tail`があるので、宣言の時点でコンパイルエラー。呼び出し側（行11）に問題はなく、可変長引数に渡せる個数に上限もない。`join(String tail, String... parts)`の順にすれば通る。

### 問4

```
 1: public class Printer {
 2:     static void show(Object v) {
 3:         System.out.println("Object");
 4:     }
 5: 
 6:     static void show(String v) {
 7:         System.out.println("String");
 8:     }
 9: 
10:     public static void main(String[] args) {
11:         Object o = "text";
12:         show(o);
13:         show("text");
14:     }
15: }
```

このプログラムをコンパイルして実行した結果はどれか。

- A. Object、String の順に表示される
- B. String、String の順に表示される
- C. Object、Object の順に表示される
- D. String、Object の順に表示される

<br>
<br>
<br>
<br>
<br>

**正解: A**（回答: B）

**オーバーロードはコンパイル時に、引数の変数の型（宣言された型）だけで選ばれる。** 行12 の`o`は実体が`"text"`でも宣言型は`Object`なので`show(Object)`、行13 は`String`なので`show(String)`。実体の型で切り替わるのは**オーバーライド**（実行時）の方で、オーバーロードは実体を見ない。コンパイラは実行前に呼ぶメソッドを決めるので、「変数に何が入っているか」はまだ分からず、宣言型しか手がかりがない。

| | 決まるタイミング | 何を見るか |
|---|---|---|
| オーバーロード | コンパイル時 | 変数の宣言型 |
| オーバーライド | 実行時 | 実体の型 |
