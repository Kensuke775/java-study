# ながら勉強 口頭問題 セット2（暗黙で付くものまとめ）

コードを見ずに、言葉だけで考える用。「〇〇には、暗黙で何が付くか」を答える形式。

---

## 問題1：interfaceのフィールド（定数）に暗黙で付くもの

`interface`の中に書いたフィールドには、何も書かなくても暗黙でどんな修飾子が付きますか？（3つ答えよ）

<details>
<summary>解答・解説</summary>

**`public static final`の3つ全部**

```java
interface Test {
    int COUNT = 10;   // 実質 public static final int COUNT = 10;
}
```

`final`が付くので、`COUNT++`のような再代入・インクリメント/デクリメント・複合代入演算子はすべてコンパイルエラーになる。

</details>

---

## 問題2：interfaceの本体のない（抽象）メソッドに暗黙で付くもの

`interface`の中に書いた、中身の無いメソッド（`void sample();`のような形）には、何が暗黙で付きますか？

<details>
<summary>解答・解説</summary>

**`public abstract`**

```java
interface Test {
    void sample();   // 実質 public abstract void sample();
}
```

</details>

---

## 問題3：interfaceのdefaultメソッド・staticメソッドに暗黙で付くもの

`interface`の中の`default`メソッドや`static`メソッドには、何が暗黙で付きますか？また、`default`・`static`というキーワード自体は省略できますか？

<details>
<summary>解答・解説</summary>

**暗黙で付くのは`public`だけ。`default`・`static`というキーワード自体は省略できない（自分で明示的に書く必要がある）。**

```java
interface Test {
    default void sample() { ... }   // 実質 public default void sample() { ... }
    static void calc() { ... }      // 実質 public static void calc() { ... }
}
```

抽象メソッドと違い、`default`／`static`は「暗黙で付く」側ではなく「書かないとただの抽象メソッドとして扱われてしまう（もしくはエラーになる）」ので要注意。

</details>

---

## 問題4：interfaceの中にネストしたクラス・インターフェースに暗黙で付くもの

`interface`の中に別の`class`や`interface`をネストして書いた場合、何が暗黙で付きますか？

<details>
<summary>解答・解説</summary>

**`public static`**

```java
interface Outer {
    class Inner {}   // 実質 public static class Inner {}
}
```

`static`が付くので、外側の`Outer`のインスタンスを作らなくても`new Outer.Inner()`のようにいきなりインスタンス化できる（検証済み：`static`が付いていないと、外側のインスタンス無しでは`new`できないはずだが、これは何もせずインスタンス化できた）。

</details>

---

## 問題5：recordのアクセサメソッドに暗黙で付くもの（record自体のアクセス修飾子とは無関係）

`record`のコンポーネントに対して自動生成される「アクセサメソッド」（例：`value()`）には、何が暗黙で付きますか？**record自体がpublicではなくpackage-privateだった場合、アクセサの修飾子はそれに合わせて変わりますか？**

<details>
<summary>解答・解説</summary>

**アクセサメソッドは常に`public`（record自体のアクセス修飾子とは無関係、合わせて変わらない）**

```java
record RecAcc(String value) {}   // recordはpublicなし（package-private）
```
```
// コンパイル後の実体（javapで確認）
final class RecAcc extends java.lang.Record {
    RecAcc(String);              // ← カノニカルコンストラクタはpackage-private（recordに合わせている）
    public String value();       // ← アクセサは常にpublic！
}
```

**ここが引っかけポイント**：カノニカルコンストラクタは「recordのアクセス修飾子と釣り合わせる」ルールがある（`public record`なら`public`必須）が、**アクセサメソッドは常に無条件で`public`**、という非対称な扱いになっている。

</details>

## まとめ表（このセットの検証結果）

| 対象 | 暗黙で付くもの |
|---|---|
| interfaceのフィールド | `public static final`（3つとも） |
| interfaceの抽象メソッド | `public abstract` |
| interfaceのdefault/staticメソッド | `public`のみ（`default`/`static`自体は明示必須） |
| interface内のネストクラス/インターフェース | `public static` |
| recordのアクセサメソッド | 常に`public`（recordのアクセス修飾子と無関係） |
| recordのカノニカルコンストラクタ | recordのアクセス修飾子と**釣り合う**もの（自動では変わらない） |
