## 問題1

`String literal = "java";`とした後、`String runtimeConcat = ja + va;`（`ja`・`va`は変数で、中身を連結すると`"java"`になる）とした場合、`literal == runtimeConcat`はどうなりますか？

<details><summary>解答</summary>

**`false`になります。**変数同士の`+`連結は実行時に評価されるため、コンパイラは値を事前に確定できず、常に新しいオブジェクトをヒープ上に生成します。結果の中身が定数プールの文字列と一致していても、無関係な別オブジェクトになります。

</details>

## 問題2

`String compileTimeConcat = "ja" + "va";`のように、リテラル同士を`+`で連結した場合、`"java"`という既存のリテラルと同一のオブジェクトになりますか？

<details><summary>解答</summary>

**同一になります。**両方がコンパイル時に値の確定している定数（リテラル）なので、コンパイラは実行を待たずにその場で`"java"`という1つのリテラルへ畳み込みます（定数畳み込み）。畳み込まれた結果は普通の文字列リテラルと同じ扱いになり、定数プール上の既存の`"java"`とそのまま同一視されます。

</details>

## 問題3

`String ja = "Ja"; String va = "va"; String result = ja + va;`とした場合、`result`の中身は`"java"`（すべて小文字）と一致しますか？

<details><summary>解答</summary>

**一致しません。**`result`の中身は`"Java"`（大文字J）になります。`String`は大文字小文字を区別するため、`"Java"`と`"java"`は`equals()`で比較しても`false`になる、完全に別の文字列です。

</details>

## 問題4

`String string = "java"; String ja = "ja"; String va = "va"; String concatBeforeIntern = ja + va; String java = concatBeforeIntern.intern();`という一連の処理で、`string == java`はどうなりますか？

<details><summary>解答</summary>

**`true`になります。**`intern()`は「その内容と同じ文字列が既に定数プールにあれば、新しいオブジェクトを作らず既存の参照を返す」動作です。`concatBeforeIntern`の中身`"java"`は、既に`string`の時点でプールに登録済みなので、`intern()`は新規生成せず`string`と同じ参照を返します。

</details>

## 問題5

問題4の状況で、`intern()`を呼ぶ**前**の`concatBeforeIntern`自体は、`string`と同じオブジェクトですか？

<details><summary>解答</summary>

**別オブジェクトです。**`ja + va`という実行時連結は、`intern()`を呼ぶより前の時点で、既に新しいヒープオブジェクトを生成してしまっています。`intern()`は「呼ばれた後に新規生成をしない」だけであって、呼ばれる前に既に作られてしまった一時オブジェクトの存在自体は無かったことになりません（GC対象になるだけです）。

</details>

**`false`になります。**`intern()`を呼んでいないため、`java`変数は`ja + va`の実行時連結で新しく作られたヒープオブジェクトをそのまま指します。中身が同じ`"java"`であっても、定数プール上の`string`とは別の実体のままです。

</details>

## 問題8

`int[][] c = new int[2][];`とした直後、`c[0]`や`c[1]`はどんな状態ですか？

<details><summary>解答</summary>

**両方とも`null`です。**外側の次元（要素数2）だけが確定し、内側の次元（各要素が指す`int[]`）は指定されていないため、各要素は「`int[]`型への参照」としてまだ何も指していない状態＝参照型のデフォルト値`null`になります。

</details>

## 問題10

`int[] i = {};`（要素数0の配列）は、`i == null`が`true`になりますか？

</details>

## 問題11

`int[] i = {};`の後に、`i[0] = new int[]{1,1,1};`と書くとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「不適合な型: int[]をintに変換できません」というエラーです。`int[] i`は「`int`を要素として持つ配列」なので、`i[0]`という箱に入れられるのは`int`型の値だけで、`int[]`（配列そのもの）は入れられません。これは`int[][]`（`int[]`を要素とする配列）とは根本的に違う型だからです。

</details>

## 問題12

同じ`int[] i = {};`に対して、型を合わせて`i[0] = 5;`と書くとどうなりますか？

<details><summary>解答</summary>

**実行時に`ArrayIndexOutOfBoundsException`になります。**「Index 0 out of bounds for length 0」というエラーで、要素数0の配列に0番目は存在しないことを示しています。今回は型が合っているのでコンパイルは通り、実行時に初めて「範囲外」という問題が表面化します。

</details>

## 問題13

一度`int[] i = {};`（要素数0）で作ってしまった配列に、後から要素を追加してサイズを増やすことはできますか？

<details><summary>解答</summary>

**できません。**Javaの配列はサイズが固定で、一度作った配列のサイズを後から変更する仕組みはありません。値を入れたいなら、最初から必要な要素数で作り直す（`i = new int[3];`のように、変数の参照先を新しい配列に丸ごと差し替える）しかありません。動的にサイズが伸び縮みする配列が欲しい場合は`ArrayList`を使います。

</details>

## 問題14

`enum`とは何ですか？

<details><summary>解答</summary>

**「取りうる値が決まりきった、限られた選択肢の集合」を表すための専用の型です。**各定数（例：`Season.SPRING`）はそのenum型の唯一無二のインスタンス（Singleton）として扱われ、`==`で安全に比較できます。`enum`は暗黙的に`java.lang.Enum`を継承するため他のクラスは`extends`できませんが、`interface`は`implements`できます。

</details>

## 問題16

`switch(str){ case "Java" -> System.out.println(str); };`のように、switch文の閉じ`}`の直後に`;`を付けても問題ありませんか？

<details><summary>解答</summary>

**問題ありません。**この`;`は「switch文専用のルール」ではなく、Java全体で使える**空文（からぶん）**という一般的な仕組みです。`;`だけを単独で書くと「何もしない文」として扱われ、どこにでも置けます。switch文の後ろにたまたま空文が1つくっついているだけで、付けても付けなくてもどちらでも構いません。

</details>

## 問題17

`String result = switch(str){ case "Java" -> return "ok"; default -> "no"; };`のように、switch式の中で`return`を使うとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「式の開始が不正です」というエラーです。`return "ok";`は「メソッドを終了して値を渡しなさい」という動作の命令（文）であって、値そのもの（式）ではありません。switch式の`case X ->`の右側は「値（式）をよこせ」という場所なので、文である`return`は置けません。

</details>

## 問題18

同じ理由で、switch**文**（値を代入していない、ただのswitch）であっても、`case "Java" -> return "ok";`のようにアロー構文で直接`return`を書くとどうなりますか？

<details><summary>解答</summary>

**やはりコンパイルエラーになります。**「caseの予期しない文です。予期されるのは、式、ブロックまたはthrow文です」というエラーです。switch式かswitch文かに関わらず、**アロー構文（`->`）の右側**に置けるのは「式・ブロック・`throw`文」の3種類だけという制約があります。

</details>

## 問題19

問題18の状況で、`return`を書きたい場合はどうすればよいですか？

<details><summary>解答</summary>

**ブロック`{ }`で包みます。**`case "Java" -> { return "ok"; }`のように書けば、ブロックの中はただの通常の文の並びになるので、制約が外れて`return`も書けるようになります。

</details>

## 問題20

コロン形式（`case "Java": return "ok";`）の場合はどうですか？

<details><summary>解答</summary>

**ブロックで包まなくても、そのまま`return`を書けます。**コロン形式は昔ながらの「複数の文をただ並べる」スタイルなので、右側に置けるものの種類に制約が無く、`return`をそのまま書いても問題ありません。この制約の有無が、アロー形式とコロン形式の決定的な違いです。

</details>

## 問題36

`int a = 2;`として、`switch (a)`の中身が`case 1 -> System.out.println("A");`、`case 2 -> System.out.println("B");`、`case 3 -> System.out.println("C");`、`default -> System.out.println("D");`という、すべて**アロー形式**（`break`なし）のswitch文だった場合、何が表示されますか？

<details><summary>解答</summary>

**`B`だけが表示されます。**アロー形式（`->`）のswitchは、一致した`case`の右側だけを実行して、そこでswitch全体を抜けます。次の`case`へ落ちていく「フォールスルー」が起きないので、`break`も不要です。`a`が`2`なので`case 2`の`B`だけが出力され、`C`や`D`は実行されません。なお、switchの閉じ`}`の後ろに`;`が付いていても、問題16のとおり空文なのでコンパイルエラーにはなりません。

</details>

## 問題37

問題36と同じ内容を、コロン形式（`case 1: System.out.println("A");`のように`->`ではなく`:`を使い、`break`は書かない）で書いた場合、何が表示されますか？

<details><summary>解答</summary>

**`B`、`C`、`D`の3つが順に表示されます。**コロン形式は、一致した`case`から下へ向かって、`break`に当たるかswitchの終わりまで、すべての文を実行し続けます（フォールスルー）。`case 2`から始まり、`case 3`の`C`、`default`の`D`まで続けて実行されます。アロー形式との決定的な違いです。

</details>

## 問題40

</details>

## 問題41

次のテキストブロックを`System.out.println`で出力すると、どうなりますか？1行目は`A`の直後が`\`で終わっています。2行目は、1行目より4文字分インデントが深く、`A`、空白7個、`\s`の順に並んでいます。3行目は閉じの`"""`だけで、インデントは1行目と同じです。

<details><summary>解答</summary>

**`A`、空白4個、`A`、空白8個が並んだ1行だけが出力されます。**1行目の行末の`\`で改行が消えて、2行目とつながります。2行目のインデントは、1行目より4文字分深い分（空白4個）だけ残ります。2つ目の`A`の後ろの空白7個は、すぐ後ろに`\s`があるので行末扱いされず、そのまま残ります。さらに`\s`が空白1個になるので、合計で空白8個です。最後に、テキストブロック自体の末尾の改行と`println`の改行で、空行が1つ続きます。

</details>

## 問題42

パッケージ宣言が異なっていれば、同じ名前のクラスを宣言できますか？

<details><summary>解答</summary>

**できます。**クラスの本当の名前は、パッケージ名とクラス名をつなげた**完全修飾名**（`p1.Same`と`p2.Same`のように）です。パッケージが違えば完全修飾名が違うので、別のクラスとして扱われます。JDKにも、`java.util.Date`と`java.sql.Date`のように、パッケージだけが違う同名のクラスがあります。

</details>

## 問題43

あるクラスがどのパッケージに属するかは、ソースファイルを置いたフォルダで決まりますか？

<details><summary>解答</summary>

**決まりません。ソースファイルの`package`宣言で決まります。**ソースが`p1`フォルダにあっても、`package p2;`と書けば、そのクラスは`p2`に属します（クラス名は`p2.B`になります）。`package`宣言が無ければ、どのフォルダにあっても無名パッケージに属します。

</details>

## 問題44

`-d`オプションでコンパイルしたとき、クラスファイルはどこに作られますか？また、そのクラスファイルを別のフォルダに移して実行すると、どうなりますか？

<details><summary>解答</summary>

**`package`宣言のとおりのフォルダ階層に作られます。**`package p2;`のクラスなら、`p2`フォルダの中です。実行するときも、パッケージ名どおりのフォルダからクラスファイルを探すので、別のフォルダに移すと、「NoClassDefFoundError（wrong name）」というエラーで実行できません。ソースファイルを置くフォルダは慣例ですが、クラスファイルを置くフォルダは、パッケージ名と合っている必要があります。

</details>

## 問題45

`package p1;`と宣言した`public class Same`を、フォルダだけ分けて（`a/Same.java`と`b/Same.java`）2つ作り、一緒にコンパイルするとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「クラスp1.Sameが重複しています」というエラーです。フォルダを分けても、`package`宣言が同じなら、同じ名前のクラスを2回宣言したことになり、別のクラスにはなりません。別のクラスにするのは、`package`宣言を変えることです。

</details>

## 問題46

別のパッケージに、同じ名前の`public class Same`を2つ作るとき、なぜソースファイルをフォルダで分ける必要がありますか？

<details><summary>解答</summary>

**`public`なクラスは、ファイル名をクラス名と同じにする必要があり、同じフォルダには同じ名前のファイルを2つ置けないからです。**`Same.java`が2つ必要になるので、`p1/Same.java`と`p2/Same.java`のようにフォルダを分けます。別のクラスにしているのは`package`宣言で、フォルダを分けるのは、同じ名前のファイルを置くためです。なお`public`を付けなければ、`X.java`と`Y.java`のようにファイル名を変えて、同じフォルダに同名のクラスを置くこともできます。

</details>

## 問題47

`p1.Same`と`p2.Same`の両方を、`import p1.Same;`と`import p2.Same;`でインポートすると、どうなりますか？また、両方を使うにはどうしますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「同じ単純名の型がSameの単一型インポートによってすでに定義されています」というエラーです。片方だけを`import`して、もう片方は`p2.Same`のように完全修飾名で書けば、両方を使えます。`import`を使わずに、両方を完全修飾名で書いても構いません。

</details>

## 問題48

`int`型の値を`Number`型の引数に渡すと、`Number`クラスのインスタンスが新しく作られるんですか？

<details><summary>解答</summary>

**いいえ、作られません。**`Number`はabstractクラスなので、そもそも`Number`単体のインスタンスは作れません（`new Number()`は「Numberはabstractです」というコンパイルエラーになります）。`int`は自動でオートボクシングされ、対応するラッパークラス（`Integer`）のインスタンスになります。それを`Number`型の変数へアップキャストしているだけで、実体はIntegerのままです。

</details>

## 問題49

`Number`型の変数`n`の実体が`Integer`だったとき、`n instanceof Integer`は`true`になりますか？

<details><summary>解答</summary>

**`true`になります。**`instanceof`は、変数の宣言上の型（静的型）ではなく、その変数が実際に指しているオブジェクトの型（実体・動的型）を調べます。`n`の宣言は`Number`型でも、実体が`Integer`である以上、`n instanceof Integer`は`true`と判定されます。

</details>

## 問題50

`IllegalStateException`は、どんなときにスローされますか？チェック例外ですか？

<details><summary>解答</summary>

**「引数の値」ではなく「呼ぶタイミング・状態」が不適切なときにスローされます。**`java.lang.RuntimeException`のサブクラスなので、非チェック例外です（`throws`宣言なしで投げられます）。典型例は、`Iterator`の`remove()`を、`next()`を一度も呼ばずに呼び出したときです。値そのものがおかしい場合の`IllegalArgumentException`とは違い、こちらは「今その操作をしていい状況ではない」ことを表します。

</details>
