## 問題1

`String literal = "java";`とした後、`String runtimeConcat = ja + va;`（`ja`・`va`は変数で、中身を連結すると`"java"`になる）とした場合、`literal == runtimeConcat`はどうなりますか？

<details><summary>解答</summary>

**`false`になります。**変数同士の`+`連結は実行時に評価されるため、コンパイラは値を事前に確定できず、常に新しいオブジェクトをヒープ上に生成します。結果の中身が定数プールの文字列と一致していても、無関係な別オブジェクトになります。

</details>

## 問題2

`String compileTimeConcat = "ja" + "va";`のように、リテラル同士を`+`で連結した場合、`"java"`という既存のリテラルと同一のオブジェクトになりますか？

<details><summary>解答</summary>

**同一になります。**両方がコンパイル時に値の確定している定数（リテラル）なので、コンパイラは実行を待たずにその場で`"java"`という1つのリテラルへ畳み込みます（定数畳み込み）。畳み込まれた結果は普通の文字列リテラルと同じ扱いになり、定数プール上の既存の`"java"`とそのまま同一視されます。

</details>

## 問題3

`String ja = "Ja"; String va = "va"; String result = ja + va;`とした場合、`result`の中身は`"java"`（すべて小文字）と一致しますか？

<details><summary>解答</summary>

**一致しません。**`result`の中身は`"Java"`（大文字J）になります。`String`は大文字小文字を区別するため、`"Java"`と`"java"`は`equals()`で比較しても`false`になる、完全に別の文字列です。

</details>

## 問題4

`String string = "java"; String ja = "ja"; String va = "va"; String concatBeforeIntern = ja + va; String java = concatBeforeIntern.intern();`という一連の処理で、`string == java`はどうなりますか？

<details><summary>解答</summary>

**`true`になります。**`intern()`は「その内容と同じ文字列が既に定数プールにあれば、新しいオブジェクトを作らず既存の参照を返す」動作です。`concatBeforeIntern`の中身`"java"`は、既に`string`の時点でプールに登録済みなので、`intern()`は新規生成せず`string`と同じ参照を返します。

</details>

## 問題5

問題4の状況で、`intern()`を呼ぶ**前**の`concatBeforeIntern`自体は、`string`と同じオブジェクトですか？

<details><summary>解答</summary>

**別オブジェクトです。**`ja + va`という実行時連結は、`intern()`を呼ぶより前の時点で、既に新しいヒープオブジェクトを生成してしまっています。`intern()`は「呼ばれた後に新規生成をしない」だけであって、呼ばれる前に既に作られてしまった一時オブジェクトの存在自体は無かったことになりません（GC対象になるだけです）。

</details>

## 問題6

`String string = "java"; String ja = "ja"; String va = "va"; String java = ja + va;`（`intern()`を呼ばない）とした場合、`string == java`はどうなりますか？

<details><summary>解答</summary>

**`false`になります。**`intern()`を呼んでいないため、`java`変数は`ja + va`の実行時連結で新しく作られたヒープオブジェクトをそのまま指します。中身が同じ`"java"`であっても、定数プール上の`string`とは別の実体のままです。

</details>

## 問題7

`String string = "java"; String ja = "ja"; String va = "va"; String java = ja + va;`という一連のコードで、作られたStringオブジェクトの総数はいくつですか？

<details><summary>解答</summary>

**4個です。**①`string`（定数プールの`"java"`）、②`ja`（定数プールの`"ja"`）、③`va`（定数プールの`"va"`）、④`ja + va`の実行時連結結果（ヒープ上の新規オブジェクト）の4個です。`java`変数は④をそのまま指すので、追加で5個目が作られるわけではありません。

</details>

## 問題8

`int[][] c = new int[2][];`とした直後、`c[0]`や`c[1]`はどんな状態ですか？

<details><summary>解答</summary>

**両方とも`null`です。**外側の次元（要素数2）だけが確定し、内側の次元（各要素が指す`int[]`）は指定されていないため、各要素は「`int[]`型への参照」としてまだ何も指していない状態＝参照型のデフォルト値`null`になります。

</details>

## 問題9

問題8の`c`に対して、`c[0] = new int[]{1, 1, 1};`のように後から代入することはできますか？

<details><summary>解答</summary>

**できます。**`c[0]`という「箱」自体は`new int[2][]`の時点で既に存在しており、その中身がまだ`null`なだけです。存在する箱に対して後から値を代入するのは普通の代入操作なので問題ありません。

</details>

## 問題10

`int[] i = {};`（要素数0の配列）は、`i == null`が`true`になりますか？

<details><summary>解答</summary>

**`false`になります。**`{}`でも配列オブジェクト自体はきちんと作られています（`i.getClass()`は`class [I`を返し、`identityHashCode`も普通に値を持つ）。「要素数0の配列」と「参照が`null`（そもそも配列オブジェクトが存在しない）」は根本的に別の状態です。

</details>

## 問題11

`int[] i = {};`の後に、`i[0] = new int[]{1,1,1};`と書くとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「不適合な型: int[]をintに変換できません」というエラーです。`int[] i`は「`int`を要素として持つ配列」なので、`i[0]`という箱に入れられるのは`int`型の値だけで、`int[]`（配列そのもの）は入れられません。これは`int[][]`（`int[]`を要素とする配列）とは根本的に違う型だからです。

</details>

---

## 問題12

同じ`int[] i = {};`に対して、型を合わせて`i[0] = 5;`と書くとどうなりますか？

<details><summary>解答</summary>

**実行時に`ArrayIndexOutOfBoundsException`になります。**「Index 0 out of bounds for length 0」というエラーで、要素数0の配列に0番目は存在しないことを示しています。今回は型が合っているのでコンパイルは通り、実行時に初めて「範囲外」という問題が表面化します。

</details>

## 問題13

一度`int[] i = {};`（要素数0）で作ってしまった配列に、後から要素を追加してサイズを増やすことはできますか？

<details><summary>解答</summary>

**できません。**Javaの配列はサイズが固定で、一度作った配列のサイズを後から変更する仕組みはありません。値を入れたいなら、最初から必要な要素数で作り直す（`i = new int[3];`のように、変数の参照先を新しい配列に丸ごと差し替える）しかありません。動的にサイズが伸び縮みする配列が欲しい場合は`ArrayList`を使います。

</details>

## 問題14

`enum`とは何ですか？

<details><summary>解答</summary>

**「取りうる値が決まりきった、限られた選択肢の集合」を表すための専用の型です。**各定数（例：`Season.SPRING`）はそのenum型の唯一無二のインスタンス（Singleton）として扱われ、`==`で安全に比較できます。`enum`は暗黙的に`java.lang.Enum`を継承するため他のクラスは`extends`できませんが、`interface`は`implements`できます。

</details>

## 問題15

`enum`が自動的に持っているメソッドを3つ挙げてください。

<details><summary>解答</summary>

**`values()`（宣言順の全定数の配列を返す）・`valueOf(String)`（定数名の文字列から対応する定数を取得する）・`ordinal()`（宣言順のインデックス、0始まり）・`name()`（定数名を文字列で返す）などです。**これらはコンパイラが自動的に用意してくれます。

</details>

## 問題16

`switch(str){ case "Java" -> System.out.println(str); };`のように、switch文の閉じ`}`の直後に`;`を付けても問題ありませんか？

<details><summary>解答</summary>

**問題ありません。**この`;`は「switch文専用のルール」ではなく、Java全体で使える**空文（からぶん）**という一般的な仕組みです。`;`だけを単独で書くと「何もしない文」として扱われ、どこにでも置けます。switch文の後ろにたまたま空文が1つくっついているだけで、付けても付けなくてもどちらでも構いません。

</details>

## 問題17

`String result = switch(str){ case "Java" -> return "ok"; default -> "no"; };`のように、switch式の中で`return`を使うとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「式の開始が不正です」というエラーです。`return "ok";`は「メソッドを終了して値を渡しなさい」という動作の命令（文）であって、値そのもの（式）ではありません。switch式の`case X ->`の右側は「値（式）をよこせ」という場所なので、文である`return`は置けません。

</details>

## 問題18

同じ理由で、switch**文**（値を代入していない、ただのswitch）であっても、`case "Java" -> return "ok";`のようにアロー構文で直接`return`を書くとどうなりますか？

<details><summary>解答</summary>

**やはりコンパイルエラーになります。**「caseの予期しない文です。予期されるのは、式、ブロックまたはthrow文です」というエラーです。switch式かswitch文かに関わらず、**アロー構文（`->`）の右側**に置けるのは「式・ブロック・`throw`文」の3種類だけという制約があります。

</details>

---

## 問題19

問題18の状況で、`return`を書きたい場合はどうすればよいですか？

<details><summary>解答</summary>

**ブロック`{ }`で包みます。**`case "Java" -> { return "ok"; }`のように書けば、ブロックの中はただの通常の文の並びになるので、制約が外れて`return`も書けるようになります。

</details>

---

## 問題20

コロン形式（`case "Java": return "ok";`）の場合はどうですか？

<details><summary>解答</summary>

**ブロックで包まなくても、そのまま`return`を書けます。**コロン形式は昔ながらの「複数の文をただ並べる」スタイルなので、右側に置けるものの種類に制約が無く、`return`をそのまま書いても問題ありません。この制約の有無が、アロー形式とコロン形式の決定的な違いです。

</details>
