## 問題1

try-catch文で、catchブロックの**中で**新しく例外をthrowしました。同じtry文の、その下に並んでいる別のcatchブロックで、その例外を捕まえることはできますか？

<details><summary>解答</summary>

**できません。**catchブロックが受け持つのは、**tryブロックの中で発生した例外だけ**です。catchブロックの中で投げた例外は、同じtry文のどのcatchの担当範囲にも入りません。そのままfinallyを実行した後、try文の外（呼び出し元）へ伝わっていきます。同じtry文の下にあるcatchが、たとえ`catch (RuntimeException e)`のように型として一致していても、捕まえることはありません。捕まえたいなら、try-catchをもう一段外側に書く必要があります。

</details>

## 問題2

次のコードを、コマンドライン引数なしで実行すると、何が出力されますか？

```java
try {
    System.out.print(args.length);
    args[0].charAt(0);
    System.out.print("A");
} catch (NullPointerException | IndexOutOfBoundsException e) {
    System.out.print("C");
    throw new RuntimeException();
} catch (RuntimeException e) {
    System.out.print("R");
} finally {
    System.out.print("E");
}
System.out.print("Z");
```

<details><summary>解答</summary>

**`0CE`と出力された後、RuntimeExceptionがスローされてプログラムが終了します。**検証済みです。

- 引数がないので`args.length`は`0`で、`0`が出力されます。
- `args[0]`でArrayIndexOutOfBoundsExceptionが発生します。これはIndexOutOfBoundsExceptionのサブクラスなので、マルチキャッチに捕まって`C`が出力されます。
- catchの中でRuntimeExceptionを投げますが、問題1のとおり、下の`catch (RuntimeException e)`には捕まりません。なので`R`は出力されません。
- finallyは必ず実行されるので、`E`が出力されます。
- 例外がmainの外へ出ていくので、`Z`は出力されません。

ひっかけは、「下にRuntimeExceptionのcatchがあるから、`R`が出力されてから`Z`まで進む」と考えてしまうところです。

</details>

## 問題3

`record Country(String name) {}`とだけ書いた場合、equalsメソッドはObjectクラスのもの（参照の比較）がそのまま使われますか？

<details><summary>解答</summary>

**いいえ。recordを宣言しただけで、コンパイラがequalsのオーバーライドを自動で生成します。**自動生成されるequalsは、参照ではなく、**全てのコンポーネントをそれぞれのequalsで比較**します。equalsのほかに、hashCode、toString、コンストラクタ、アクセサ（`name()`）も自動で生成されます。`javap`でクラスファイルを確認すると、`public final boolean equals(java.lang.Object)`がちゃんと入っています。

普通のclassでequalsをオーバーライドしていない場合は、Objectのequalsが使われるので`==`と同じ参照の比較になります。この違いを混同しないことがポイントです。

</details>

## 問題4

recordを使うと、`==`も中身の比較に変わりますか？`new Country("US") == new Country("US")`と`new Country("US").equals(new Country("US"))`の結果をそれぞれ答えてください。

<details><summary>解答</summary>

**`==`は変わりません。**結果は、`==`が`false`、equalsが`true`です。

`==`はJavaの演算子なので、意味を変える方法がありません。オブジェクトに対しては、recordでもStringでも普通のclassでも、常に「同じインスタンスか（参照が同じか）」を比較します。一方equalsはメソッドなので、オーバーライドで動きを書き換えられます。recordが書き換えているのはequalsだけです。

覚え方：「`==`はそのまま、equalsが書き換わる」。

</details>

## 問題5

`new Country(new String("US")).equals(new Country("US"))`の結果は、trueですか？falseですか？片方のnameは`new`で作った別のStringオブジェクトです。

<details><summary>解答</summary>

**trueです。**検証済みです。recordのequalsは、コンポーネントを`==`ではなく**equals**で比較します。つまり中では`"US".equals("US")`が呼ばれます。Stringのequalsは文字の並びを比較するので、Stringのオブジェクトが別々でも結果はtrueになります。

ちなみに、2つのnameを`==`で比べると（`a.name() == b.name()`）、プールの`"US"`と`new`で作った`"US"`は別オブジェクトなのでfalseになります。結果を決めるのは、`new String`を使ったかどうかではなく、**`==`とequalsのどちらで比較しているか**です。

</details>

## 問題6

数値リテラルの先頭にアンダースコア`_`を付けた`_123`のような書き方は、「数値リテラルの前にアンダースコアを置いた」としてコンパイルエラー（不正なアンダースコアです）になりますか？

<details><summary>解答</summary>

**「不正なアンダースコアです」というエラーには、なりません。**そもそも`_123`は数値リテラルとして扱われず、**識別子（variable名）として解釈される**ため、全く別の種類のエラーになります。検証済み：

```java
long num3 = 987_654_L;     // 不正なアンダースコアです（数値の末尾・接尾辞Lの直前）
float num4 = _123.45F;     // ';'がありません（全然別のエラー）
```

`_123`は実は合法な識別子です（検証済み：`int _123 = 5;`は普通にコンパイル・実行でき、`5`が出力される）。Javaの識別子は`_`（アンダースコア）や英字で始められるため、字句解析（トークン化）の段階で`_123.45F`を見た瞬間、コンパイラは「数値リテラルの開始」ではなく「識別子`_123`の開始」と判断してしまいます。その結果、`_123.45F;`という文は「識別子`_123`に対して`.45F`というフィールド／メソッドアクセスを試みている（ただし`45F`は数字から始まるので識別子として不正）」という扱いになり、「文ではありません」「';'がありません」という構文エラーになります（検証済み：`_123.45F;`だけを単独の文として書いても同じエラーが出る）。

**ポイント**：アンダースコアの配置ルール（数値の先頭・末尾・小数点の直前直後・接尾辞の直前直後には置けない、というルール）は、あくまで「字句解析で**数値リテラルとして認識された**トークンの内部」にのみ適用されます。`_`から始まるトークンは、その時点で数値ではなく**識別子として確定**するため、「数値リテラルの先頭にアンダースコアを置く」という状況そのものが実質的に発生しません（識別子としての構文エラーに化けるだけ）。

</details>

## 問題7

クラスのインスタンス変数として`int`・`double`・`boolean`・`char`を宣言し、何も初期化せずに`new`した場合、それぞれのデフォルト値は何になりますか？特に`char`のデフォルト値に注意してください。

<details><summary>解答</summary>

**`int`は`0`、`double`は`0.0`、`boolean`は`false`、`char`は`'\u0000'`（null文字）です。**検証済み：

```java
public class DefaultValues {
    int i;
    double d;
    boolean b;
    char c;

    public static void main(String[] args) {
        DefaultValues dv = new DefaultValues();
        System.out.print(dv.i + ",");
        System.out.print(dv.d + ",");
        System.out.print(dv.b + ",");
        System.out.print((int)dv.c);
    }
}
```
→ 実行結果：`0,0.0,false,0`

`char`のデフォルト値`'\u0000'`は、画面にそのまま出力しても**何も表示されない制御文字**なので見落としやすいですが、`(int)`にキャストすると中身が`0`であることが確認できます。`boolean`のデフォルトは`true`ではなく`false`である点も、選択肢のひっかけとしてよく狙われます。

ちなみに`(int)`キャストせずに`System.out.print(dv.c)`だけ実行すると、本当に画面上は何も表示されません。検証済み：`"[" + dv.c + "]"`を出力すると、`[`と`]`の間にヌルバイト（`\0`）が1個挟まっているだけなので、見た目上は`[]`のようにくっついて見えます（バイト単位で確認すると`[` `\0` `]`とちゃんと1文字分の制御文字が入っていることが分かる）。

</details>

## 問題8

テキストブロックの直後に`.formatted(...)`で値を埋め込む書き方について、渡せる引数の個数や型に制限はありますか？また、同じ`%s`を複数回使って、複数の`String`を渡すこともできますか？

<details><summary>解答</summary>

**制限はありません。** `formatted(Object... args)`は**可変長引数（varargs）**なので、個数は0個でも10個でも自由ですし、型も書式指定子に対応していれば何でも混ぜられます。検証済み：

```java
"""
Name: %s
Age: %d
Height: %.1f
Active: %b
Grade: %c
""".formatted("Taro", 25, 172.5, true, 'A')
```
→ `Name: Taro / Age: 25 / Height: 172.5 / Active: true / Grade: A`

同じ型（`String`）を複数渡すことも問題ありません。検証済み：

```java
"""
First: %s
Second: %s
Third: %s
""".formatted("Apple", "Banana", "Cherry")
```
→ `First: Apple / Second: Banana / Third: Cherry`

ポイントは、**書式指定子（`%s`・`%d`など）と引数が、書かれた順番（左から右）で1対1に対応する**という点です。1個目の`%s`には1個目の引数、2個目の`%s`には2個目の引数……というように、位置で機械的にマッチングされます。`%s`の個数と渡す引数の個数が一致してさえいれば、型をいくつ混ぜても、同じ型を何個並べても自由です。

主な書式指定子は以下の通りです。

| 書式指定子 | 対応する型の例 |
| --- | --- |
| `%s` | 任意の型（`toString()`される） |
| `%d` | `int`・`long`などの整数 |
| `%f` / `%.1f` | `float`・`double`（`.1`は小数点以下の桁数指定） |
| `%b` | `boolean` |
| `%c` | `char` |

</details>

## 問題9

`StringBuilder`の初期capacityと、容量が足りなくなった時の拡張のされ方について説明してください。

<details><summary>解答</summary>

**初期capacityはコンストラクタによって決まり、容量超過時は「今のcapacity×2+2」か「実際に必要な文字数」の大きい方に拡張されます。**検証済み：

初期capacity：

| コンストラクタ | 初期capacity |
| --- | --- |
| `StringBuilder()` | `16` |
| `StringBuilder(String str)` | `str.length() + 16` |
| `StringBuilder(int capacity)` | 指定した値そのまま |

容量超過時の拡張：**新しいcapacity = max(今のcapacity × 2 + 2, 実際に必要な文字数)**

```
初期16 → 17文字必要 → capacity=34   (16×2+2=34 ≥ 17 なのでそのまま採用)
初期20 → 51文字必要 → capacity=51   (20×2+2=42 < 51 なので、必要な51の方を採用)
初期16 → 39文字必要 → capacity=39   (16×2+2=34 < 39 なので、必要な39の方を採用)
```

ポイントは2段階に分かれていることです。①`new`した時点でコンストラクタの種類に応じて初期capacityが決まる（`String`を渡すと`文字列の長さ+16`になる点に注意）。②その後`append()`等で容量を超えそうになった時だけ、自動的に再確保が走り、「2倍+2」か「必要量」の大きい方まで一気に拡張される（容量内に収まっている間は一切変化しない）。

</details>

## 問題10

`StringBuilder`の`equals()`は、`String`の`equals()`と同じように中身（文字の並び）を比較してくれますか？

<details><summary>解答</summary>

**いいえ、`StringBuilder`は`equals()`をオーバーライドしていないので、`Object`のデフォルト（＝`==`と同じ参照比較）のままです。**検証済み：

```java
StringBuilder sb1 = new StringBuilder("hello");
StringBuilder sb2 = new StringBuilder("hello");

sb1.equals(sb2)   // → false（中身は同じでも別オブジェクト）
sb1 == sb2        // → false
sb1.equals(sb1)   // → true（自分自身への参照なので一致）

// 比較: Stringの場合
String s1 = new String("hello");
String s2 = new String("hello");
s1.equals(s2)     // → true（Stringは中身を比較するequals()をオーバーライド済み）
```

`String`は`equals()`を「文字の並びが同じかどうか」で判定するようオーバーライドしていますが、`StringBuilder`にはそのオーバーライドがありません。そのため`StringBuilder`の`equals()`を呼んでも、結局`==`と全く同じ「同一オブジェクトかどうか」の判定にしかならない点に注意が必要です。中身を比較したい場合は、`sb1.toString().equals(sb2.toString())`のように一度`String`に変換する必要があります。

</details>

## 問題11

`final int a;`と宣言だけしておいて、別の行で`a = 10;`と後から代入した場合、この`a`は`switch`文の`case`ラベルに使える「定数式」として扱われますか？

<details><summary>解答</summary>

**扱われません。コンパイルエラーになります。**検証済み：

```java
final int a;
a = 10;
int x = 10;
switch (x) {
    case a: System.out.print("A"); break;   // エラー: 定数式が必要です
}
```

`final`かつ「1回しか代入されない（definitely-assigned）」ことは保証されていても、それだけでは「定数変数（constant variable）」にはなりません。Javaの仕様上、定数変数と認められるのは**宣言と同時に定数式で初期化された`final`変数**だけです（例：`final int a = 10;`）。後から代入する「blank final」は、たとえ結果的に定数的な値になっていても、コンパイラの目には「定数式」として映りません。

</details>

## 問題12

`final int a = someMethod();`のように、`final`変数をメソッドの戻り値で初期化した場合、この`a`は`switch`の`case`ラベルに使えますか？

<details><summary>解答</summary>

**使えません。** `final`であっても、初期化に使った式がコンパイル時に値の決まる「定数式」でなければ、定数変数にはなりません。検証済み：

```java
static int someMethod() { return 10; }

final int a = someMethod();
int x = 10;
switch (x) {
    case a: System.out.print("A"); break;   // エラー: 定数式が必要です
}
```

メソッド呼び出しの結果は、実行するまで値が分からない（コンパイラにとっては）ので、定数式とは認められません。問題11の「blank final」とあわせて、「`final`＝定数式」と早合点しないことがポイントです。定数式になるのは、リテラルや、リテラル同士の算術演算（`5 + 5`など）、他の定数変数を使った式に限られます。

</details>

## 問題13

`String a = "cat";`に対して、`String b = String.valueOf(a);`とした場合、`a == b`は`true`になりますか？

<details><summary>解答</summary>

**`true`になります。**検証済み：

```java
String a = "cat";
String b = String.valueOf(a);
System.out.println(a == b);   // true
```

`String.valueOf(Object obj)`は、内部的に`obj.toString()`を呼んでいます。そして`String`クラスの`toString()`は「**自分自身（`this`）をそのまま返す**」という実装になっています。つまり`String.valueOf(a)`は新しいStringを作らず、渡した`a`そのものの参照を返すので、`==`で比較しても同じオブジェクトになります。「`valueOf`やメソッド経由だから新しいオブジェクトになるはず」という思い込みに注意です。

</details>

## 問題14

`String a = "cat";`に対して、`String b = "c" + getSuffix();`（`getSuffix()`は実行時に`"at"`を返すメソッド）とした場合、`a == b`はどうなりますか？同じ`"c" + "at"`という見た目でも、リテラルどうしの結合と結果が変わる理由も答えてください。

<details><summary>解答</summary>

**`false`になります。**検証済み：

```java
String a = "cat";
String b = "c" + getSuffix();   // getSuffix()は"at"を返す
System.out.println(a == b);     // false

String c = "c" + "at";          // リテラル同士の結合

```

`"c" + "at"`のように**両方がリテラル（コンパイル時に値が分かる定数式）**の結合は、コンパイラが**コンパイル時に`"cat"`へ畳み込み**、文字列プールの既存オブジェクトを指すようになります。一方`"c" + getSuffix()`は、片方が**実行時にしか値の分からないメソッド呼び出し**なので畳み込みができず、実行時に新しい`String`オブジェクトが生成されます。見た目の文字列が同じでも、「コンパイル時に確定する式かどうか」で`==`の結果が変わる点がポイントです（問題11・12の「定数式」の話と根っこは同じです）。

</details>

## 問題15

`Object[] arr = new String[2];`のように、`String[]`を`Object[]`型の変数に代入すること自体はコンパイルできます。その後`arr[1] = Integer.valueOf(1);`と書くと、コンパイルは通りますか？実行するとどうなりますか？

<details><summary>解答</summary>

**コンパイルは通りますが、実行時に`ArrayStoreException`がスローされます。**検証済み：

```java
Object[] arr = new String[2];
arr[0] = "a";                    // OK
arr[1] = Integer.valueOf(1);     // コンパイルは通るが、実行時に例外

// 実行結果:
// Exception in thread "main" java.lang.ArrayStoreException: java.lang.Integer
```

配列は「共変（covariant）」なので`String[]`を`Object[]`に代入できますが、**配列が実際に覚えている実行時の型は`String[]`のまま**です。コンパイラは変数の宣言型（`Object[]`）しか見ないので`arr[1] = Integer.valueOf(1)`を許しますが、JVMは要素を書き込む瞬間に「この配列は本当は`String[]`だぞ」と実行時チェックをして弾きます。対して`Object[] arr = new Object[2];`なら同じ代入は何の問題もなく通ります（検証済み）。「コンパイルが通る＝安全」ではない代表例です。

</details>

## 問題16

`sealed interface Shape permits Circle {}`に対して、`Circle`を`enum`として実装する場合（`enum Circle implements Shape { INSTANCE }`）、`final`や`non-sealed`のような修飾子は必要ですか？定数ごとに個別の実装（コンスタント固有ボディ）を持つ場合はどうですか？

<details><summary>解答</summary>

**どちらの場合も修飾子は不要です。** `enum`は常に暗黙的に閉じた型として扱われるため、sealedの直接サブタイプになる際に`final`／`sealed`／`non-sealed`を書く必要がありません。検証済み：

```java
sealed interface Shape permits Circle {}

enum Circle implements Shape { INSTANCE }   // 修飾子なしでOK

// 定数固有ボディがあっても同じくOK
enum Circle implements Shape {
    INSTANCE { public String tag() { return "x"; } };
    public abstract String tag();
}
```

一方、同じ場所を**普通のクラス**や**abstractクラス**で実装する場合は、`final`・`sealed`・`non-sealed`のいずれかが必須です（書かないと「sealed、non-sealedまたはfinal修飾子が必要です」というコンパイルエラー）。「enumだけは特別扱いされる」という点を覚えておくとひっかけに強くなります。

</details>

## 問題17

同じく`sealed interface Shape permits Circle {}`に対して、`Circle`を**インタフェース**として実装する場合、`interface Circle extends Shape {}`と修飾子なしで書くとコンパイルは通りますか？

<details><summary>解答</summary>

**通りません。** `sealed`か`non-sealed`のどちらかを明示する必要があります。検証済み：

```java
sealed interface Shape permits Circle {}

interface Circle extends Shape {}              // エラー: sealedまたはnon-sealed修飾子が必要です
non-sealed interface Circle extends Shape {}    // OK
```

クラスの場合は`final`／`sealed`／`non-sealed`の3択ですが、**インタフェースは`final`にできない**ため、選べるのは`sealed`か`non-sealed`の2択だけになります。「直接の子は何らかの形で修飾子が必須」というルール自体はクラスもインタフェースも共通ですが、選べる修飾子の種類が型によって変わる点に注意です。

</details>

## 問題18

可変長引数（varargs）のパラメータは、1つのメソッドに何個まで書けますか？また、必ず最後のパラメータでないといけませんか？`int[]... a`のように「配列の可変長引数」は許されますか？

<details><summary>解答</summary>

**可変長引数は1メソッドに1つだけ、かつ必ず最後のパラメータでなければなりません。ただし「配列の可変長引数」自体は問題なく許されます。**検証済み：

```java
void m(int... a) {}                      // OK
void m(int a, int... b) {}               // OK（可変長引数が最後）
void m(int... a, int b) {}               // エラー: 可変長引数パラメータは最後のパラメータにする必要があります
void m(int... a, String... b) {}         // エラー: 同じ理由（2つ目も結局「最後」ではない）
void m(int[]... a) {}                    // OK（int[]の可変長引数＝実質2次元配列的な受け取り方）
void m(final int... a) {}                // OK（finalを付けても問題ない）
```

ひっかけやすいのは「可変長引数が2つあるのは単純にダメ」という理解だけだと、`int[]... a`のような「要素が配列型の可変長引数」まで一緒にダメだと誤解してしまう点です。禁止されているのは「可変長引数パラメータの後ろに別のパラメータが続くこと」であって、要素の型が配列であること自体は何も問題ありません。

</details>

## 問題19

入れ子になった`try-with-resources`（外側のtryの中に、さらに内側のtryがある構造）で、内側のリソースがクローズされるタイミングはいつですか？「全部のリソースは、一番外側のtry文が終わるまでまとめてクローズされる」という理解は正しいですか？

<details><summary>解答</summary>

**正しくありません。内側のリソースは、内側のtryブロックを抜けた「その時点」でクローズされます。**外側のtryが終わるまで待つわけではありません。検証済み：

```java
try (var outer = new Res("outer")) {
    System.out.print("outer-body-");
    try (var inner = new Res("inner")) {
        System.out.print("inner-body-");
    }
    System.out.print("outer-cont-");
}
// 出力: outer-body-inner-body-close-inner-outer-cont-close-outer-
```

内側のtry-with-resourcesは、ブロックを抜けた瞬間に自分の担当するリソース（`inner`）を即座にクローズします。それから制御が外側のtryブロックに戻って`outer-cont-`が出力され、最後に外側のtryブロック全体を抜けるタイミングで`outer`がクローズされます。「クローズは全部まとめて最後」ではなく、「**それぞれのtryブロックを抜けた瞬間に、そのブロックのリソースだけが閉じる**」という理解が正確です。

</details>

## 問題20

`X.super.method()`という書き方が使えるのは、具体的にどういう条件を満たしたときですか？「`X`というインタフェースのdefaultメソッドを、どこかで継承していればOK」という理解で合っていますか？

<details><summary>解答</summary>

**合っていません。「どこかで継承」では不十分で、`X`を直接implements（またはextends）している必要があります。**検証済み：

```java
// NG例：Implは Mid を実装しているが、Base は直接実装していない
interface Base { default void show() { print("Base"); } }
interface Mid extends Base { default void show() { print("Mid"); } }
class Impl implements Mid {
    public void show() { Base.super.show(); }   // エラー: Baseは内部クラスを囲みません
}

// OK例：Cは A と B を両方直接実装している
interface A { default String tag() { return "A"; } }
interface B { default String tag() { return "B"; } }
class C implements A, B {
    public String tag() { return A.super.tag() + B.super.tag(); }   // どちらもOK → "AB"
}
```

`Impl`は`Mid`を実装していて、`Mid`が`Base`を継承しているので「間接的には`Base`の子孫」ですが、それだけでは`Base.super`は使えません。`X.super.method()`の`X`は、**その場で書いているクラス／インタフェースが、`implements`や`extends`で直接名前を書いている型**でなければならない、という点がポイントです。

</details>

## 問題21

`List.of("A", "B")`で作ったリストを`new ArrayList<>()`のコンストラクタに渡して、そのArrayListに`add()`しました。コンパイルエラーになりますか？それとも正常に動きますか？

<details><summary>解答</summary>

**正常に動きます。**`new ArrayList<>(List.of("A", "B"))`は、`List.of()`の中身を**コピーして**新しい可変のArrayListを作ります。`List.of()`自体は不変ですが、そこから作ったArrayListは独立した別インスタンスなので、`add()`は問題なく成功します。一方、`List.of()`が返したリスト**そのもの**に`add()`すると、実行時に`UnsupportedOperationException`が発生します。「`List.of()`で作ったリスト自身を直接変えようとするか、コピーして使うか」で結果が変わります。

</details>

## 問題22

`protected`なフィールドは、サブクラスからしかアクセスできませんか？

<details><summary>解答</summary>

**違います。同一パッケージ内なら、継承関係がなくてもアクセスできます。**`protected`のアクセス範囲は「同一パッケージ内」＋「別パッケージのサブクラス」の2つです。「サブクラスからしか使えない」という思い込みは間違いで、同じパッケージにある別クラスからも普通にアクセスできます。`package-private`（修飾子なし）とほぼ同じ範囲に、さらに「別パッケージのサブクラスからもOK」が加わったものだと考えると整理しやすいです。

</details>

## 問題23

`switch`文の`case`ラベルに使える変数はどういう条件を満たす必要がありますか？`final`が付いていればOKですか？

<details><summary>解答</summary>

**`final`が付いているだけでは不十分です。「コンパイル時定数式で初期化されていること」が必要です。**具体的には、宣言と同時に定数式（リテラルや定数式の演算）で値を確定させている必要があります。次の2つはNGです：

- **blank final**：`final int a; a = 10;`のように宣言と代入を別の行に書いたもの
- **メソッドの戻り値での初期化**：`final int a = someMethod();`のように、実行時にしか値が分からないもの

逆に`final int a = 10;`や`final int a = 5 + 5;`、`static final`のクラスフィールドはコンパイル時定数として認められるのでOKです。「`final`＝定数」という短絡的な理解は危険で、「コンパイル時に値が確定しているか」が本当の判断基準です。

</details>

## 問題24

`"c" + "at"`という文字列連結式と、`"c" + getSuffix()`（`getSuffix()`は実行時に`"at"`を返す）という式があります。両方とも`==`で`"cat"`と比較した場合、結果は同じですか？

<details><summary>解答</summary>

**違います。**`"c" + "at"`はコンパイル時定数式なので、コンパイラがコンパイル時に`"cat"`へ畳み込み、文字列プールの同一オブジェクトを指します。`==`は`true`になります。一方`"c" + getSuffix()`はメソッドの戻り値を含むため実行時連結になり、その都度新しい`String`オブジェクトが生成されます。`==`は`false`です。また`final`変数でも、宣言と同時にリテラルや定数式で初期化されていれば畳み込みの対象になりますが、メソッドの戻り値で初期化された`final`変数は対象外です。`String.valueOf(stringVariable)`は引数が`String`の場合、`toString()`が`this`を返すので`==`で`true`になる点も覚えておきましょう。

</details>

## 問題25

## 問題26

クラス直下に`if (x > 0) { x = 20; }`という文を書きました。コンパイルできますか？

<details><summary>解答</summary>

## 問題27

`indexOf(String target, int fromIndex)`で、`fromIndex`に指定した位置は検索に含まれますか？含まれませんか？

<details><summary>解答</summary>

**含まれます。**`indexOf(String, int fromIndex)`は`fromIndex`の位置から右（末尾方向）へ検索し、`fromIndex`自身も検索対象に含まれます。`lastIndexOf(String, int fromIndex)`も同様に`fromIndex`自身を含んで、左（先頭方向）へ検索します。「fromIndexの次から」ではなく「fromIndex自身から」という点に注意してください。また`lastIndexOf`でサブ文字列を検索する場合、`fromIndex`は「一致の**開始位置**の上限」なので、`fromIndex`より後ろに伸びる文字列でも`fromIndex`から始まっていれば一致として返されます。

</details>

## 問題28

`System.out.println(new char[]{'a', 'b'})`を実行すると、何が出力されますか？

**`ab`が出力されます。**`System.out.println(char[])`という専用のオーバーロードが存在するため、`char`配列だけは文字をそのまま並べて出力されます。他の配列（`int[]`など）は`Object`として扱われ`[I@ハッシュ値`のような形式になります。ただしこれは`println`に直接渡した場合の話で、`"" + charArray`のように文字列連結した場合はこのオーバーロードは効かず、`[C@ハッシュ値`形式になります。`char[]`だけが特別扱いされる点を覚えておきましょう。

</details>

## 問題31

try-with-resourcesを入れ子にした場合、内側のリソースはいつクローズされますか？外側のtryが終わるまで待ちますか？

<details><summary>解答</summary>

**待ちません。内側のtryブロックを抜けた時点で、すぐにクローズされます。**たとえば次の順序で実行されます：`外側body開始 → 内側body → 内側リソースclose → 外側body続き → 外側リソースclose`。「try-with-resourcesは全部まとめて最後に閉じる」という理解は誤りで、「それぞれのtryブロックを抜けた瞬間に、そのブロック担当のリソースだけが閉じる」のが正確です。

## 問題36

## 問題39
