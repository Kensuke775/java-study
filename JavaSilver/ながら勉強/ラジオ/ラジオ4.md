## 問題1

`main`メソッドの中から、`sample()`のようにレシーバー無しで直接呼び出すメソッドがある場合、そのメソッドには何が必要ですか？

<details><summary>解答</summary>

**`static`が必要です。** `main`自体が`static`なので、その中からレシーバー無しで呼ぶメソッドは、呼ばれる側も`static`でなければなりません。

</details>

## 問題2

もし`main`から呼んでいるヘルパーメソッドに`static`が付いていなかった場合、何が起きますか？

<details><summary>解答</summary>

**コンパイルエラーになります。** 「非staticメソッドを、staticコンテキストから参照することはできません」というエラーです。`main`から見ればそのメソッド呼び出しは暗黙の`this.メソッド名()`と同じ扱いになりますが、`static`である`main`には`this`が存在しないためです。

</details>

## 問題3

`char`型は、ワイドニングの系統図の中で`byte`・`short`と同じグループにいますか？

<details><summary>解答</summary>

**違います。** `char`は`byte`・`short`とは別系統で、`int`のところで初めて合流します（`byte→short→int→...`という道と、`char→int→...`という道は、`int`より手前ではつながっていません）。

</details>

## 問題6

なぜ`byte`・`short`と`char`の間は、ビット幅が近くても自動変換できないのですか？

<details><summary>解答</summary>

**符号の有無が違うからです。** `byte`・`short`は符号あり、`char`は符号なしの16bitです。例えば`short`の`-1`をそのまま`char`にすると、全く別の巨大な正の値になってしまうため、Javaは自動変換を許可せず明示的なキャストを要求します。

</details>

## 問題8

`"a.b.c".replace(".", "-")`と`"a.b.c".replaceAll(".", "-")`は、同じ結果になりますか？

<details><summary>解答</summary>

**なりません。** `replace`は`"."`をただの文字として扱い`"a-b-c"`になりますが、`replaceAll`は`"."`を正規表現の「任意の1文字」として解釈してしまい、全部の文字が置換されて`"-----"`になります。

</details>

## 問題36

## 問題37

`interface A`に`default void sample()`があり、`interface B extends A {}`、`class C implements B`という関係があります。`C`の中から`A.super.sample();`と書くとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。** `C`は`B`を直接`implements`していますが、`A`は直接の実装対象ではありません（`B`を経由した間接的な関係でしかない）。`型名.super.メソッド名()`は直接の実装/継承対象にしか使えないため、`A.super.sample()`は使えません。正しくは`B.super.sample();`と書きます（`B`自身は`sample()`をオーバーライドしていないので、実質的に`A`のdefault実装が呼ばれます）。

</details>

## 問題38

defaultメソッド`sample()`を持つ`interface A`があるとして、`A.sample();`のように型名から直接呼び出すとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「staticでないメソッドをstaticコンテキストから参照することはできません」というエラーです。`sample()`はdefaultメソッド、つまりインスタンスメソッドなので、`型名.メソッド名()`というstatic呼び出しの形では解釈できません。呼ぶには`型名.super.メソッド名()`という専用構文が必要です。

</details>

## 問題39

`interface Worker { void work(); }`を`class Engineer extends Employee implements Worker {}`が実装しているとします（`Engineer`自身には`work()`が書かれていない）。もし`Employee`が`public void work()`を持っていたら、この`Engineer`はコンパイルエラーになりますか？

<details><summary>解答</summary>

**なりません。** インターフェースの抽象メソッドは、必ずしもそのクラス自身に直接書く必要はなく、継承したスーパークラスのメソッドで契約が満たされていればOKです。`Engineer`は`Employee`から`work()`を継承しているので、`Worker`が要求する`work()`の契約を（自分では書かずに）継承したメソッドが肩代わりして満たしています。

</details>

## 問題40

`interface Worker { void work(); }`、`class Employee implements Worker { public void work(){...} public void report(){...} }`、`class Engineer extends Employee { public void create(){...} }`という関係があるとします。次の3行はそれぞれコンパイルできますか？

```java
Worker a = new Engineer();
Employee b = new Engineer();
Engineer c = new Engineer();
a.create();
b.work();
c.report();
```

<details><summary>解答</summary>

**`a.create();`だけコンパイルエラーになります。**`b.work();`と`c.report();`は問題なくコンパイルできます。3つとも実体は同じ`Engineer`インスタンスですが、呼び出せるメソッドの範囲は実体ではなく**変数の宣言型（静的型）**で決まります。`a`は`Worker`型なので`Worker`が知っているメソッド（`work()`）しか呼べず、`Worker`にも`Employee`にも存在しない`create()`は呼べません。`b`は`Employee`型なので`work()`が呼べ、`c`は`Engineer`型なので自分の`create()`に加え継承した`report()`も呼べます。

</details>

## 問題41

上の問題40の状況で、もし`Engineer`が`work()`をオーバーライドしていなかった場合、`Worker a = new Engineer(); a.work();`は動的束縛（動的ディスパッチ）を経ずに呼ばれますか？

<details><summary>解答</summary>

**いいえ、オーバーライドの有無に関わらず、動的束縛の探索プロセス自体は常に同じように働きます。** オーバーライドしていない場合、動的型（`Engineer`）自身には実装が無いので、継承チェーンを1段上に辿って`Employee.work()`が見つかり、それが呼ばれます。オーバーライドしていれば、動的型自身の実装が優先して見つかります。「未実装だから動的束縛が働かない」のではなく、「動的束縛が継承チェーンを遡った結果、たまたま親のメソッドに行き着く」だけです。

</details>

## 問題42

`class A {...} class B extends A {...}`のように継承関係がある時、`A a = new A(); B b = (B) a;`と書くと、コンパイルは通りますか？

<details><summary>解答</summary>

**通ります。** `A`と`B`は継承関係にあるので、`(B) a`というダウンキャストの書き方自体は文法的に成立します。コンパイラは「継承関係があるかどうか」＝「理論上、実行時にうまくいく可能性があるかどうか」だけをチェックします。

</details>

## 問題43

問題42の`B b = (B) a;`を実際に実行すると、何が起きますか？（`a`の実体は`new A()`で作られた本物の`A`のインスタンス）

<details><summary>解答</summary>

**`ClassCastException`が実行時にスローされます。** ダウンキャストが安全に成功するのは、実体が本当にそのサブクラス（またはさらにそのサブクラス）である場合だけです。今回は実体が`A`そのものなので、「`A`を`B`として無理やり扱おうとする」ことになり、JVMが実行時に矛盾を検知して例外をスローします。

</details>

## 問題44

`A`と、`A`とは継承関係が全く無い`Unrelated`という別のクラスがあるとして、`A a = new A(); Unrelated u = (Unrelated) a;`と書くと、コンパイルは通りますか？

## 問題45

普通のクラスのコンストラクタは、recordの正準コンストラクタのように、引数を必ずフィールドへ代入しなければなりませんか？

<details><summary>解答</summary>

**義務はありません。** recordの正準コンストラクタは、コンパイラが自動生成するアクセサ・`equals`・`hashCode`が「全フィールド初期化済み」を前提にしているため代入が強制されますが、普通のクラスのコンストラクタはただのメソッドの一種で、中身は完全に自由です。何も代入しなくてもコンパイルは通り、そのフィールドは型のデフォルト値（`int`なら`0`など）のままになります。

</details>

## 問題46

コンストラクタの引数名とフィールド名が同じ`num`だった場合、`this.`を付けずに`num = num;`と書くと、フィールドに代入されますか？

<details><summary>解答</summary>

**されません。** 名前が衝突している時、`this.`を付けない裸の変数名は常に**一番近いスコープ（引数・ローカル変数）**を指します。`num = num;`は「引数のnumに、引数のnum自身を代入する」だけの実質何もしない文になり、フィールドの`num`はデフォルト値のまま放置されます。フィールドを指したい時は`this.num`と明示する必要があります。

</details>

## 問題48

`int[] array = {};`は、「箱は1個あるが中身が空（未初期化）」という意味ですか？

<details><summary>解答</summary>

**違います。**「箱の数そのものがゼロ」という意味です。「配列を作った」＝「インデックス0の箱が用意された」ではなく、「配列を作った」＝「指定した個数分だけ箱が用意された」であり、今回は個数として`0`を指定したことになります。`new int[1]`（長さ1、`array[0]`はデフォルト値`0`で存在する）とは全く別物です。

</details>

## 問題49

`args[0].length()`という式で、`.length()`は配列の`.length`プロパティと同じものですか？

<details><summary>解答</summary>

**違います。**`args`は`String[]`なので、`args[0]`は1個の`String`です。`String`クラスは`length()`という**メソッド**（丸括弧あり）を持っており、文字列の文字数を返します。配列自体が持つ`.length`（プロパティ、丸括弧なし）とは別物で、`args[0].length()`は「配列の0番目の要素（＝1個のString）」に対して「Stringのlength()メソッド」を呼んでいるだけです。

</details>

## 問題50

`public static void main(String[] args)`を`java Main`のように**引数なし**で実行した場合、`args`は`null`になりますか？

<details><summary>解答</summary>

**なりません。**Javaの仕様上、`main`の`args`は引数を渡さなくても`null`にはならず、必ず**要素数0の配列**になります（`args.length`は`0`）。そのため`args[0]`にアクセスしようとすると、`NullPointerException`ではなく`ArrayIndexOutOfBoundsException`が発生します。

</details>
