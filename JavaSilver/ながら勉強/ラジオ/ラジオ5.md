## 問題1

`interface A`に`default void sample() {...}`があるとします。この`sample()`メソッドは、修飾子を何も書いていませんが、実際には何が付いていることになりますか？

<details><summary>解答</summary>

**暗黙的に`public`が付いています。** インターフェースの抽象メソッドもdefaultメソッドも、どちらも暗黙的に`public`です。

</details>

## 問題2

`interface A`の`default void sample()`を、`class B implements A`側で`private void sample() {...}`として実装しようとすると、どうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「(public)より弱いアクセス権限を割り当てようとしました」というエラーです。インターフェースのメソッドは暗黙的に`public`なので、実装側でそれより弱い`private`にすることは許されません。

</details>

---

## 問題3

同じ状況で、`private`の代わりに`protected`で実装しようとした場合はどうですか？

<details><summary>解答</summary>

**同じくコンパイルエラーになります。**`protected`も`public`より弱いアクセス権限なので、`private`の場合と全く同じ理由でエラーになります。

</details>

## 問題4

このルールは、抽象メソッド（`void work();`のような中身の無いメソッド）にも同じように適用されますか？

<details><summary>解答</summary>

**適用されます。** defaultメソッドでも抽象メソッドでも、インターフェース側は暗黙的に`public`なので、実装する側でアクセス修飾子を弱めることはできません。

</details>

---

## 問題5

実装する側のクラスが`abstract`クラスであれば、アクセス修飾子を弱めても許されますか？

<details><summary>解答</summary>

**許されません。**「今すぐ全部実装しなくていい」という`abstract`の性質と、「実装するなら元より弱めてはいけない」というアクセス修飾子のルールは、全く別次元の話です。`abstract`クラスであっても、アクセス修飾子を弱めようとすればコンパイルエラーになります。

</details>

---

## 問題6

普通のクラス継承（インターフェースの実装ではなく、`extends`によるオーバーライド）でも、アクセス修飾子を弱めることは禁止されていますか？

<details><summary>解答</summary>

**禁止されています。** インターフェースの実装に限らず、通常のクラス継承のオーバーライド全般に共通するルールです。逆に、アクセス修飾子を**広げる**方向（例：`protected`→`public`）は問題なくOKです。

</details>

## 問題7

`class C extends B`のように、`new C()`で実際に作られたインスタンスがあるとします。それを`((A) new C())`のように別の型へキャストすると、新しいインスタンスが作られますか？

<details><summary>解答</summary>

**作られません。**インスタンスは`new`した瞬間に1つだけ作られ、その後は何をどうキャストしても変わりません。キャストが変えているのは実体そのものではなく、「その実体をプログラム上どの型として扱うか」という参照の型（静的型）のラベルだけです。矢印（参照）の先にある実体は常に同じインスタンスのままです。

</details>

## 問題8

`C original = new C(); A asA = (A) original;`とキャストした場合、`original == asA`は`true`になりますか？

<details><summary>解答</summary>

**`true`になります。**`identityHashCode`（オブジェクトの実体そのものを識別する値）も完全に一致します。キャストは同じ実体を指す参照の型（ラベル）を変えているだけで、実体は同一だからです。

</details>

## 問題9

`interface A`の`default void sample() {...}`があり、`abstract class B implements A`が何も書かず、`final class C extends B`も`sample()`を実装しなかった場合、`new C().sample()`は動きますか？

<details><summary>解答</summary>

**動きます。**`A`のdefault実装（`"A"`と表示する処理）がそのまま使われます。`B`が何も書かなければ、`A`のdefault実装を黙って継承するだけで済み、`C`も改めて実装する必要はありません。

</details>

## 問題10

同じ状況で、`B`側で`public abstract void sample();`とわざわざ再宣言していた場合、`C`が`sample()`を実装しないとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「Cはabstractでなく、B内のabstractメソッドsample()をオーバーライドしません」というエラーです。`B`が`abstract`として再宣言した時点で、`A`のdefault実装で一度完成していた契約が「未実装の状態」に巻き戻されます。`B`自身は`abstract`クラスなので実装しなくても許されますが、`B`を継承する具象クラス`C`は、abstractメソッドが残っている以上、自分で必ず実装しなければなりません。

</details>

## 問題11

問題9・10のように、`B`で`abstract`として再宣言するかどうかで結果が変わるのは、「書いても書かなくても冗長なだけで同じ」ということですか？

<details><summary>解答</summary>

**いいえ、明確に意味が変わります。**「defaultメソッドで一度実装済みになった契約」を、サブクラス側の都合で「あえてもう一度未実装扱いに戻し、下の階層に実装を強制する」というテクニックです。冗長な重複ではありません。

</details>

## 問題12

`abstract`メソッド（中身の無いメソッド）を1つでも持つクラスは、そのクラス自身も`abstract`でなければなりませんか？

<details><summary>解答</summary>

**必要です。**「NonAbstractはabstractでなく、NonAbstract内のabstractメソッドsample()をオーバーライドしません」というエラーになります。`abstract`メソッドは実装が無いので、そのクラスが`abstract`でなければ普通に`new`でインスタンス化できてしまい、実装の無いメソッドを呼べてしまう矛盾が生じるためです。

</details>

---

## 問題13

逆に、`abstract`クラスは必ず`abstract`メソッドを持っていなければなりませんか？

<details><summary>解答</summary>

**その必要はありません。**`abstract`クラスは、単に「直接インスタンス化させたくない」という意図だけで`abstract`にすることもできます。「abstractメソッドを持つならクラスもabstract」という関係は一方向で、逆（abstractクラスなら必ずabstractメソッドを持つ）は成り立ちません。

</details>

## 問題14

`abstract`クラス自身は、`private`な（中身のある）通常のメソッドを持つことができますか？

<details><summary>解答</summary>

**できます。**`abstract`クラスは「abstractメソッドを持てる／持たなくてもよい」クラスというだけで、通常のクラスと同様に`private`な通常メソッドも自由に持てます。

</details>

## 問題15

`abstract`メソッド自身に`private`修飾子を付けることはできますか？またその理由は？

<details><summary>解答</summary>

**できません。**「修飾子abstractとprivateの組合せは不正です」というエラーになります。`private`メソッドはサブクラスから見えず、オーバーライドの対象になりません。`abstract`は「サブクラスに実装させる」ことが前提なので、そもそも見えない`private`とは両立しません。

</details>

---

## 問題16

`abstract`メソッド自身に`final`修飾子を付けることはできますか？またその理由は？

<details><summary>解答</summary>

**できません。**「修飾子abstractとfinalの組合せは不正です」というエラーになります。`final`は「オーバーライド禁止」を意味しますが、`abstract`は「サブクラスに実装（＝オーバーライド）させる」ことが前提なので、正反対の指示になり矛盾します。

</details>

---

## 問題17

`abstract`メソッド自身に`static`修飾子を付けることはできますか？またその理由は？

<details><summary>解答</summary>

**できません。**「修飾子abstractとstaticの組合せは不正です」というエラーになります。`static`メソッドは特定のインスタンスに紐づかず、オーバーライド（動的束縛）の対象になりません（隠蔽にしかならない）。`abstract`は動的束縛前提の仕組みなので両立しません。

</details>

## 問題18

`final class Sample { abstract void sample(); }`のように、`final`クラスの中に`abstract`メソッドを書くとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**`abstract`メソッドを1つでも持つクラスは、そのクラス自身も`abstract`でなければなりません。しかし`final`と`abstract`はクラス修飾子として併用が禁止されているため、「abstractメソッドを持つ→クラスもabstractが必要→でもfinalとabstractは併用不可」という連鎖で、finalクラスはabstractメソッドを持てません。

</details>

## 問題19

`final`クラスが`interface`を実装する場合、そのインターフェースの抽象メソッドや未実装のdefaultメソッドを、サブクラスに実装を先送りすることはできますか？

<details><summary>解答</summary>

**できません。**`final`クラスは継承が禁止されているため、サブクラスを作ってそこに実装を先送りするという選択肢自体が存在しません。そのため`final`クラスは、実装すべきメソッドをすべてその場で実装済みでなければなりません。

</details>

## 問題20

`((A) new C()).sample(); ((B) new C()).sample();`のように、式の中で`new C()`を複数回書いた場合、これらは同じインスタンスですか？

<details><summary>解答</summary>

**別々のインスタンスです。**`new`は呼ぶたびに独立した新しいインスタンスを作ります。式の中で使い捨てにすると、その後はそのインスタンスを参照する手段がなくなります。

</details>

## 問題21

上の問題20の後に`C c = new C(); System.out.println(c.value);`と書いた場合、それ以前の`new C()`で`value`を変更していたら、この`c.value`にも反映されますか？

<details><summary>解答</summary>

**反映されません。**`C c = new C();`は、それ以前の`new C()`たちとは無関係な、全く新しいまっさらなインスタンスです。同じインスタンスに対して複数回操作したい場合は、`new`を1回だけにして変数を使い回す必要があります（キャストしても実体は変わらないので、型を変えて呼び分けることは可能）。

</details>

## 問題22

サブクラス`C`が、スーパークラス`B`と同じ名前のフィールド（例：`int value;`）を宣言した場合、これは「オーバーライド」ですか？

<details><summary>解答</summary>

**オーバーライドではありません。**フィールドは動的束縛（ポリモーフィズム）の対象にならず、名前が同じフィールドがサブクラスにもあると、それは上書きではなく**隠蔽（シャドーイング）**になります。つまり`B`の`value`と`C`の`value`は、名前が同じでも完全に別々の2つのフィールドとして共存します。

</details>

## 問題23

`B c = new C();`（`B`と`C`両方が独自の`value`を持つ）として`c.value`にアクセスすると、どちらの`value`が見えますか？

<details><summary>解答</summary>

**`B`の`value`が見えます。**フィールドはメソッドと違い、**参照の静的型（この場合`B`）で直接アクセス先が決まり**、動的型（`C`）を見て中身が切り替わることがありません。`C`側でどれだけ`value`に加算しても、`B`型経由でアクセスする限り`B`自身のフィールド（変化していない方）しか見えません。

</details>

## 問題24

問題23の状況で、もし`C`が独自の`value`を宣言していなかったら（`B`のものをそのまま使っていたら）、`c.value`は`C`側での変更を反映しますか？

<details><summary>解答</summary>

**反映します。**`C`が独自の`value`を持たなければ、`C`のメソッド内の`value`は継承した`B`の`value`をそのまま指すことになります。フィールドは1つしか存在しないため、`B`型経由でアクセスしても同じフィールドが見えます。

</details>

## 問題25

`switch (str) { case "A" -> total++; default -> total++; };`のように、`->`（アロー）を使ったswitchは、必ず値を生成する「switch式」ですか？

<details><summary>解答</summary>

**いいえ、必ずしもそうではありません。**「`->`（アロー）かどうか」と「switch文かswitch式か」は独立した軸です。今回のように、switch全体を何にも代入せず、各caseの中で`total++`のような処理を実行するだけなら、それは**switch文**であり、たまたま各caseの書き方にアロー構文を使っているだけです。

</details>

## 問題26

アロー構文を使ったswitch文の場合でも、`default`は必須ですか？

<details><summary>解答</summary>

**不要です。**アロー構文であっても、**switch文である限り**defaultは不要というルールがそのまま適用されます。該当するcaseが無ければ何も実行せず素通りするだけで問題ありません（値を返す「switch式」の場合とは異なり、網羅性は求められません）。

</details>

## 問題27

`String s = "\"";`と書いた場合、`s`の文字数（`length()`）はいくつになりますか？

<details><summary>解答</summary>

**1です。** ソースコード上は`\`と`"`の2文字書かれていますが、実際にできる文字列の中身は`"`（1文字）だけです。「ソースコードに書く文字数」と「実行時にできる文字列の中身の文字数」は別物です。

</details>

## 問題28

エスケープシーケンスの`\`（バックスラッシュ）は、文字列データの一部として保存されますか？

<details><summary>解答</summary>

**保存されません。**`\`はそれ自体が文字列の中身になる文字ではなく、「次の1文字を特別な意味で解釈してください」とコンパイラに指示するための記号です。指示を実行し終わったら`\`という記号自体は消えて、指示された結果（この場合`"`という1文字）だけが残ります。

</details>

## 問題29

通常の文字列リテラル（`"..."`）の中に`"`を1個だけ含めたい場合、エスケープは必要ですか？テキストブロック（`"""..."""`）の場合と比べてどうですか？

<details><summary>解答</summary>

**通常の文字列リテラルでは、`"`を1個含めるだけでも常にエスケープが必須です**（`\"`と書く必要がある）。一方テキストブロックでは、`"`は1個・2個までならエスケープ不要でそのまま書けます（3個以上で必須になる）。「どのくらいの連続数からエスケープが要るか」という発動条件が、通常の文字列リテラルとテキストブロックで違います。

</details>

## 問題30

`class A { int num = 10; } class B extends A {} class C extends B { ... super.num ... }`のように3段階の継承があり、`B`が独自の`num`を持たない場合、`C`から`super.num`と書くと何が表示されますか？

<details><summary>解答</summary>

**`10`が表示されます。**`super`は常に直近の`B`だけを指しますが、`B`は`A`から`num`を継承しているだけ（自分では持っていない）ので、「`B`が持っているnum」は実質`A`のnumです。結果的に`A`の値が見えますが、これは`B`を飛び越えて直接`A`にアクセスしたのではなく、あくまで`B`を経由しています。

</details>

## 問題31

同じ状況で、もし`B`が独自に`int num = 20;`を宣言していたら、`C`の`super.num`は何を表示しますか？

<details><summary>解答</summary>

**`20`が表示されます。**`B`自身のフィールドが優先され、`A`の`num`は隠蔽されて見えなくなります。`super`は直近の`B`だけを見るという原則は変わらず、今回は`B`自身が持つ値がそのまま見えます。

</details>

## 問題32

`interface A`のdefaultメソッドを`interface B extends A`が継承し、`class C implements B`から`A.super.sample()`のように**間の`B`を飛び越えて`A`を名指しする**ことはできますか？

<details><summary>解答</summary>

**できません。**`型名.super.メソッド名()`という構文は、その型名が呼び出し元クラスの**直接の**実装/継承対象である場合にしか使えません。`C`は`B`しか直接`implements`していないので、`A`を名指しすることはできず、正しくは`B.super.sample();`と書く必要があります。

</details>

## 問題33

問題30〜32を踏まえると、`super`（または`型名.super`）に共通する原則は何ですか？

<details><summary>解答</summary>

**`super`（または`型名.super`）は、常に自分の直接の1段階上しか見ません。** フィールドの場合、直近の相手（`B`）が自分では持たずそのまま継承しているものは結果的に素通しで見えますが（問題30）、直近の相手が独自に持っていればそちらが優先されます（問題31）。interfaceのdefaultメソッドの場合は、`型名.super`で明示的に名指しする型が直接の関係者でなければならず、間の層を飛び越えて名指しすることはできません（問題32）。現れ方は違いますが、根っこは同じ「直近の1段階しか見ない」という制約です。

</details>

## 問題34

`int[][] arr2 = new int[2][];`と書いた場合、`arr2.length`と`arr2[0]`はそれぞれ何になりますか？

<details><summary>解答</summary>

**`arr2.length`は`2`、`arr2[0]`は`null`になります。**`int[][]`は「`int[]`を要素として持つ配列」で、`new int[2][]`は外側の次元（2）だけを確定させ、内側の次元（各要素が指す`int[]`）は指定しません。各要素は「`int[]`型への参照」としてまだ何も指していない状態＝参照型のデフォルト値`null`になります。

</details>

## 問題35

問題34の`arr2`に対して`arr2[0][0]`にアクセスすると、`ArrayIndexOutOfBoundsException`と`NullPointerException`のどちらになりますか？

<details><summary>解答</summary>

**`NullPointerException`になります。**`arr2[0][0]`は2段階に分解されます。まず`arr2[0]`は`arr2`（長さ2）の範囲内なので成功し、結果は`null`。次に、その`null`に対してさらに`[0]`でアクセスしようとするため、`NullPointerException`が発生します。もし1段階目の添字が範囲外（`arr2[5]`など）であれば`ArrayIndexOutOfBoundsException`になりますが、今回は1段階目が有効範囲内で成功する点がポイントです。

</details>

## 問題36

「中身が空の配列（`{}`のような要素数0の配列）」と「配列の参照が`null`」は同じ状態ですか？

<details><summary>解答</summary>

**別物です。**「要素数0の配列」は、配列自体はきちんと存在していて、ただ有効なインデックスの範囲が無い（`length`が`0`）状態です。一方「参照が`null`」は、配列という実体そのものがまだ作られておらず、参照が何も指していない状態です。`new int[2][]`の各要素は後者（`null`）にあたります。

</details>

## 問題37

`String s = NULL;`（大文字の`NULL`）と書くと、`null`と同じように機能しますか？

<details><summary>解答</summary>

</details>

## 問題39

`public static void sample(int void) {...}`のように、予約語`void`を引数名として使うとどうなりますか？

## 問題40

予約語を識別子として使えないというルールは、引数名だけの特別なルールですか？

<details><summary>解答</summary>

**いいえ、識別子が使われる場所すべてに共通するルールです。**メソッド名（`public void class() {}`）、クラス名（`public class int {}`）、ローカル変数名（`int true = 5;`）のいずれも同じようにコンパイルエラーになります。「引数だから特別」ということはなく、「識別子が必要な場所」という1つの大きなグループ全体に対して、予約語だけがまとめて締め出されています。

</details>

## 問題41

`static`初期化子・インスタンス初期化子・コンストラクタを持つクラスから、同じクラスのインスタンスを2個作った場合、`static`初期化子は何回実行されますか？

<details><summary>解答</summary>

**1回だけです。**そのクラスが最初に使われる（≒最初にロードされる）タイミングで1回だけ実行され、何個インスタンスを作っても2回目以降は実行されません。

</details>

## 問題42

同じ状況で、インスタンス初期化子とコンストラクタは、インスタンスを作るたびに毎回実行されますか？

<details><summary>解答</summary>

**毎回実行されます。**`new`するたびに、インスタンス初期化子とコンストラクタの両方が毎回実行されます。1回の`new`ごとの実行順序は「インスタンス初期化子 → コンストラクタ」です。

</details>

## 問題43

`static`初期化子・インスタンス初期化子・コンストラクタを持つクラスのインスタンスを2個作った場合、全体としての出力順序はどうなりますか？

<details><summary>解答</summary>

**「static初期化子（最初の1回だけ）→ 1個目：インスタンス初期化子→コンストラクタ → 2個目：インスタンス初期化子→コンストラクタ」の順です。**`static`初期化子はクラス全体に対して一番最初に1回だけ割り込み、それ以降は`new`のたびにインスタンス初期化子とコンストラクタのペアが繰り返されます。

</details>

## 問題44

`record`を`extends`して継承しようとすると、どうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「final Bookからは継承できません」というエラーです。`record`は宣言時に何も書かなくても暗黙的に`final`クラスとして扱われるため、継承することはできません。

</details>

## 問題45

`public record Book(String name) {}`のように`public`で宣言したrecordの正準コンストラクタを、明示的に`private`で書くとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「レコードBookに無効な標準コンストラクタがあります((public)より強いアクセス権限を割り当てようとしました)」というエラーです。recordの正準コンストラクタは、recordクラス自身と同じか、それ以上に公開的でなければならず、`public record`の場合は正準コンストラクタも`public`以上（実質`public`のみ）でなければなりません。

</details>

## 問題46

通常のクラス（record ではない）で、`public class Sample { private Sample() {} }`のように、クラス自体は`public`だがコンストラクタは`private`にする、ということはできますか？

<details><summary>解答</summary>

**できます。**通常のクラスでは、クラス自体のアクセス修飾子とコンストラクタのアクセス修飾子は完全に独立していて、合わせる必要が一切ありません（シングルトンパターンなどでよく使われる書き方です）。この点が、recordの正準コンストラクタの特殊なルールとの大きな違いです。

</details>

## 問題47

`interface Test { default void value() {...} } record Data(String value) implements Test {}`のように、recordのcomponent名が、実装するinterfaceの戻り値`void`のメソッド名と一致するとどうなりますか？

<details><summary>解答</summary>

**コンパイルエラーになります。**「戻り値の型Stringはvoidと互換性がありません」というエラーです。`record`は各componentに対して同じ名前・その型を返すアクセサメソッドを自動生成しますが、これは`implements`したインターフェースの同名メソッドに対するオーバーライド（実装）候補として扱われます。`String`と`void`は戻り値として互換性が無いため、実装が成立しません。

</details>

## 問題48

`interface Test2 { Object value(); } record Data2(String value) implements Test2 {}`の場合はどうですか？

<details><summary>解答</summary>

**コンパイルは成功します。**`record`が自動生成する`value()`アクセサの戻り値は`String`ですが、`String`は`Object`のサブタイプなので、共変戻り値のルールにより問題なく実装として成立します。

</details>

## 問題49

問題47のように`void`との不一致でコンパイルエラーになったのは、`void`だからという特別なルールですか？

<details><summary>解答</summary>

**いいえ、特別なルールではありません。**「recordが自動生成するアクセサの戻り値の型」と「インターフェース側が要求する戻り値の型」の間に、通常のオーバーライドと同じ「一致 or 共変（サブタイプ）」という互換性があるかどうかで判定されているだけです。例えば`interface`側が`int`、componentが`String`の組み合わせでも、同じ理由でコンパイルエラーになります。

</details>

## 問題50

`String string1 = new String("java"); String string2 = new String("java");`のように、同じ内容の文字列を`new String(...)`で2回作ると、`string1 == string2`はどうなりますか？

<details><summary>解答</summary>

**`false`になります。**`new String(...)`は呼ぶたびに常に新しいオブジェクトをヒープ上に生成します。定数プールに同じ内容の文字列があるかどうかや、他に何回`new String(...)`したかとは無関係に、毎回別々の実体が作られます。

</details>
