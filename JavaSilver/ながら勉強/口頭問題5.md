# ながら勉強 口頭問題 セット5（static⇔instanceのアクセス方向）

コードを見ずに、言葉だけで考える用。

---

## 問題1：インスタンスメソッドからstaticメンバーへのアクセス

インスタンスメソッドの中から、`static`フィールドや`static`メソッドにアクセスすることはできますか？

<details>
<summary>解答・解説</summary>

**できる（何の制限もなく自由にアクセス可能）**

```java
static int count = 0;
static void hello() { System.out.println("static hello"); }

void run() {
    System.out.println(count);   // OK
    hello();                     // OK
    count++;                     // OK
}
```
→ 検証済み。すべて問題なく動作。

</details>

---

## 問題2：staticメソッドからインスタンスメンバーへのアクセス

逆に、`static`メソッドの中から、インスタンスフィールドやインスタンスメソッドにアクセスすることはできますか？

<details>
<summary>解答・解説</summary>

**できない（コンパイルエラー）**

```java
class Value {
    private String data;
    public static void print() {
        System.out.println(data);   // ← エラー
    }
}
```
```
エラー: staticでない変数 dataをstaticコンテキストから参照することはできません
```

`static`メソッドが呼ばれる時、「どのインスタンスの話か（`this`）」という情報がそもそも存在しない。インスタンスフィールド・インスタンスメソッドは「個々のインスタンスごとに別々に存在するもの」なので、その紐付け先が無い`static`メソッドからは触りようがない。

</details>

## 問題3：なぜ一方通行になるのか（理由を説明せよ）

「instance→staticはOK、static→instanceはNG」というこの一方通行は、なぜ生まれるのか、理由を言葉で説明してください。

<details>
<summary>解答・解説</summary>

**インスタンスの世界は、staticの世界を包み込む、より広い（情報の多い）世界だから**

```
インスタンスの世界 ⊃ staticの世界
```

- **インスタンスメソッド**が呼ばれている時点で、「今どのインスタンスか」という情報（`this`）に加えて、当然「そのクラス全体で共有されているstatic情報」にもアクセスできる（instanceの情報が、staticの情報を包含している）
- **staticメソッド**が呼ばれている時点では、そもそも「今どのインスタンスか」という情報自体が存在しない。なので、それを前提とするインスタンスメンバーには手が届かない

「狭い方（instance）から広い方（static）は覗けるが、広い方（static）から狭い方（instance）は覗けない」というイメージで覚えると一貫している。

</details>

|---|---|---|
| インスタンスメソッド | staticフィールド・staticメソッド | ✅可能 |
| インスタンスメソッド | インスタンスフィールド・インスタンスメソッド | ✅可能（当然） |
| staticメソッド | staticフィールド・staticメソッド | ✅可能 |
| staticメソッド | インスタンスフィールド・インスタンスメソッド | ❌不可能 |
