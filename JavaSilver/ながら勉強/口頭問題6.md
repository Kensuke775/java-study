## 問題1：コンストラクタを1つも書かなかった場合

クラスにコンストラクタを1つも書かなかった場合、何が起こりますか？

<details>
<summary>解答・解説</summary>

**コンパイラが、引数なしの`public`なデフォルトコンストラクタを自動生成する**

```java
class Item {
    // コンストラクタなし
}
new Item();   // OK（自動生成された引数なしコンストラクタが使われる）
```
→ 検証済み。

</details>

## 問題2：引数ありコンストラクタを1つでも書いた場合

もし引数ありのコンストラクタ（例：`Item(String name)`）を1つでも自分で書いた場合、引数なしのデフォルトコンストラクタはどうなりますか？

<details>
<summary>解答・解説</summary>

**自動生成されなくなる（`new Item()`はエラーになる）**

```java
class Item {
    Item(String name) {}   // これを書いた瞬間
}
new Item();   // ← エラー
```
```
エラー: クラス Itemのコンストラクタ Itemは指定された型に適用できません。
  期待値: String
  検出値: 引数がありません
```

「デフォルトコンストラクタの自動生成」は、**コンストラクタが1つも無い場合限定のサービス**。1つでも自分でコンストラクタを書いた時点で、その自動生成は行われなくなる。引数なし版も欲しいなら、自分で明示的に書く必要がある。

</details>

## 問題3：フィールドは、親クラス型の変数経由で見るとどうなるか

```java
class A {
    int value = 100;
}
class B extends A {
    int value = 200;   // Aとは別の、Bだけのvalue
}

B b = new B();
A a = b;   // 同じインスタンスを、A型の変数にも代入
```

`b.value`と`a.value`は、それぞれいくつになりますか？（同じインスタンスなのに違う値になるかどうかも含めて答えよ）

<details>
<summary>解答・解説</summary>

**`b.value`は200、`a.value`は100（同じインスタンスなのに、経由する変数の型によって結果が変わる）**

```
b.value(B型経由)=200
a.value(A型経由)=100
```
→ 検証済み。

**フィールドの参照は、メソッドと違って動的束縛（ポリモーフィズム）が効かない。** どのフィールドを見るかは、**実体（実際にnewしたクラス）ではなく、変数の静的型（宣言された型）**によって決まる。`b`は`B`型なので`B`自身の`value`（200）、`a`は`A`型なので`A`自身の`value`（100）を見る。

**メソッドとの対比**：メソッドのオーバーライドなら、`a.method()`と書いても実体（`B`）の方が動く（動的束縛）。しかしフィールドは、あくまで**その変数の型が持つフィールドに固定**される。この非対称性が試験でよく狙われるポイント。

</details>

## 問題4：ダウンキャストの成否は、何によって決まるか

```java
class A {}
class B extends A {}
class C extends A {}

A a = new B();
B b = (B) a;   // これは成功する？
C c = (C) a;   // これは成功する？
```

`(B) a`と`(C) a`、それぞれ成功しますか？理由も答えよ。

<details>
<summary>解答・解説</summary>

**`(B) a`は成功、`(C) a`は失敗（`ClassCastException`）**

```
1つ目OK
Exception in thread "main" java.lang.ClassCastException: class B cannot be cast to class C
```
→ 検証済み。

`a`の**実体（実際に`new`したもの）は`B`**。ダウンキャストが成功するかどうかは、**「その変数の実体が、キャストしたい型と一致するか（またはそのサブタイプか）」**だけで決まる。`(B) a`は実体そのものなので成功。`(C) a`は、`C`も`A`の子孫ではあるが、`B`とは兄弟同士（無関係）なので、実体が`B`である以上`C`にはなれず失敗する。

**コンパイルは通る理由**：コンパイラは「`A`の子孫であれば理論上あり得る」という上下関係だけを見て許可する（`C`も`A`のサブクラスだから）。実際に成功するかどうかは、実行時の実体次第。

</details>

## まとめ表

| 観点 | 結論 |
|---|---|
| コンストラクタ0個 | 引数なしデフォルトコンストラクタが自動生成される |
| コンストラクタ1個以上（引数あり含む） | 自動生成はもう行われない（自分で書いた分だけが存在する） |
| フィールドの参照先 | 変数の**静的型**で固定（動的束縛は効かない） |
| メソッドの参照先（オーバーライドあり） | 実体（**動的型**）で決まる（動的束縛が効く） |
| ダウンキャストの成否 | コンパイルは型の上下関係だけでOK/NG判定、実行時の成否は**実体**次第 |
