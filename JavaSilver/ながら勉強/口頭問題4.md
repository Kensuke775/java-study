## 問題1：ローカル変数に付けられる修飾子

メソッドの中で宣言するローカル変数に付けられる修飾子は何ですか？（`public`・`private`・`protected`・`static`・`final`のうち当てはまるものを全て選べ）

<details>
<summary>解答・解説</summary>

**`final`だけ**

```java
private int x = 1;   // ← メソッドの中に書くとエラー
```
```
エラー: 式の開始が不正です
```

`public`・`private`・`protected`・`static`はすべて**フィールド専用**の概念（「クラスの外からどう見えるか」「クラス全体で共有するか」という話）。ローカル変数は最初からメソッドの中だけに存在する一時的な変数なので、そもそもこれらの概念が意味を持たない。付けられる可能性があるのは「再代入を禁止する」という`final`だけ。

</details>

## 問題2：ローカル変数にデフォルト値はあるか

フィールド（インスタンス変数・クラス変数）は、初期化しなくても型ごとのデフォルト値（`int`なら0、`String`なら`null`など）が自動で入りました。**ローカル変数にも同じようにデフォルト値は入りますか？**

<details>
<summary>解答・解説</summary>

**入らない**

```java
int x;
System.out.println(x);   // ← エラー
```
```
エラー: 変数xは初期化されていない可能性があります
```

デフォルト値の自動設定は**フィールド限定の恩恵**。ローカル変数には一切適用されず、「使う前に必ず自分で代入しておく（確定代入）」というルールが課される。

**覚え方**：「フィールドは自動でデフォルト値、ローカル変数は自分で初期化必須」

</details>

## 問題3：入れ子のブロックで、同じ名前のローカル変数を宣言できるか

```java
void m() {
    int x = 1;
    {
        int x = 2;   // ← これは書けるか？
    }
}
```

内側の`{}`ブロックの中で、外側と同じ名前`x`を再宣言することはできますか？

<details>
<summary>解答・解説</summary>

**できない（コンパイルエラー）**

```
エラー: 変数 xはすでにメソッド m()で定義されています
```

これは**フィールドとローカル変数のシャドーイング（同名でも共存可）とは全く違うルール**。外側のローカル変数`x`と、内側ブロックの`x`は、**どちらも同じ「メソッド`m()`のローカルスコープ」に属している**ため、名前が衝突する。フィールドとローカル変数は別々のスコープ（クラスレベル/メソッドレベル）だから共存できたが、ローカル変数同士（引数も含む）は、ネストしたブロックの中であっても**同じ土俵にいる**ので重複扱いになる。

</details>

## 問題4：ラムダ式から参照するローカル変数のルール

ラムダ式の中で、外側のローカル変数を使いたい場合、そのローカル変数にはどんな制約がありますか？

<details>
<summary>解答・解説</summary>

**「`final`または実質的final（effectively final）」である必要がある**＝**ラムダ式の外で、その変数への再代入が（`final`を付けていなくても）一切無いこと**

```java
int count = 0;
Supplier<Integer> s = () -> count;
count = 1;   // ← ラムダの外でcountを書き換えると
```
```
エラー: ラムダ式から参照されるローカル変数は、finalまたは事実上のfinalである必要があります
```

`final`と明示的に書かなくても、**実際に一度も再代入されていなければ「実質的final」とみなされOK**。しかし少しでも再代入すると、その時点で条件を満たさなくなり、ラムダ式内での参照がエラーになる。

</details>

## まとめ表

| 観点 | ローカル変数の性質 |
|---|---|
| 付けられる修飾子 | `final`のみ |
| デフォルト値 | 無い（自分で初期化必須、確定代入ルール） |
| 同じスコープ内での名前重複 | 不可（ネストしたブロック・引数も含めて同じ土俵） |
| フィールドとの名前重複 | 可（シャドーイング、別スコープ扱い） |
| ラムダ式からの参照 | `final`または実質的finalであることが必須 |
