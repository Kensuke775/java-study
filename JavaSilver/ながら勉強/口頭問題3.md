# ながら勉強 口頭問題 セット3（varが使える・使えない）

**読み上げる人へ**：各問の問題文だけを読み上げて、回答を待ってください。回答があったら、解答・解説を読み上げてから次の問題に進んでください。

コードを見ずに、言葉だけで考える用。「varがここで使えるか、使えないか」を答える形式。

---

## 問題1：次の書き方のうち、エラーになるものを全て選べ

A. `var x = 1;`（ローカル変数、初期化子あり）
B. `var x;`（ローカル変数、初期化子なし）
C. `var x = 1, y = 2;`（1行で複数同時宣言）
D. `var x = null;`（nullで初期化）
E. `var arr = {1, 2, 3};`（配列初期化子の省略形）

<details>
<summary>解答・解説</summary>

**エラーになる：B・C・D・E（Aだけが正常）**

- B：初期化子が無いと、そもそも型を推論する材料が無いのでエラー（`ローカル変数xの型を推論できません`）
- C：`var`は複合宣言（1行で複数variable宣言）では使えない（`'var'は複合宣言で許可されません`）
- D：`null`だけでは、どんな参照型なのか推論しようがないのでエラー（`変数初期化子は'null'です`）
- E：`{1,2,3}`という配列初期化子の省略形は、**明示的な型（`int[]`など）が無いと使えない**書き方。`var`はその明示的な型そのものを省略する仕組みなので、両方を同時に省略することはできない（`配列初期化子には明示的なターゲット型が必要です`）

**まとめると**：`var`が使えるのは「**型が一意に確定する初期化子が、1つだけ**書かれている場合」だけ。

</details>

## 問題2：varが使える場所・使えない場所

次のうち、`var`が**使えない**場所を全て選べ。

A. メソッドの中のローカル変数
B. メソッドの引数（パラメータ）
C. クラスのフィールド
D. メソッドの戻り値の型
E. 拡張for文（`for (var s : list)`）
F. catch節の例外変数（`catch (var e)`）

<details>
<summary>解答・解説</summary>

**使えない：B・C・D・F（AとEだけが正常）**

- B（引数）：`'var'はここでは許可されません`
- C（フィールド）：`'var'はここでは許可されません`
- D（戻り値の型）：`'var'はここでは許可されません`
- F（catch節）：`'var'はここでは許可されません`
- A（ローカル変数）：もちろんOK（varの本来の用途）
- E（拡張for文）：OK（`for (var s : list)`は、要素の型を右辺のコレクションから推論できるので使える）

**覚え方**：`var`は徹底して「**メソッドの中で完結するローカルな存在**」専用。メソッドのシグネチャ（引数・戻り値）や、クラスの構造（フィールド）、例外ハンドリングの型宣言など、**外から見える／型が契約になる場所には一切使えない**。拡張for文の中だけは「ローカル変数の一種」という扱いなのでOK。

</details>

## 問題3：ラムダ式とvar

`var r = () -> System.out.println("hi");`という書き方は使えますか？理由も答えよ。

<details>
<summary>解答・解説</summary>

**使えない（エラー）**

```
エラー: ローカル変数rの型を推論できません
  (ラムダ式には明示的なターゲット型が必要です)
```

ラムダ式自体は「どの関数型インタフェース（`Runnable`や`Function`など）として使われるか」が決まって初めて意味を持つ。`var`で受けようとすると、右辺（ラムダ式）だけからは**どの関数型インタフェースを実装したいのか判断できない**ため、型推論が成立しない。

正しくは、明示的に型を書く必要がある。

```java
Runnable r = () -> System.out.println("hi");   // OK
```

</details>

## 問題4：`var`という単語自体を変数名として使えるか

```java
int var = 5;
System.out.println(var);
```

これはコンパイルできますか？

<details>
<summary>解答・解説</summary>

**できる（コンパイル成功）**

`var`は完全な予約語（reserved keyword）ではなく、**契約的（contextual）キーワード**。型の位置（宣言の先頭）に書かれた時だけ特別な意味（型推論）を持つが、**変数名・メソッド名としては普通に使える**。

（`record`のコンポーネント名に`record`という単語自体が使えたのと同じ理屈）

</details>

## まとめ表

| 場所 | varが使えるか |
|---|---|
| ローカル変数（初期化子1つのみ） | ✅ |
| 拡張for文の要素 | ✅ |
| メソッドの引数 | ❌ |
| メソッドの戻り値の型 | ❌ |
| クラスのフィールド | ❌ |
| catch節の例外変数 | ❌ |
| 複合宣言（`var a=1, b=2;`） | ❌ |
| `null`だけの初期化 | ❌ |
| 配列初期化子の省略形（`{1,2,3}`） | ❌ |
| ラムダ式だけの初期化 | ❌（ターゲット型が要る） |
| 変数名・メソッド名として`var`を使う | ✅（予約語ではない） |
