# Java用語集

パッと意味が出てこない単語をここにまとめる。増えたら随時追記。

## フィールド（field）

クラス（やレコード、インターフェースなど）の中に**直接**宣言された変数。

```java
class Person {
    int age;        // ← フィールド
    void greet() {
        int local = 1;  // ← これはフィールドではない（ローカル変数）
    }
}
```

## メンバー（member）

クラスの中に属するもの全般を指す**総称**。フィールド・メソッド・コンストラクタ・（内部クラスなど）をまとめて「メンバー」と呼ぶ。

- フィールド → メンバーの一種
- メソッド → メンバーの一種
- コンストラクタ → メンバーの一種

「メンバー」＝上位概念、「フィールド」「メソッド」などはその下位分類、というイメージ。

## アクセス修飾子（access modifier）

クラス・メソッド・フィールド・コンストラクタなどに付けて、「どこからアクセスできるか」を制御するキーワード。

| 修飾子 | アクセスできる範囲 |
|---|---|
| `public` | どこからでも |
| `protected` | 同じパッケージ + サブクラス |
| （何も書かない＝package-private） | 同じパッケージ内のみ |
| `private` | 同じクラスの中だけ |

強さの順：`public > protected > (package-private) > private`

## シグネチャ（signature）

**メソッド名＋引数の型と並び順**のこと。

```java
void method(int a, String b)   // シグネチャ：method(int, String)
```

含まれないもの：戻り値の型、引数の名前、修飾子。オーバーロードが成立するか・重複定義でエラーになるかは、すべて「シグネチャが同じか違うか」で判定される。

## カノニカルコンストラクタ（canonical constructor）

`record`特有の用語。**レコードヘッダーと同じ引数リストを持つコンストラクタ**のこと（暗黙生成か明示的に書くかは無関係、詳細は[[../record/カノニカルコンストラクタ]]）。

## 追加のコンストラクタ

`record`特有の用語。カノニカルとは違う引数リストを持つコンストラクタ。必ず`this(...)`でカノニカルに委譲しなければならない（詳細は[[../record/カノニカルコンストラクタ]]）。
