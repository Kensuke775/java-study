# ボクシングとワイドニングの連鎖ルール

## 核心：暗黙変換は1段階までしか連鎖しない

```java
Double d = Math.round(3.14);   // ← エラー
```

`Math.round(3.14)`の戻り値は`long`（プリミティブ）。代入先は`Double`（ラッパークラス）。必要な変換は2段階。

1. `long → double`（ワイドニング）
2. `double → Double`（ボクシング）

**この2段階を、コンパイラは暗黙的に「まとめて」はやってくれない。**「ラッパークラスだからワイドニングが起きない」のではなく、「**ワイドニング単体、ボクシング単体はそれぞれOKだが、2つを連続でつなげる暗黙変換は認められていない**」というのが正確。

## 解決：キャストで1段階を手動で済ませる

```java
Double d = (double)Math.round(3.14);   // ← OK
```

- `(double)Math.round(3.14)` → 明示的にワイドニングを済ませる（`long→double`を自分でやる）
- 残るは`double → Double`という**ボクシング1段階だけ** → 単体なので暗黙で自動的にOK

他にも`Long.valueOf(...).doubleValue()`のように、先にボクシングしてから`xxxValue()`で目的のプリミティブに変換する方法もある（詳細は[[valueOfとxxxValue]]参照）。

## これは「二次元配列の問題」ではない

```java
Double[][] d = {{0.1, 0.1e-2}, {Math.floor(3.14), Math.round(3.14)}};
```

この形で出題されると「二次元配列・データ型の問題」に見えるが、本質はそこではない。`Double x = Math.round(3.14);`のように配列を使わない1行に単純化しても、全く同じ理由で同じエラーになる。配列はたまたまの出題文脈（入れ物）であって、テーマの中心ではない。

| | 位置づけ |
|---|---|
| ワイドニング | この問題の**本質的なテーマ**（`long→double`の変換連鎖が効くか） |
| キャスト | その問題を**解決する手段**（明示的にワイドニングを1段階済ませる道具） |
| 二次元配列・データ型 | 問題が**出題されている場所（文脈）**であって、テーマそのものではない |

## 用語の整理：アップキャスト／ダウンキャストとは別物

- **アップキャスト／ダウンキャスト** → クラスやインターフェースの**継承関係**専用の用語
- **ワイドニング／ナローイング** → `int`・`long`・`double`などの**プリミティブ型**専用の用語（`byte → short → int → long → float → double`の順で拡大変換＝ワイドニング、逆向きが縮小変換＝ナローイング）

`long → double`は**ワイドニング変換**であり、「アップキャスト」とは呼ばない。

## まとめ

- ❌「ラッパークラスだからワイドニングが起きない」
- ✅「**ワイドニング→ボクシングという2段階の暗黙変換の連鎖は認められない**」
- 解決策：キャストで先にワイドニングだけ手動で済ませれば、残りはボクシング1段階だけになるので通る
