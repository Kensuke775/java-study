# package宣言とディレクトリ構造

## 教材の表記ラベルと実際のフォルダ構造は別物

問題文でよく見る以下のような表記:

```
ex6¥Main.java
ex6¥Foo.java
ex6¥Bar.java
```

これは「この一連のファイルが演習6（ex6）の教材である」ということを示す**教材側のグルーピングラベル**にすぎず、実際にコンパイルする際に必要なディレクトリ構造とは無関係。`ex6¥`という表記のまま1つのフォルダに全部平置きすればよい、という意味ではない。

## 実際のディレクトリ構造は`package`宣言だけで決まる

```java
// Main.java
package ex;

// Foo.java
package ex.a;

// Bar.java
package ex.b;
```

`javac`は「`package ex.a;`と書かれたファイルは、必ず`ex/a/`ディレクトリに置かれている」ことを前提にパッケージ解決を行う。表記上のラベル（`ex6¥`など）がどうであれ、実際に必要な配置は次のように**`package`宣言の内容だけ**が一意に決める。

```
（どこか）/
└── ex/
    ├── Main.java     (package ex;)
    ├── a/
    │   └── Foo.java  (package ex.a;)
    └── b/
        └── Bar.java  (package ex.b;)
```

この対応がずれていると、`import ex.a.Foo;`のような文がクラスを見つけられずコンパイルエラーになる。

## まとめ

- 教材の`ラベル¥ファイル名`という表記 → 単なる「この演習セットに属するファイル」という目印（実在フォルダ名とは限らない）
- 実際に必須のディレクトリ構造 → 各ファイルの`package`宣言だけで一意に決まる
- 「表記がまとまっているから同じフォルダにある」と思い込まず、`package`文を見てディレクトリ構造を組み立てる、という読み方をする
