# -d / -cp（-classpath）のお作法

## それぞれの引数が何を指すか

| コマンド | 何を指定するか |
|---|---|
| `javac Foo.java` | **ソースファイル名**（`.java`ファイル） |
| `javac -d 出力先 Foo.java` | `-d`の後ろ＝**コンパイル結果（.class）の出力先フォルダ** |
| `javac -cp 検索先 Foo.java` | `-cp`の後ろ＝**他のクラスを探しに行く場所（パス）** |
| `java -cp 検索先 クラス名` | `-cp`の後ろ＝**探しに行く場所（パス）**、その後ろ＝**実行するクラス名（ドット区切り）** |

- `-cp`と`-classpath`は完全に同じもの（`-cp`は`-classpath`の短縮形）。効果に一切違いはない
- `javac`／`java`どちらの引数も、**指定した場所にあるクラス全部が必要というわけではない**。「もし必要になったら、そこを探しに行く」という受動的な仕組み

## 検証：-dで指定した出力先と、-cpで指定した検索先が一致していれば動く

```java
// src/ex/x/Test.java
package ex.x;
public class Test {
    public static void main(String[] args) {
        System.out.println("Test's main running");
    }
}
```

```
javac -d classes src/ex/x/Test.java
→ classes/ex/x/Test.class が生成される

java -cp classes ex.x.Test
→ "Test's main running" が出力される
```

```
java -cp classes ex.x.Test
       └──┬──┘  └───┬───┘
       検索場所    実行するクラス名
      （classesフォルダを起点に探す） （public static void mainを持つクラス）
```

## ポイントまとめ

- `-cp`／`-d`で指定するフォルダは、**パッケージ構造の一番上（起点）**。`ex/x/`まで含めた深い場所を指定するわけではない
- 実行対象として`java`コマンドに指定する「クラス名」は、必ず**`public static void main(String[] args)`を持つクラス**でなければならない（違うクラスを指定すると「mainメソッドが見つからない」という実行時エラーになる）
- パッケージがある場合、実行時のクラス名指定は**フォルダ区切り（`/`）ではなくドット区切り**（`ex.x.Test`）
- コンパイル時（`javac`）の引数は**ファイル名**（`.java`）、実行時（`java`）の引数は**クラス名**（パッケージ込みのドット区切り）——ここを混同しない

## 教材上の表記（`ex6¥ファイル名`）に惑わされない

問題文でよく見る`ex6¥Main.java`のような表記は、教材側の「この演習セットに属するファイル」という**グルーピングラベル**にすぎず、実際にコンパイル・実行する際に必要なディレクトリ構造とは無関係。実際の配置は各ファイルの**`package`宣言**だけが一意に決める（詳細は[[宣言について]]を参照）。

## よくある誤答パターン：「〜する必要がある」という架空の依存関係

- 使ってもいない`import static`文が「必要」という主張（実際には無くても困らない）
- 参照してもいないクラスの`.class`ファイルが「クラスパス上に見つかる必要がある」という主張（実際には参照が無ければ探しに行く場面自体が発生しない）

どちらも「本当にそのクラス同士に依存関係があるか」を確認すれば機械的に見抜ける、Silverでよくある引っかけパターン。
