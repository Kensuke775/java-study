# ソースファイルモード（`java Test.java`）でどのクラスが実行されるか

## 一番上のクラスが「機械的に」選ばれる

```java
class First {
    public static void main(String[] args) { System.out.println("First's main"); }
}
class Second {
    public static void main(String[] args) { System.out.println("Second's main"); }
}
```
```
$ java Test.java
First's main
```
→ 検証済み。ファイル名（`Test.java`）と一致するクラスが無くても、**ファイル内で一番上に書かれたクラス**が選ばれて実行される。

## 選ばれたクラスに`main`が無いと、下に`main`があってもそこで即エラー

```java
class First {
    void hello() { System.out.println("First's hello (not main)"); }
}
class Second {
    public static void main(String[] args) { System.out.println("Second's main"); }
}
```
```
$ java Test.java
エラー: クラスにmain(String[])メソッドが見つかりません: First
```
→ 検証済み。`Second`に`main`があっても一切見に行かず、そこで失敗する。

## ポイント：「エントリーポイントを探し回る」のではない

ソースファイルモードの動きは、次の**2段階**に分けて理解するのが正確。

1. **クラスの選定**：ファイル内で一番上に書かれたクラスを、`main`があるかどうかに関係なく機械的に選ぶ
2. **`main`の確認**：①で選ばれたクラスに`public static void main(String[] args)`があるかどうかを確認する。無ければその時点でエラー（②の確認は①で選ばれたクラス**だけ**に対して行われ、ファイル内の他のクラスは一切候補にならない）

「ファイル内のどこかに`main`を持つクラスがあれば、それが実行される」という理解は誤り。**「一番上のクラス」という機械的な位置だけで決まり、そのクラスにたまたま`main`が無ければ、他のクラスに`main`があっても救済されない**、という一貫した仕組み。

## まとめ

| 状況 | 結果 |
|---|---|
| 一番上のクラスに`main`がある | そのクラスの`main`が実行される |
| 一番上のクラスに`main`が無く、下のクラスに`main`がある | エラー（`main`が見つからない）。下のクラスは探しに行かない |
