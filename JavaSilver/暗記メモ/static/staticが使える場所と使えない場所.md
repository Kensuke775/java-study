# staticが使える場所と使えない場所

## `static`を付けられる場所・付けられない場所

| 対象 | `static`を付けられるか |
|---|---|
| トップレベルのクラス自体 | ❌（`public static class T {}`はエラー） |
| クラス直下のフィールド | ✅ |
| クラス直下のメソッド | ✅ |
| クラスの中にネストしたクラス（インナークラス） | ✅（`static class Inner {}`） |
| クラス直下の初期化ブロック（`static { ... }`） | ✅ |
| ローカル変数（メソッドの中の変数） | ❌ |
| メソッドの中に書く`static class`・`static {}` | ❌ |

**ポイント：`static`が使えるのは「クラス本体の直下」だけ**。「インスタンスメソッドか`static`メソッドか」は関係なく、**メソッドという箱の中に入った時点で、`static`付きの宣言は一切書けなくなる**。

## 検証：トップレベルクラスに`static`

```java
public static class T {
}
```
```
エラー: 修飾子staticをここで使用することはできません
```

## 検証：クラス直下ならOK（フィールド・メソッド・ネストクラス・初期化ブロック）

```java
public class T2 {
    static int x = 1;          // staticフィールド
    static void m() {}         // staticメソッド
    static class Inner {}      // staticネストクラス
    static {                   // static初期化ブロック
        x = 2;
    }
}
```
→ コンパイル成功（検証済み）。

## 検証：メソッドの中には`static`付きの宣言が一切書けない

```java
void method() {
    static String cont = "";   // ← エラー（ローカル変数にstaticは不可）
}
```
```
エラー: 式の開始が不正です
```

```java
void method() {
    static class Local {}   // ← エラー
}
```
```
エラー: 式の開始が不正です
```

```java
void method() {
    static {   // ← エラー
        int x = 1;
    }
}
```
```
エラー: 式の開始が不正です
```

## staticメソッドの中は「インスタンスの情報」を一切持てない

`static`メソッドは、どのインスタンスにも紐づかずに（`new`しなくても）呼び出せる。そのため、`static`メソッドの中には「今どのインスタンスの話をしているか」という情報（＝`this`）がそもそも存在しない。

### ①インスタンスメソッドは呼べない

```java
class Value {
    void instanceMethod() {}
    static void staticMethod() {
        instanceMethod();   // ← エラー
    }
}
```
```
エラー: 非staticメソッドinstanceMethod()を、staticコンテキストから参照することはできません
```

### ②インスタンス変数（フィールド）にも触れない

```java
class Value {
    private String contents;
    public static void print() {
        System.out.println(contents);   // ← エラー
    }
}
```
```
エラー: staticでない変数 contentsをstaticコンテキストから参照することはできません
```

### ③`this`自体も使えない（詳細は[[../this/staticメソッドの中では使えない]]）

`this.method()`や`this.field`も、結局は上の①②と同じ理由でエラーになる（`this`が指すべき「今のインスタンス」がstaticコンテキストには存在しないため）。

## 「触れない」のは自分自身（暗黙のthis）だけ。引数で渡されたインスタンスは触れる

上の②は「`contents`という書き方（レシーバー無し＝暗黙の`this.contents`）」がエラーになる例。しかし、**引数として明示的に渡されたオブジェクトのフィールドになら、staticメソッドの中からでも自由にアクセスできる**。

```java
public class T {
    int num = 10;

    static void bad() {
        num *= 2;   // ← エラー（暗黙のthis.numとして解釈される）
    }
    // エラー: staticでない変数 numをstaticコンテキストから参照することはできません

    static void modify(T t) {
        t.num *= 2;   // ← OK
    }

    public static void main(String[] args) {
        T obj = new T();
        modify(obj);
        System.out.println(obj.num);   // → 20
    }
}
```
→ 検証済み。

### なぜ違うのか

- `bad()`の中の`num`は、書かなくても実際には`this.num`と解釈される（**自分自身**への暗黙アクセス）。staticメソッドには`this`（今の自分）という概念が無いので、これはエラーになる
- `modify(T t)`の中の`t.num`は`this`を一切使っていない。`t`は**引数として明示的に渡された、他のオブジェクトへの参照**であり、「そのオブジェクトが持つフィールドに、名前を指定してアクセスしている」だけの普通のフィールドアクセス

**正確なルールは「staticメソッドは`this`が使えない（＝暗黙の自分自身にアクセスできない）」であって、「オブジェクトのフィールドに一切触れない」ではない。** 引数などで明示的に渡されたオブジェクト経由なら、staticメソッドからでも他のインスタンスのフィールド・メソッドは自由に読み書き・呼び出しできる。「参照渡しで受け取ったオブジェクトの中身を書き換える」という定番パターン（`modify(Sample s)`のような例）は、まさにこの仕組みが土台になっている。

## `new`でインスタンスを作ること自体は、staticとは無関係にいつでもできる

```java
public class T {
    int num = 10;
    void hello() { System.out.println("hello, num=" + num); }

    public static void main(String[] args) {
        T obj = new T();              // (1) newでインスタンス生成
        obj.hello();                  // (2) 生成したインスタンスのメソッド呼び出し
        System.out.println(obj.num);  // (3) 生成したインスタンスのフィールド読み取り
        obj.num = 20;                 // (4) 生成したインスタンスのフィールド書き込み
        new T().hello();              // (5) newした直後に即座にメソッド呼び出し
    }
}
```
→ 検証済み。すべてコンパイル・実行成功。

`new Xxx()`は「新しいオブジェクトを1つ作る」という操作であって、`this`（今の自分）とは無関係。static文脈だろうがインスタンス文脈だろうが、`new`はどこでも自由に書ける。`new Child().num`のように、newした直後にそのままフィールド・メソッドにアクセスする書き方も、この意味で何の問題もない。

## できる／できないの一覧

| やっていること | 例 | staticメソッドの中でOKか |
|---|---|---|
| インスタンスを`new`で作る | `new T()` | ✅ OK |
| 作った（または渡された）オブジェクトのメソッドを呼ぶ | `obj.hello()` | ✅ OK |
| 作った（または渡された）オブジェクトのフィールドを読む・書く | `obj.num` / `obj.num = 20` | ✅ OK |
| `this`というキーワード自体を使う | `this.hello()` | ❌ エラー |
| レシーバーを省略して、自分（このクラス）のインスタンスメンバーを呼ぶ | `hello();`（`this.hello()`の省略形） | ❌ エラー |
| レシーバーを省略して、自分（このクラス）のインスタンスフィールドに触る | `num *= 2;`（`this.num`の省略形） | ❌ エラー |

**禁止されているのは「`this`という単語（や、その省略形）を使うこと」だけ**。`new`で作ったオブジェクトや、引数で渡されたオブジェクトは、`this`とは無関係の「ただの変数」にすぎないので、それを経由したアクセスはstaticかどうかに関わらず自由にできる。

## まとめ

- `static`が書けるのは「クラス本体の直下」だけ（トップレベルクラス自体・ローカル変数・メソッドの中身には書けない）
- `static`メソッドの中では、`this`もインスタンスメソッドもインスタンス変数も一切触れない（「今どのインスタンスの話か」という文脈が存在しないため）
- ただしこれは「**自分自身（暗黙のthis）**」に限った話。**引数として明示的に渡されたオブジェクト**のフィールド・メソッドには、staticメソッドの中からでも普通にアクセスできる
- 逆に、`static`同士（`static`フィールド・`static`メソッド）へのアクセスは、`static`メソッドの中からでも普通にできる
