# static ⇔ インスタンスメソッドの再定義エラー

`static`メソッドは「オーバーライド」の対象外。親と子で`static`かどうかが食い違うと、方向がどちらでもコンパイルエラーになる。

- **インスタンス → static**（親がインスタンスメソッド、子で`static`にする）→ ❌ エラー
- **static → インスタンス**（親が`static`、子でインスタンスメソッドにする）→ ❌ エラー

## 問題51：親がstatic、子がインスタンスメソッド

```java
interface A {
    default void operate() {
        System.out.print("Start... ");
    }
}
class Super {
    static void print() {
        System.out.print("SUPER ");
    }
}
class Sub extends Super implements A {
    public void operate() {
        A.super.operate();
        System.out.print("Sub#Start... ");
    }
    public void print() {          // ← ここでエラー（16行目）
        super.print();
        System.out.print("SUB ");
    }
}
```

```
エラー: Subのprint()はSuperのprint()をオーバーライドできません
オーバーライドされたメソッドはstaticです
```

`Super.print()`が`static`なのに、`Sub.print()`は`static`が付いていない**インスタンスメソッド**として再定義しようとしている → エラー。

## 逆パターン：親がインスタンスメソッド、子がstatic

```java
class Super {
    void print() {
        System.out.print("SUPER ");
    }
}
class Sub extends Super {
    static void print() {          // ← ここでエラー
        System.out.print("SUB ");
    }
}
```

```
エラー: Subのprint()はSuperのprint()をオーバーライドできません
オーバーライドするメソッドがstaticです
```

こちらも同じ理由でエラー。エラーメッセージの主語が変わる点に注意（「オーバーライド**され**た方（親）がstatic」か「オーバーライド**する**方（子）がstatic」か）。

## まとめ


| 親        | 子                 | 結果                                    |
| -------- | ----------------- | ------------------------------------- |
| `static` | `static`（同じシグネチャ） | ✅ OK（オーバーライドではなく「隠蔽（hiding）」という別の仕組み） |
| インスタンス   | インスタンス            | ✅ OK（通常のオーバーライド）                      |
| `static` | インスタンス            | ❌ コンパイルエラー                            |
| インスタンス   | `static`          | ❌ コンパイルエラー                            |


**ポイント**：`static`はクラスに紐づく処理で、動的束縛（実行時にインスタンスの実体を見て呼び分ける仕組み）に一切乗らない。そのため「オーバーライド」という概念自体が`static`メソッドには適用されず、親子で`static`の有無が一致していないと即エラーになる。`static`同士なら再定義自体は可能だが、それは「オーバーライド」ではなく「隠蔽（hiding）」と呼ばれる別ルール。
