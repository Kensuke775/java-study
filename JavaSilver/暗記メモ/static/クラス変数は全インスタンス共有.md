# クラス変数（static）は全インスタンスで共有される（問題28）

## インスタンス変数とクラス変数の違い

| | 宣言 | 実体 |
|---|---|---|
| **インスタンス変数**（例：`name`） | `public String name;`（`static`なし） | **インスタンスごとに別々**に存在する |
| **クラス変数**（例：`id`） | `public static String id;`（`static`あり） | **クラス全体でたった1つだけ**共有される |

```java
class Item {
    public static String id;   // クラス変数
    public String name;        // インスタンス変数
    public Item(String name) {
        this.name = name;
        id = "1";
    }
}
```

## 検証：片方のインスタンス経由での変更が、もう片方にも反映される

```java
Item a = new Item("A");
System.out.print(a.name + a.id + ",");   // A1,
Item b = new Item("B");
System.out.print(b.name + b.id + ",");   // B1,
b.id = "2";                              // ← b経由で書いているが、実体は共有のstatic id
a.name = "C";                            // aだけのnameフィールドを変更（idには影響なし）
System.out.print(a.name + a.id + ",");   // C2,  ← idがさっき"2"に変わっている
System.out.print(b.name + b.id + ",");   // B2,
```
```
A1,B1,C2,B2,
```
→ 検証済み。

`a.id`と`b.id`は、書き方こそ違うが**中身は完全に同じ変数**を指している。`b.id = "2"`と書いた瞬間、`a.id`も同時に`"2"`になる（新しく`a`専用の`id`が存在するわけではないため）。

## 「newのたびに1に戻る」は自動的な性質ではない

コンストラクタの中に`id = "1";`という代入コードが書いてあるから、**newして実行するたびに、その代入が実行されて結果的に上書きされている**だけ。「static変数はnewされると自動でリセットされる」という性質があるわけではない。もしコンストラクタにこの行が無ければ、`id`は一度設定されたらそのまま保持され続ける。

## まとめ

- インスタンス変数：`new`するたびに独立した値を持てる（別々の箱）
- クラス変数（`static`）：クラス全体でたった1つの箱を、どのインスタンス経由でアクセスしても共有している
- `obj.staticフィールド`のように書けても、実体はインスタンスに紐づかない、クラス全体で1つの変数
