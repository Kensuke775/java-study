# Objectクラスのメソッド

## すべてのクラスは暗黙で`Object`を継承している

```java
class Value {
    // 何も書いていなくても、Objectから継承したtoString()/equals()/hashCode()が最初から使える
}
```

自分で`extends`を書かなくても、Javaのすべてのクラスは最初から`java.lang.Object`を継承している。そのため、どんなクラスにも最初から`toString()`・`equals()`・`hashCode()`などが備わっている（中身をカスタマイズしたい時に**オーバーライド**する）。

## 代表的な3つ

| メソッド | 役割 |
|---|---|
| `toString()` | インスタンスを文字列化する時に使われる |
| `equals(Object)` | インスタンス同士の「等しさ」を判定する |
| `hashCode()` | ハッシュベースのコレクション（`HashMap`など）で使われる整数値 |

## `toString()`：`println`や文字列連結で自動的に呼ばれる特別なメソッド

```java
class Value {
    public String data;
    public Value(String data) { this.data = data; }

    public String toString() {
        return this.data;
    }
}

Value v = new Value("B");
System.out.println(v);        // → B（v.toString()が自動的に呼ばれる）
System.out.println(v.data);   // → B（フィールドに直接アクセス、toStringは呼ばれない）
```

`System.out.println(オブジェクト)`や`オブジェクト + "文字列"`（文字列連結）は、内部で自動的にそのオブジェクトの`toString()`を呼び出す、という仕組みがJavaに組み込まれている。

- `println(v)` → `v.toString()`が呼ばれ、その**戻り値**が表示される
- `println(v.data)` → `toString()`は一切呼ばれず、フィールドの値がそのまま渡される

たまたま`toString()`の中身が`this.data`をそのまま返す実装なら結果は同じに見えるが、経由するルート（メソッド経由 vs フィールド直接）は全く別物。`toString()`の中身を変えれば、`println(v)`の表示内容だけが変わる。

**`toString()`という決まった名前で`Object`のデフォルト実装をオーバーライドしない限り**、`println`にはこのカスタマイズは反映されない。別名（例：`getInfo()`）のメソッドを定義しても、`println`から自動的に呼ばれることはない。

オーバーライドしなかった場合のデフォルトの`toString()`は、`クラス名@ハッシュ値`という形式（例：`Value@7344699f`）を返す。

## `this`は引数と名前衝突していなければ省略可能

```java
public String toString() {
    return this.data;   // これでも
    return data;        // これでも、意味は全く同じ
}
```

`this`が必須になるのは、引数名とフィールド名が衝突していて区別が必要な場合（例：コンストラクタの`this.data = data;`）。`toString()`のように引数が無いメソッドでは、名前の衝突が起きないので`this`は省略可能な、単なるスタイルの違いにすぎない。
