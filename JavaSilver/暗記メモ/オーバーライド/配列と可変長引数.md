# 配列と可変長引数

## 「1つのメソッド内の別引数」と「2つの別メソッド」は話が違う

**1つのメソッドの中の、別々の引数として共存する場合 → 問題なし**

```java
public void f(double[] d1, double... d2) {}
```
→ コンパイル成功。`d1`と`d2`は同じメソッドの別々の引数同士で、比較対象（重複する相手）がそもそも存在しない。

**同じ名前で、配列版と可変長引数版の「2つの別メソッド」を定義する場合 → エラー**

```java
public static void main(String[] args) {}
public static void main(String... args) {}
```
```
エラー: mainでmain(String...)とmain(String[])の両方を宣言することはできません
```

## なぜ2つの別メソッドの方はダメなのか：型として完全に同一

`T...`（可変長引数）は、バイトコードでは**`T[]`と完全に同一の型**として扱われる（シンタックスシュガー）。`...`が追加しているのは「呼び出し方のバリエーション」だけで、型としての新しい区別を何も生み出していない。

- `main(String[] args)` → 実体は「`String[]`を1つ受け取るmain」
- `main(String... args)` → 実体も「`String[]`を1つ受け取るmain」

同じシグネチャのメソッドを2回定義したことになるため、重複宣言エラーになる。

## 可変長引数は「配列」でも「個別の値」でも渡せる（呼び出し方だけの違い）

```java
static void f(int... x) { ... }

f(1, 2, 3);              // ✅ 個別の値を並べて渡せる
f(new int[]{1, 2, 3});   // ✅ 配列をそのまま渡すこともできる
```

```java
static void f(int[] x) { ... }

f(1, 2, 3);              // ❌ エラー（実引数リストと仮引数リストの長さが異なります）
f(new int[]{1, 2, 3});   // ✅ これしかできない
```

| | 型としての正体 | 呼び出し方 |
|---|---|---|
| `int... x`（可変長引数） | `int[]` | `f(1,2,3)`も`f(配列)`も両方OK |
| `int[] x`（配列） | `int[]` | `f(配列)`だけOK |

## 検証：`f(1)`や`f(1,2,3)`も、実際には配列を作ってから渡している

```java
static void f(int... x) { System.out.println(x.length); }
f(1);
f(1, 2, 3);
```

バイトコード（`javap -c`）を見ると、呼び出し側で配列生成の命令が挿入されている。

```
// f(1) の部分
newarray       int        ← サイズ1のint配列を新規作成
iconst_0 / iconst_1 / iastore   ← 配列[0]=1
invokestatic   f:([I)V    ← 完成した配列をfに渡す

// f(1, 2, 3) の部分
newarray       int        ← サイズ3のint配列を新規作成
iconst_0/iconst_1/iastore, iconst_1/iconst_2/iastore, iconst_2/iconst_3/iastore
invokestatic   f:([I)V    ← 完成した配列をfに渡す
```

`f`メソッド自体のシグネチャは`f:([I)V`（`int[]`を1つ受け取る）という1種類のみ。「`f(1)`や`f(1,2,3)`という書き方」は**呼び出し側だけに用意された省略記法**であり、メソッドに実際に渡っているものは常に配列そのもの。

## まとめ

- `...`が追加しているのは「呼び出し方のバリエーション」だけで、型としての新しい区別を何も生まない
- だから配列版と`...`版を両方定義すると、コンパイラには「同じものを2回書いた」としか見えず重複エラーになる
- 一方、1つのメソッドの中で配列引数と可変長引数を別々のパラメータとして持つのは、比較対象が無いので普通に共存できる
