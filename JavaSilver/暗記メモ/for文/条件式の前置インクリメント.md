# for文の条件式に前置インクリメントを使った場合の挙動

## 条件式が`++i`（前置）だと、本文実行前にすでに1つ進んでいる

```java
int[] array = {10, 20, 30};
for (int i = 0; ++i < array.length; i++) {
    System.out.println("i=" + i);
}
```
```
i=1
```
→ 検証済み。1回しか実行されない。

流れ：

1. `i = 0`（初期化、最初の1回だけ）
2. `++i < array.length` を評価 → **先に`i`を`1`にしてから**`1 < 3`を判定 → `true`
3. 本文実行（この時点で`i`はすでに`1`） → `i=1`と出力
4. `i++` → `i`が`2`になる
5. 条件を再評価 → `++i`で`i`が`3`になってから`3 < 3`を判定 → `false` → 終了

## 条件式が`++i`、更新式が`i++`だと、1周ごとに+2ずつ進む

```java
int[] array = {10, 20, 30, 40, 50, 60, 70};   // length=7
for (int i = 0; ++i < array.length; i++) {
    System.out.println("i=" + i);
}
```
```
i=1
i=3
i=5
```
→ 検証済み。

- 更新式の`i++`で+1
- 次の周の条件式`++i`でさらに+1

なので**1周ごとにトータル+2**進む。ただし最初の1回目だけは、初期化直後にまだ更新式（`i++`）を通っていないので、条件式の`++i`による+1だけが効いて`i=0→1`からスタートする。

## ポイント

- 「更新式の`i++`（後置）は最後に評価される」という話とは別に、**「条件式自体が前置インクリメントだと、その条件式の評価タイミングで先に加算されてしまう」**という、条件式側の前置/後置の違いによる影響がある
- 前置か後置かで、本文が実行される時点での`i`の値が変わってくるので、出力結果を予測する時は「どのタイミングで、前置か後置か」を1つずつ丁寧に追う必要がある
