# instanceof（継承関係との判定）

## サブクラスは「親クラスでもある」ので、instanceofは親クラス側でtrueになる

```java
class A {}
class B extends A {}

static void test(Object obj) {
    if (obj instanceof A) {
        System.out.println("A判定:true -> " + obj.getClass().getSimpleName());
    }
}

Object[] objects = { new A(), new B(), "c" };
for (Object obj : objects) {
    test(obj);
}
```
```
A判定:true -> A
A判定:true -> B
（"c"は何も出力されない）
```

`B extends A` なので、「`B`のインスタンスは`A`でもある」という関係が成り立つ。そのため `obj instanceof A` は、`new A()`だけでなく`new B()`に対しても**true**になる。`"c"`（`String`）のように`A`と無関係な型だけが`false`。

**覚え方**：「`B`は`A`を持っている（＝`B` is-a `A`）」ので、`instanceof A`の判定は`A`本人にも、`A`を継承した`B`にも通る。`instanceof`は「その型ちょうど」ではなく「**その型、またはそのサブタイプかどうか**」を判定している。

`interface`の実装関係でも同じ考え方が成り立つ（`class B implements A` でも `b instanceof A` はtrue）。

## Object[]やList<Object>に色んな型を混ぜられる理由

```java
Object[] objects = { new A(), new B(), "c" };
```
`String`も`A`も`B`も、すべて`Object`のサブタイプなので、`Object`の入れ物に混ぜて入れられる。
