# instanceofパターン変数のスコープ（elseの中では使えない）

## 検証コード

```java
public static String test(Object obj) {
    String s = "";
    if (obj instanceof String str) {
        s = obj.toString();
    } else {
        s = str.toLowerCase();   // ← ここでエラー
    }
    return s;
}
```
```
エラー: シンボルを見つけられません
            s = str.toLowerCase();
                ^
  シンボル:   変数 str
```
→ 検証済み。**コンパイルエラー**。

## なぜ`else`の中で使えないのか

`obj instanceof String str`で作られるパターン変数`str`は、**「`obj instanceof String`がtrueだった場合」にしか存在しない**。

- `if`ブロックの中 → `obj instanceof String`が`true`だったからここに来ている → `str`は確実に存在する → ✅使える
- `else`ブロックの中 → `obj instanceof String`が`false`だったからここに来ている → `str`はそもそも生成されていない → ❌未定義

「`if`の中でしか使えない」という単純な話ではなく、**「その条件が成立した、という事実が保証されている範囲でしか使えない」**というのが正確な理解（フロースコープ／definite assignmentの一種）。

## 反転（`!`）すれば、逆に`else`側どころか`if`の外でも使えるようになる

```java
if (!(obj instanceof String str)) {
    return "not a string";   // ここでreturn/throw/continue/breakなどで抜ける
}
// ここから先はstrが使える（elseが無くても！）
System.out.println(str.toLowerCase());
```

条件を`!`で反転させ、**trueだった場合（＝objがStringではなかった場合）に必ずメソッドを抜ける**ようにしておくと、その`if`ブロックを通過した後の残りのコードでは「`obj`は必ず`String`だった」ということが保証されるため、`str`がそのまま使えるようになる。これが「反転すればスコープが伸びる」というテクニック。

## まとめ

| 書き方 | `str`が使える範囲 |
|---|---|
| `if (obj instanceof String str) { ... } else { ... }` | `if`の中だけ。`else`の中では使えない |
| `if (!(obj instanceof String str)) { return; } ...` | `if`ブロックを抜けた後の残りのコード全体で使える |

「`if`の中でしか使えない」と丸暗記せず、「**その条件が成立したことが保証されている場所でしか使えない**」という原則で考えると、反転パターンも含めて一貫して理解できる。
