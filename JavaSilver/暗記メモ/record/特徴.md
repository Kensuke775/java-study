# recordの特徴

## recordにはsealed/non-sealedが書けない（構文エラー）

`record`には`sealed`も`non-sealed`もそもそも書けません（構文エラー）。`record`は常に暗黙で`final`なので、sealed階層の一員として扱うための追加修飾子自体が不要かつ書けないのです。

```java
sealed interface Foo permits Product {
    void methodZ();
}
non-sealed record Product(int id) implements Foo {   // ← 構文エラー
    public void methodZ(){}
}
```
```
エラー: class, interface, enumまたはrecordがありません
```

選択肢Gの例（`non-sealed record`）自体がコンパイルエラーを起こす無効な例なので、この記述は誤りです。

## この問題最大のポイント

`class`が継承階層で使う`final`/`sealed`/`non-sealed`という3択は、`record`には一切適用されません（`record`は常に`final`固定で、それ以外の修飾子を付ける余地が構文上そもそも存在しない）。「レコードだからsealedにするなら特別な書き方が必要」という発想自体が罠で、正しくは「レコードには最初から`sealed`系の修飾子を書く必要も書く余地もない」という結論です。

`sealed`インターフェースを実装するレコードは、修飾子なし（デフォルト）か`final`（暗黙のものを明示するだけ）のどちらかしか書けません。
