# recordの宣言構文ルール

## `record`キーワードは、名前の直前に置かないと成立しない

```java
Record record(String name) {}
```
```
エラー: class, interface, enumまたはrecordがありません
```

`record`キーワードが`Record`という名前の前に置かれていないと、コンパイラは「戻り値`Record`・メソッド名`record`・引数`String name`」という**普通のメソッド宣言**として解釈しようとする。しかしトップレベルに書けるのは`class`/`interface`/`enum`/`record`のいずれかの型宣言だけなので、宙に浮いたメソッド定義は構文エラーになる。「`record`はクラス名（型名）より前に置く必要がある」というだけの単純な話。

## `record`は`extends`できない

```java
record Product(double price) extends Record {}
```
```
エラー: '{'がありません
```

`record`は自動的に`java.lang.Record`を継承する仕組みになっており、**自分で明示的に`extends クラス名`を書くことは構文上許されていない**（`record`の後には`implements インターフェース`は書けても`extends クラス`は書けない）。

## `record`は元々暗黙で`final`（明示してもしなくても継承不可）

```java
final record Product(int... x) {}   // finalは冗長だが無害
record Product(int... x) {}         // これでも同じく継承不可
```

`record`は書いても書かなくても暗黙で`final`。`final`を明示的に書いてもコンパイルは通るが、書かなくても最初から継承不可能という結論は変わらない（詳細は[[特徴]]参照）。

## コンポーネント名に予約語っぽい単語を使うのは合法

```java
public record Record(Object record) {}   // コンポーネント名が"record"でもOK
```
→ コンパイル成功。`record`は完全な予約語ではなく**契約的（contextual）キーワード**なので、変数名・コンポーネント名として使うこと自体は問題ない。

## 検証問題（問題13）

```java
A. public record Record() {}
B. Record record(String name) {}
C. public record Record(Object record) {}
D. record Product(double price) {}
E. record Product(double price) extends Record {}
F. final record Product(int... x) {}
```

コンパイルエラーが発生するもの（2つ選択）→ **B、E**

| | 判定 | 理由 |
|---|---|---|
| A | ✅正常 | 引数無しのrecordも合法 |
| **B** | ❌エラー | `record`キーワードが無く、宙に浮いたメソッド宣言になっている |
| C | ✅正常 | コンポーネント名に`record`という単語を使うこと自体は合法 |
| D | ✅正常 | 基本形 |
| **E** | ❌エラー | `record`は`extends`できない（自動でRecordを継承するため） |
| F | ✅正常 | `final`は冗長だが無害（recordは元々暗黙でfinal） |
