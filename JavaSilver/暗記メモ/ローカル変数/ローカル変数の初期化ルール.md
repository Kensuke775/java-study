# ローカル変数の初期化ルール（確定代入）

## `var`だけが特別（宣言と同時に必ず初期化）

```java
var x;   // ← エラー（varは宣言時に初期化子が無いと型を推論できない）
```

`var`は右辺の式から型を推測する仕組みなので、初期化子（`= 値`）が無いとそもそも型が決まらず、宣言することすらできない。

## `int`・`final int`は「宣言時」の初期化は不要

```java
int TEST;              // OK（宣言だけ、代入は後回しでもよい）
final int VALUE;       // OK（同上）
```

どちらも「宣言と同時に代入する必要はない」という点は共通。違いは:

- `int TEST;` → 後から**何度でも**再代入できる
- `final int VALUE;` → 後から代入できるのは**1回だけ**（2回目の代入はエラー）

## 確定代入（definite assignment）ルール

どちらも共通して守るべきルールは**「実際に読み取ろうとする箇所があるなら、そこに到達するまでに必ず1回は代入されていること」**だけ。逆に言えば、**一度も読み取らないなら、代入すらしなくてもコンパイルは通る**。

```java
void test() {
    final int VALUE;   // 一切代入しない
    // 何もしない
}
```
→ コンパイル成功（使わなければ未代入のままでもOK）。

## まとめ表

| | 宣言時に初期化必須か | 再代入の回数制限 |
|---|---|---|
| `var` | ✅ 必須（型推論のため） | 制限なし |
| `int` | ❌ 不要 | 制限なし |
| `final int` | ❌ 不要 | **1回だけ** |

「`final`＝絶対にその場で代入しなきゃいけない」は誤解で、実際には「その場での初期化が必須なのは`var`だけ」。`final`が課しているのは「回数制限（1回まで）」の方。

## 検証問題：ex14/Main.java（問題14）

```java
public class Main {
    protected void main(int a) {           // (A)
        final var FLAG = true;
        final int VALUE;                   // (B)
        if (!FLAG) VALUE = 100;            // (C)
        System.out.println(VALUE);         // (D)
    }
    public static void main(String[] args) {
        new Main().main(100);
    }
}
```

→ **(D)の行でコンパイルエラー**（`変数VALUEは初期化されていない可能性があります`）

### なぜエラーになるのか

`FLAG`は`true`というリテラルで初期化された`final`変数＝**コンパイル時定数**。そのため`!FLAG`は**常にfalse**であることがコンパイラにも分かっており、`if (!FLAG) VALUE = 100;`という代入は**絶対に実行されない**（＝`VALUE`はどの経路を辿っても代入されないまま）。

その未代入の`VALUE`を`System.out.println(VALUE);`で**読み取ろうとした瞬間**、確定代入ルールに引っかかりコンパイルエラーになる。

- `println`が無ければ（`ex14/Main.java`の実際のコードのように）VALUEを一切読み取らないので、代入されていなくても**コンパイルは通る**
- `println(VALUE);`を足すと、その時点で初めて「読み取る前に必ず代入されているか」が問われ、`FLAG`が定数`true`である以上`VALUE`は絶対に代入されていないため、**コンパイルエラーになる**

「FLAGがfalseになることが無いから代入が起きず、その代入されていない箇所を出力しようとしているためコンパイルエラーになる」という理解で正確。
