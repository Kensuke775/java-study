# 引数はすべて「値渡し」（プリミティブは値のコピー、参照型は参照のコピー）

## プリミティブ型：呼び出し元の変数とは別物のコピーが渡される

```java
int num = 10;
modify(num);
System.out.println(num);   // → 10（変わらない）

private static void modify(int num) {   // ← 呼び出し元とは別の、新しいローカル変数
    num *= 2;   // このnum（引数側のコピー）だけが20になる
}
```
→ 検証済み。出力は**10**のまま。

`modify(int num)`の`num`は、呼び出し元の`num`と**名前が同じだけで実体は別の変数**。呼び出し時に、呼び出し元の`num`の**値（10）だけがコピーされて**、`modify`側の新しいローカル変数（引数）に渡される。

- 加算されるのは、あくまで`modify`側が持っている**コピーされた方**の`num`
- 呼び出し元の`num`は、そのコピー元として値を貸しただけで、その後は一切関与しない（別の変数なので、コピー先をどういじっても影響を受けない）

**イメージ**：同じ名前の付箋を2枚用意して、片方（呼び出し元）の数字を、もう片方（引数側）に書き写した状態。書き写した後の付箋（引数側）にいくら書き込んでも、元の付箋（呼び出し元）は無傷のまま。

## 参照型：オブジェクトそのものはコピーされず、「参照（矢印）」だけがコピーされる

```java
Sample s = new Sample(10);
modify(s);
System.out.println(s.num);   // → 20（変わる）

private static void modify(Sample s) {
    s.num *= 2;
}
```
→ 検証済み。出力は**20**。

`modify(Sample s)`の`s`も、呼び出し元の`s`とは別の変数（コピーされている）という点はプリミティブと同じ。しかし今回コピーされているのは**「どのオブジェクトを指しているかという矢印（参照）」**であって、**指し示す先の実体（`Sample`インスタンス）はコピーされず、たった1つだけ共有されている**。

そのため`modify`の中で`s.num *= 2`とすると、共有している実体のフィールドを書き換えることになり、呼び出し元の`s.num`にもその変更が反映される。

## まとめ：どちらも「値渡し」だが、コピーされるものの中身が違う

| | コピーされるもの | 呼び出し先での変更が呼び出し元に影響するか |
|---|---|---|
| プリミティブ（`int`など） | 値そのもの | ❌ 影響しない（完全に別々の値になる） |
| 参照型（`Sample`など） | オブジェクトへの参照（矢印） | ✅ 影響する（矢印の先の実体は1つを共有しているため） |

Javaの引数渡しは常に「値渡し」（call by value）で統一されている。ただし参照型の場合の「値」とは**参照（矢印）そのもの**を指すため、結果として「実体を共有しているように見える」だけ、という理解が正確（「参照渡し」という言葉自体はJavaの正式な仕組みとしては存在しない）。
