# ひし形継承問題（diamond problem）

## どんな形か

複数のインターフェースを実装していて、**同じシグネチャのメソッドが複数の経路から降ってくる**ことで衝突が起きる問題。図にするとひし形（◇）になることからこう呼ばれる。

```
              A (interface, abstract sample())
             /                                \
      B extends A                        C extends A
   (defaultでsample→"B")            (defaultでsample→"C")
             \                                /
                  D implements B, C
```

`B`と`C`が両方とも`A`から派生し、両方とも`sample()`を`default`で実装している。`D`はその両方を`implements`しているので、「どちらの`sample()`を使うか」が衝突する。

## 検証コード

```java
interface A {
    void sample();
}

interface B extends A {
    default void sample() {
        System.out.println("B");
    }
}

interface C extends A {
    @Override
    default void sample() {
        System.out.println("C");
    }
}

public class D implements B, C {
    @Override
    public void sample() {
        super.sample();   // ← これがNG
    }
}
```
```
エラー: シンボルを見つけられません
        super.sample();
             ^
  シンボル: メソッド sample()
```

## ポイント①：`D`が自分で`sample()`をオーバーライドすること自体は必須かつ正しい対応

`B`・`C`両方が同じシグネチャの`default`メソッドを持っている以上、`D`は必ず自分で`sample()`をオーバーライドして衝突を解消しなければならない（オーバーライドせずに放置するとコンパイルエラー）。

## ポイント②：衝突解消の中で、どちらかの実装を呼びたい時は`ただのsuper`では書けない

- クラスの継承なら`super.method()`でOK
- しかし**インターフェースが複数絡む衝突解消の場面では、ただの`super`という構文がそもそも存在しない**

```java
public void sample() {
    B.super.sample();   // ← これなら"B"を呼べる
    // または
    C.super.sample();   // ← これなら"C"を呼べる
}
```

`インターフェース名.super.メソッド名()`という専用構文で、**「どちらの`default`実装を使いたいか」を名指しで指定する**必要がある。`super.sample()`（インターフェース名無し）は「曖昧だからエラー」なのではなく、「そんな書き方自体がJavaに存在しないので、シンボルが見つからない」というエラーになる。

## まとめ

| | 内容 |
|---|---|
| 衝突が起きる条件 | 複数のインターフェースが、同じシグネチャの`default`メソッドを持ち、それを1つのクラスが両方`implements`する |
| 解消方法 | 実装クラスが必ず自分でそのメソッドをオーバーライドする |
| オーバーライドの中身 | 呼びたい方を`インターフェース名.super.メソッド名()`で明示的に指定する（ただの`super.メソッド名()`は使えない） |
