# interface概要

## 暗黙で付く修飾子


| 対象                    | 暗黙で付くもの                                    |
| --------------------- | ------------------------------------------ |
| 変数（定数）                | `public static final` の3つすべて               |
| 本体のないメソッド（abstract）   | `public abstract`                          |
| `default`メソッド         | `public`（`default`は書く必要あり）                 |
| `static`メソッド          | `public`（`static`は書く必要あり）                  |
| インターフェース自体（トップレベル）    | ❌ 何も付かない（`class`と同じくデフォルトでpackage-private） |
| インターフェース自体（クラスの中にネスト） | ✅ 暗黙で`static`が付く                           |


- インターフェース自体の可視性（`public`かどうか）は自動では付かない点に注意（中身のメンバーはpublic強制なのに、外側の型自体は無指定のまま、という非対称な仕組み）

## 定数（フィールド）へのアクセス

- `public static final`が暗黙で付くため、**再代入は不可**（`final変数に値を代入することはできません`エラー）
- **インスタンス経由でもアクセス可能**（`obj.CONST`）。ただし`static`変数を式（インスタンス）経由でアクセスする形になるため、警告が出る（エラーではない）
  - 警告文例：`static 変数は式ではなく型名Xで修飾する必要があります`



## staticメソッドへのアクセス（フィールドと全く違うルール）

`interface Test { static double calc() {...} }` を `class Main implements Test` が実装している場合:


| 呼び出し方                       | 結果                |
| --------------------------- | ----------------- |
| `Test.calc();`（インターフェース名経由） | ✅ 成功              |
| `m.calc();`（実装クラスのインスタンス経由） | ❌ `シンボルを見つけられません` |
| `Main.calc();`（実装クラス名経由）    | ❌ `シンボルを見つけられません` |
| `calc();`（実装クラス内から無修飾で呼ぶ）   | ❌ `シンボルを見つけられません` |


- **interfaceのstaticメソッドは実装クラスに一切継承されない**（staticフィールドは継承されてインスタンス経由でも呼べるのと対照的）
- 呼び出せるのは**「インターフェース名.メソッド名()」の1パターンのみ**



### 検証問題（問題6-15、p.377）

```java
public interface Test {
    String TEST_NAME = "Test";
    double TEST_VALUE = 5.0;
    static double calc() {
        return TEST_VALUE * TEST_VALUE;
    }
}
class Main implements Test {
    public static void main(String[] args) {
        Main m = new Main();
        // insert code here
    }
}
```

`Test:25.0`と出力するために挿入できるコード（2つ選択）:

- A. `System.out.println(m.TEST_NAME + ":" + m.calc());` → ❌（`m.calc()`が継承されずエラー）
- B. `System.out.println(Test.TEST_NAME + ":" + Test.calc());` → ✅
- C. `System.out.println(m.TEST_NAME + ":" + Test.calc());` → ✅（フィールドはインスタンス経由でもOK、staticメソッドはインターフェース名経由必須という組み合わせ）
- D. `System.out.println(TEST_NAME + ":" + calc());` → ❌（`calc()`が無修飾でも継承されずエラー）
- E. `System.out.println(Test.TEST_NAME + ":" + m.calc());` → ❌（`m.calc()`がエラー）

→ **正解：B、C**

**ポイント**：フィールド（定数）は「インスタンス経由でも警告付きで可」だが、staticメソッドは「インターフェース名経由以外は問答無用でコンパイルエラー」。この非対称性が最大の狙い。



## CharSequence実装クラス一覧（参考）

- `String` / `StringBuilder` / `StringBuffer` / `CharBuffer`
- ❌ `char`（プリミティブなのでそもそも対象外）、`Character`（1文字のスカラー値であり「並び」ではないため対象外）



## 定数（フィールド）の参照方法まとめ：3パターンすべてOK

`static`メソッドとは違い、**interfaceの定数フィールドは実装クラスに継承される**ため、以下の3通りすべてで参照できる。

```java
public interface Test {
    String TEST_NAME = "Test";
    double TEST_VALUE = 5.0;
}
class Main implements Test {
    public static void main(String[] args) {
        Main m = new Main();
        System.out.println(TEST_NAME);        // ① 無修飾 → OK
        System.out.println(m.TEST_NAME);      // ② インスタンス経由 → OK（警告あり）
        System.out.println(Test.TEST_NAME);   // ③ インターフェース名経由 → OK
    }
}
```


| 参照方法                            | 結果         | 補足                                                                                       |
| ------------------------------- | ---------- | ---------------------------------------------------------------------------------------- |
| ① `TEST_NAME`（無修飾）              | ✅ OK       | 実装クラス内から、継承した定数をそのまま名前だけで参照できる                                                           |
| ② `m.TEST_NAME`（インスタンス経由）       | ✅ OK（警告あり） | `static`変数をインスタンス式で修飾する形になるため、`警告:[static] static 変数は式ではなく型名Testで修飾する必要があります`が出る。エラーではない |
| ③ `Test.TEST_NAME`（インターフェース名経由） | ✅ OK       | 最も素直な書き方。警告も出ない                                                                          |


**staticメソッドとの対比**（前述の「staticメソッドへのアクセス」表を参照）：

- 定数（フィールド）→ ①②③すべてOK（継承されるため）
- staticメソッド → **③（インターフェース名経由）のみOK**、①②はどちらも「シンボルを見つけられません」エラー

「フィールドは継承されるが、interfaceのstaticメソッドは継承されない」という非対称性が、この一連のテーマ全体の核心。
