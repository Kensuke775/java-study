# インターフェースのフィールド

## interfaceのフィールドは暗黙で`public static final`

```java
interface Test {
    int COUNT = 0;   // ← 実質 public static final int COUNT = 0; と同じ
}
```

修飾子を何も書かなくても、interfaceのフィールド（定数）には自動的に`public static final`の3つ全部が付く。

## `final`なので、再代入・インクリメント/デクリメントは一切できない

```java
interface Test {
    int COUNT = 0;
}
class Main implements Test {
    public static void main(String[] args) {
        COUNT++;   // ← エラー
    }
}
```
```
エラー: final変数COUNTに値を代入することはできません
```

`COUNT++`や`COUNT = 1`のような**値を変更する操作は、代入である以上すべてアウト**。`final`は「一度値が決まったら二度と変更できない」という制約なので、単純な代入だけでなく、インクリメント演算子（`++`/`--`）や複合代入演算子（`+=`など）による変更もすべて「再代入」とみなされ、同じエラーになる。

**選択肢に`i++`や`COUNT += 1`のような書き方が出てきたら、「これは代入操作だ」と気づけるかどうかが分かれ目**。見た目がインクリメント演算子だからといって「代入ではない特別な操作」ではなく、あくまで中身は「現在の値に1足して、それを再代入する」という**代入の一種**であることを忘れないこと。

## まとめ

- interfaceのフィールド＝暗黙で`public static final`
- `final`なので、通常の代入だけでなく`++`/`--`/`+=`などの複合代入・インクリメント演算子による変更もすべてコンパイルエラー
