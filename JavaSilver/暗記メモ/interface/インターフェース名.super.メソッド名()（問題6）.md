# `型名.super.メソッド名()`で特定のdefault実装を呼ぶ（問題6）

## お題

```java
public interface A {
    default void sample() {
        System.out.println("Hello");
    }
}

public interface B extends A {
}

public class C implements B {
    @Override
    public void sample() {
        // ここでAのdefault実装（"Hello"）を呼んでから"Java"を出したい
        System.out.println("Java");
    }
}

public class Main {
    public static void main(String[] args) {
        A a = new C();
        a.sample();
    }
}
```

選択肢：`super.sample();` / `A.super.sample();` / `public.sample();` / `new.sample();` / `上記のいずれも誤りである`

→ **正解は「上記のいずれも誤りである」。** 選択肢に含まれる書き方はどれもコンパイルエラーになる。

## 検証1：`A.super.sample();` → コンパイルエラー

```java
public class C implements B {
    @Override
    public void sample() {
        A.super.sample();
        System.out.println("Java");
    }
}
```
```
エラー: Aは内部クラスを囲みません
        A.super.sample();
         ^
```
→ 検証済み。

**理由**：`型名.super.メソッド名()`が使えるのは、その型名が**呼び出し元クラスの直接の`implements`/`extends`対象**である場合だけ。`C`は`B`を直接`implements`しているが、`A`は直接実装していない（`B extends A`を通じた間接的な関係でしかない）ので使えない。

## 検証2：`super.sample();`（型名なし） → コンパイルエラー

```java
super.sample();
```
```
エラー: シンボルを見つけられません
        super.sample();
```
→ 検証済み。`C`のスーパークラスは`Object`だけで、`sample()`は継承していないため見つからない。

## 検証3：`A.sample();`（static呼び出しの形） → コンパイルエラー

```java
A.sample();
```
```
エラー: staticでないメソッド sample()をstaticコンテキストから参照することはできません
        A.sample();
```
→ 検証済み。`sample()`はdefaultメソッド＝インスタンスメソッドなので、`型名.メソッド名()`という静的呼び出しの形では解釈できない。

`public.sample();`・`new.sample();`はそもそも構文として成立しないので論外（キーワードの誤用）。

## 検証4：正しい呼び方 `B.super.sample();` → 成功

```java
public class C implements B {
    @Override
    public void sample() {
        B.super.sample();
        System.out.println("Java");
    }
}
```
```
Hello
Java
```
→ 検証済み。`C`は`B`を直接`implements`しているので条件を満たす。`B`自身は`sample()`をオーバーライドしていないので、実質的に`A`のdefault実装がそのまま呼ばれる。

## まとめ

| 書き方 | 結果 | 理由 |
|---|---|---|
| `super.sample();` | ❌ | `C`のスーパークラス（`Object`）に`sample()`が無い |
| `A.super.sample();` | ❌ | `A`は`C`の**直接の**実装対象ではない（`B`を経由した間接関係） |
| `A.sample();` | ❌ | `sample()`はインスタンスメソッドなのでstatic呼び出しの形は不可 |
| `B.super.sample();` | ✅ | `B`は`C`が直接`implements`している型なので条件を満たす |

- `型名.super.メソッド名()`は「暗黙のthisはそのまま使うが、どの親のdefault実装を使うか型名で指定する」専用構文
- 使える条件は「型名が呼び出し元クラスの**直接の**実装/継承対象であること」。間接的な祖先（`extends`の先の先）は指定できない
- この問題は「呼ぶ手段自体が存在しない」のではなく、「用意された選択肢の中に正しい書き方（`B.super.sample()`）が含まれていない」という引っかけ

## フィールドの`super`と共通する原則：「直近の1段階しか見ない」

`class C extends B extends A`で、`B`が独自の`num`を持っていない場合、`C`から`super.num`と書くと`10`（`A`の値）が見える（[[フィールドはオーバーライドされず隠蔽される（静的型でアクセス先が決まる）]]参照）。これは「`B`を飛び越えて直接`A`にアクセスした」わけではなく、`super`は常に直近の`B`だけを指しており、`B`が自分では持たずそのまま`A`から継承しているものが、結果的に素通しで見えているだけ。

今回の`A.super.sample()`が使えないのも同じ原則の現れ。`型名.super`という構文で**明示的に`A`を名指ししてアクセスしようとする**のは、`A`が`C`の直接の関係者でない限り許されない。

| | 直近の1段階を素通しで見る（OK） | 間にある層を飛び越えて名指しする（NG） |
|---|---|---|
| フィールド | `super.num`（`B`が持たないので`A`のものが見える） | （このような明示的な飛び越し構文は無い） |
| interfaceのdefault | `B.super.sample()`（`B`は直接implementsしているのでOK） | `A.super.sample()`（`A`は間接関係なのでNG） |

どちらも「`super`（または`型名.super`）は自分の直接の1段階上しか見ない」という同じ制約の異なる現れ方。
