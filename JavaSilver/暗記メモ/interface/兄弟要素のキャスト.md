# キャスト（instanceof関連）

## 問題48：sealed + interfaceのキャストとClassCastException

```java
sealed interface One permits Derived { String NAME = "ONE"; }
sealed class Base permits Derived { protected String name = "Base"; }
final class Derived extends Base implements One {}

Base b = new Derived();
One o = (One)b;                  // (A) 成功：bの実体はDerivedなのでOneにキャスト可
System.out.print(o.NAME);        // ONE
Derived d = (Derived)o;          // (B) 成功：oの実体は依然Derived
System.out.print(d.name);        // Base（Derivedが継承したBaseのフィールド）
o = (One)new Base();             // (C) ★ここでClassCastException（実行時）
System.out.print(o.NAME);        // (D) ← 到達しない
```

→ 正解：**C**（実行時に`ClassCastException`）

### ポイント1：見た目が同じキャストでも「実体」次第で結果が変わる

- `(One)b`（実体が`Derived`）→ 成功（`Derived`は`implements One`）
- `(One)new Base()`（実体が`Base`そのもの）→ 失敗（`Base`は`One`を実装していない）

`sealed class Base permits Derived`となっていても、`Base`型の変数には理論上`Derived`が入りうるため、コンパイラは`(One)b`のようなキャストを**コンパイル時にはエラーにできない**（実行時にチェックされるcheckedキャストとして許可される）。しかし`new Base()`と明示的に`Base`自身を生成した場合、実体は確定して`Base`のままなので、実行時に失敗が確定する。

### ポイント2：選択肢D「Dでコンパイルエラー」が誤りな理由

- Dの行（`o.NAME`）自体は文法的に問題なくコンパイルが通る
- そもそもCで例外が飛ぶため、Dの行には実行が到達しない
- 「コンパイルが通るか」と「実行時にそこへ到達できるか」は別問題



### 補足：`o.NAME`はそもそも`o`の中身を見ていない

`NAME`はリテラルで初期化された`public static final`＝**コンパイル時定数**。`javap -c`で確認すると、`o.NAME`は実際には`o`をロードして`pop`（即座に破棄）し、代わりに文字列リテラル`"ONE"`を直接埋め込んだコードにコンパイルされる。つまり「もし仮に8行目のキャストが成功していたら、`Base`インスタンスは`One`を実装していないので`NAME`にアクセスできないはず」という直感は成り立たない——`o`の実体が何であっても`o.NAME`は関係なく`"ONE"`に置き換わる（`o`が`null`でも`NullPointerException`にすらならない）。
