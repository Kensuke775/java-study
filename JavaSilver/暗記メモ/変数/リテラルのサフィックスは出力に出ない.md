# リテラルのサフィックス（L・fなど）は、出力には一切出ない

## 検証

```java
long b = 10L;
float f = 3.5f;
double d = 3.5;
System.out.println(b);   // 10
System.out.println(f);   // 3.5
System.out.println(d);   // 3.5
```
```
10
3.5
3.5
```
→ 検証済み。`L`も`f`も、出力には一切現れない。

## ポイント：`L`・`f`・`d`は「ソースコード上で、コンパイラにリテラルの型を伝えるための記号」でしかない

```java
long b = 10L;    // "この10という数値はlong型ですよ"とコンパイラに伝えるための L
float f = 3.5f;  // "このリテラルはfloat型ですよ"と伝えるための f
```

これらのサフィックスは、**あくまでソースコードを書く時点だけの話**。実際に変数の中に格納されている値そのものには「型を表す文字」など付いていない（`long`型の変数の中身は、ただの整数値`10`でしかない）。

`println`が表示するのは、あくまで**値そのもの**であって、「その値がどうやってリテラルとして書かれたか（`L`付きだったか、何も付いていなかったか）」という情報は、実行時にはもう残っていない。

## 補足：`int`から`long`へのワイドニングでも同様

```java
long a;
a = 1;   // int の 1 が、long にワイドニングされて代入される
System.out.println(a);   // → 1
```

`a = 1;`のように`int`リテラルを`long`変数に代入しても（暗黙のワイドニング）、出力される時にはただの`1`。「`long`型だから`1L`と表示されるはず」という思い込みは誤り。

## まとめ

- ソースコード中の`L`・`f`・`d`などのサフィックスは、**コンパイラに型を伝えるための記号**であり、値そのものの一部ではない
- `println`で出力されるのは値そのものだけ。サフィックスが付いていようが省略されていようが、出力結果には一切影響しない
