# ArrayListの特徴

## 検証コード

```java
ArrayList<String> list = new ArrayList<>();
list.add("a"); list.add("a"); list.add("a");
// → [a, a, a]  size=3（重複OK）

list.add(null);
// → [a, a, a, null]（nullもOK）

ArrayList<Integer> big = new ArrayList<>();
for (int i = 0; i < 1000; i++) { big.add(i); }
// → 1000件入れてもsize=1000（サイズが自動で伸びる）

ArrayList<String> pos = new ArrayList<>();
pos.add("A"); pos.add("C");
pos.add(1, "B");   // 位置を指定して挿入
// → [A, B, C]
```
→ すべて検証済み。

## 正しい説明・誤った説明（3つ選択問題の例）

| 説明 | 正誤 |
|---|---|
| `null`は使えない | ❌ 誤り（`null`も要素として格納できる） |
| 動的な配列として動作する | ✅ 正しい |
| 重複した値は扱えない | ❌ 誤り（重複を問題なく格納できる） |
| スレッドセーフではない | ✅ 正しい |
| 値を追加する箇所を制御できる | ✅ 正しい |

## それぞれの意味

### 「動的な配列」＝サイズが自動的に伸び縮みする

普通の配列（`int[]`など）は`new`した時点でサイズが固定され、後から伸ばせない。`ArrayList`は内部で固定サイズの配列を持ちつつ、容量が足りなくなると**自動的により大きな配列を作り直して中身をコピーし直す**ことで、見た目上「自由にサイズが伸びる配列」のように振る舞う。これが「動的配列（dynamic array）」の意味で、単に「中身を変更できる（ミュータブル）」という一般的な性質とは異なる、**「サイズそのものが可変」という、より限定された意味**。

### 「スレッドセーフではない」＝複数スレッドからの同時アクセスに弱い

「スレッドセーフ」とは、複数のスレッドが同時にアクセス・変更しても、データが壊れたり矛盾した状態にならないこと。`ArrayList`は内部で同期処理（ロックなど）を一切行っていないため、複数スレッドから同時に変更されると、データ破損や`ConcurrentModificationException`のような予期しない挙動が起きうる。同様の機能を持つスレッドセーフ版として`Vector`が存在する（対比としてよく出題される）。

### 「値を追加する箇所を制御できる」＝add(int index, E element)

`add(E e)`（末尾に追加のみ）だけでなく、`add(int index, E e)`で挿入位置を自分で指定できる（詳細は[[List型かArrayList型か]]参照）。

## まとめ

- `ArrayList`は**重複値OK・`null`もOK**（`Set`のような排除の仕組みは無い）
- **動的配列**：サイズ固定の普通の配列と違い、容量が足りなくなると自動的に拡張される
- **非スレッドセーフ**：同期処理が無いため、複数スレッドからの同時変更には弱い（`Vector`が同期版）
- **挿入位置の制御可**：`add(int index, E e)`で末尾以外にも挿入できる
