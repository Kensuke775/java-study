# finalメソッドの特徴

## finalメソッドの意味

- 通常のメソッドは、サブクラスで同じシグネチャで再定義（オーバーライド）して動作を変えられる
- `final`を付けたメソッドは、そのクラスで書かれた実装が「これが最終形、これ以上変更させない」と固定される
- サブクラス側で同名・同シグネチャのメソッドを書こうとすると、コンパイルエラーになる

```java
class A {
    final void methodY() {
        System.out.println("A's methodY");
    }
}
class B extends A {
    void methodY() {   // オーバーライドしようとする
        System.out.println("B's methodY");
    }
}
```
```
エラー: BのmethodY()はAのmethodY()をオーバーライドできません
オーバーライドされたメソッドはfinalです
```

## 用途

そのメソッドの動作が「どんなサブクラスでも絶対に変わってほしくない、変えられると困る」場面で使う。セキュリティに関わる処理や内部の重要なアルゴリズムなど、サブクラスに勝手に上書きされるとバグや脆弱性の原因になる処理を守るために使う。

## クラスのfinalとの違い

- **finalクラス**：そのクラス自体を継承できなくする（サブクラスを一切作れない）
- **finalメソッド**：クラスは継承できるが、そのメソッドだけはオーバーライドできなくする（部分的な固定）

「クラス全体を封じるほどではないが、この1つのメソッドだけは絶対に変えさせたくない」という時に使う。finalクラスでなくてもfinalメソッドは宣言できる。
