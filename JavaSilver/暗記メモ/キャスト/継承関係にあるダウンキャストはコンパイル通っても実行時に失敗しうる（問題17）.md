# 継承関係にあるダウンキャストはコンパイル通っても実行時に失敗しうる（問題17）

## お題

```java
class A {
    void hello() { System.out.println("A"); }
}
class B extends A {
    void hello() { System.out.println("B"); }
}

public class Main {
    public static void main(String[] args) {
        A a = new A();
        B b = (B) a;   // ← ここでどうなる？
        b.hello();
    }
}
```

→ 答えは「実行時に例外がスローされる」。

## 検証1：コンパイルは通る

```
（コンパイルエラー無し）
```
→ 検証済み。`A`と`B`は継承関係（`B extends A`）にあるので、`(B) a`という書き方自体は文法的に成立する。

## 検証2：実行するとClassCastException

```
Exception in thread "main" java.lang.ClassCastException: class A cannot be cast to class B
	at Main.main(Main.java:4)
```
→ 検証済み。

## なぜこうなるのか

`a`の実体（`new`で実際に作られたもの）は**正真正銘の`A`のインスタンス**であり、`B`のインスタンスではない。ダウンキャストが安全に成功するのは「実体が本当にそのサブクラス（またはさらにそのサブクラス）である場合」だけ。今回は実体が`A`そのものなので、「`A`を`B`として無理やり扱おうとする」ことになり、JVMが実行時に矛盾を検知して`ClassCastException`をスローする。

コンパイラは「継承関係があるかどうか」＝「理論上、実行時にうまくいく可能性があるかどうか」だけをチェックする。可能性がある（継承関係がある）場合は「実際に動かしてみないと分からない」ので、判断を実行時のJVMに委ねる。

## 検証3：継承関係が全く無い型へのキャストは即コンパイルエラー

```java
class Unrelated { }

A a = new A();
Unrelated u = (Unrelated) a;
```
```
エラー: 不適合な型: AをUnrelatedに変換できません:
        Unrelated u = (Unrelated) a;
```
→ 検証済み。継承関係が無い（可能性がゼロ）場合は、実行を待たずその場でコンパイルエラーになる。

## まとめ

| キャスト対象の関係 | コンパイル | 実行時 |
|---|---|---|
| 継承関係が**ある**（`B extends A`など） | ✅ 通る | 実体次第（実際にその型でなければ`ClassCastException`） |
| 継承関係が**全く無い**（`A`と`Unrelated`） | ❌ その場でエラー | （そもそも実行に至らない） |

「継承関係にあるキャストなら常にコンパイルが通る」＝「実行時も必ず成功する」ではない。コンパイル時チェックは「可能性の有無」だけを見ており、「実際に成功するか」は実体の型で決まる、という2段階構造。
