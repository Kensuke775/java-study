# インスタンス経由のメソッド呼び出しとキャストの結合順序（問題2-6）

## 検証コード

```java
B b = new C();
A t = new C();

b.test(1);            // (1)
(A)b.test(2);          // (2)
((A)b).test(3);        // (3)
t.test(4);             // (4)
(A)t.test(5);          // (5)
((A)t).test(6);        // (6)
```
（`A`はinterface、`B`は`test`を持たないクラス、`C`は`B extends`かつ`A implements`）

コンパイルエラーになるのは **(1)・(2)・(5)**。

## 核心ルール：`(型)変数.メソッド()`は、必ず`(型)(変数.メソッド())`と解釈される

**メソッド呼び出し（`.メソッド()`）の方が、キャスト`(型)`より強く結びつく。** カッコで明示的に囲まない限り、`(A)b.test(2)`は「`b`をAにキャストしてから呼ぶ」ではなく、「**`b.test(2)`を先に実行して、その戻り値をAにキャストする**」という意味になる。

```java
(A)b.test(2);
// ↓ 実際の解釈
(A) ( b.test(2) )
```

`b`だけを先にキャストしたいなら、`b`と`(A)`をカッコで明示的にひとまとめにする必要がある。

```java
((A)b).test(3);
// ↓ こう解釈される（bが先にAにキャストされる）
( (A)b ).test(3)
```

## なぜ`(A)b.test(2)`がコンパイルエラーになるのか：本当の原因は「voidだから」ではない

一見、「`test`メソッドの戻り値が`void`なのに、それをAにキャストしようとしているから」というのが原因に見える（実際、教科書の解説もこの説明をしている）。しかし、これは不正確。

### 実験：戻り値をvoidではなく、Stringにしても同じエラーになる

```java
class B {
    String test(int i) { return "x"; }   // voidではなくStringを返す
}
class A {}

B b = new B();
(A)b.test(2);
```
```
エラー: 文ではありません
```
→ 検証済み。`void`をやめても、**全く同じ「文ではありません」エラー**になる。もし「戻り値の型が合わないから」が本当の原因なら、`String→A`への不正なキャストを指摘するエラーが出るはずだが、それすら出てこない。

### 本当の原因：「キャスト式だけを単独の文として書くこと」自体がJavaでは許されていない

```java
Object o = "hello";
(String)o;   // 中身のある正当なキャストでも
```
```
エラー: 文ではありません
```
→ 検証済み。`void`とは無関係に、**キャスト式単体を文として置くこと自体が、そもそもJavaの構文として存在しない**（文として単独で書けるのは、メソッド呼び出し・代入・`new`・インクリメント/デクリメントなどに限られる）。

### 処理される順序

1. **構文チェック**：「この行は、文として成立する形になっているか？」→ `(A)(...)`という**キャスト式だけの形**なのでこの時点でアウト（エラー確定・処理終了）
2. **意味チェック**（メソッドが存在するか、型が合うか等）：①でアウトになった時点で、**そもそも実行されない**

なので`(2)`は、本来「`B`に`test`メソッドが無い」という別の問題も抱えているが、**構文チェックの時点で先に弾かれるため、その意味エラーが表面化する機会そのものが無い**。「2つのエラーが同時に起きている」のではなく、「構文の壁が意味チェックへの到達自体をブロックしている」というのが正確な理解。

## まとめ

| 書き方 | 解釈 | 結果 |
|---|---|---|
| `(型)変数.メソッド();` | `(型)(変数.メソッド())` ← 戻り値をキャスト | ❌ 常に「文ではありません」エラー（戻り値の型に関係なく） |
| `((型)変数).メソッド();` | `((型)変数).メソッド()` ← 先に変数をキャスト | ✅ 正常（型が合っていれば） |

「変数をキャストしてからメソッドを呼びたい」時は、**必ず`(型)変数`の部分をカッコでひとまとめにする**（`((型)変数).メソッド()`の形にする）のが唯一の正しい書き方。`(型)変数.メソッド()`という書き方は、目的を達成する構造として根本的に成立しない。
