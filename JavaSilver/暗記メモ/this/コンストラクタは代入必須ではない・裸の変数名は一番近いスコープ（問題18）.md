# 普通のコンストラクタは代入必須ではない／裸の変数名は一番近いスコープを指す（問題18）

## お題

```java
class Sample {
    private int num;
    public Sample(int num) {
        // ここに何を書けば、new Sample(10)でgetNum()が10を返すか（2つ選択）
    }
    public int getNum() { return num; }
    public void setNum(int num) { this.num = num; }
}
```

選択肢：`this.num = num;` / `this->num = num;` / `num = num;` / `setNum(num);` / `super.setNum(num);`

→ 正解は **`this.num = num;`と`setNum(num);`の2つ**。

## 前提：普通のコンストラクタはフィールドへの代入義務が無い

recordの正準コンストラクタは、コンパイラが自動生成するアクセサ・`equals`・`hashCode`が「全フィールド初期化済み」を前提にしているため、代入が強制される（[[カノニカルコンストラクタ]]参照）。しかし**普通のクラスのコンストラクタはただのメソッドの一種**で、中身は完全に自由。

```java
class Empty {
    private int num;
    public Empty(int num) {
        // 何もしない
    }
    public int getNum() { return num; }
}
// new Empty(10).getNum() → 0
```
→ 検証済み。コンパイルは通り、`num`は`int`のデフォルト値`0`のまま。

## 検証：各選択肢

| 選択肢 | 結果 |
|---|---|
| `this.num = num;` | ✅ `10`と表示 |
| `this->num = num;` | ❌ 構文自体が存在しない（C++の書き方、Javaには無い） |
| `num = num;` | ❌ `0`と表示（下記で解説） |
| `setNum(num);` | ✅ `10`と表示 |
| `super.setNum(num);` | ❌ コンパイルエラー（`Sample`の親は`Object`で`setNum`など存在しない） |

## `num = num;`がダメな理由：裸の変数名は一番近いスコープを指す

```java
public Sample(int num) {
    num = num;   // 左のnumも右のnumも「引数のnum」
}
```

コンストラクタの引数`num`とフィールドの`num`が同じ名前の場合、`this.`を付けない裸の`num`は**常に一番近いスコープ（＝引数・ローカル変数）を指す**。フィールドの方を指したい時は`this.num`と明示する必要がある。`num = num;`は「引数のnumに、引数のnum自身を代入する」だけの実質何もしない文になり、フィールドの`num`（デフォルト値`0`）は放置される。

## `setNum(num);`が動く理由：代入はコンストラクタ自身でなくても良い

`setNum(int num)`メソッドの中身は`this.num = num;`。コンストラクタから`setNum(num);`と呼び出せば、間接的にフィールドへの代入が行われる。コンストラクタが直接代入する必要はなく、他のメソッド経由でも構わない。

## まとめ

- 普通のコンストラクタは、引数をフィールドへ代入する義務が一切無い（recordの正準コンストラクタとは別ルール）
- 名前が衝突している時、裸の変数名は常に「一番近いスコープ（引数・ローカル変数）」を指す。フィールドを明示したい時は`this.`が必須
- フィールドへの代入は、コンストラクタ直接でも、セッターメソッド経由でも、どちらでも良い
