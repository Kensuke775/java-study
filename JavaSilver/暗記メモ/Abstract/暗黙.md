# abstractは何に暗黙で付く／付かないのか

| 対象 | 暗黙で`abstract`が付くか |
|---|---|
| `interface`自体 | ✅ 付く（`interface`は常に暗黙で`abstract`扱い） |
| `interface`内の本体なしメソッド | ✅ 付く（さらに`public`も暗黙で付く＝`public abstract`） |
| `abstract class`自体 | ❌ 明示的に`abstract`と書く必要がある（自動では付かない） |
| `abstract class`内の本体なしメソッド | ❌ 明示的に`abstract`と書く必要がある（自動では付かない） |

## 検証（`javap -v`でバイトコードのフラグを確認）

```java
interface Foo {
    void m();
}
```
```
flags: (0x0600) ACC_INTERFACE, ACC_ABSTRACT      ← interface自体にABSTRACTが付いている
  void m();
    flags: (0x0401) ACC_PUBLIC, ACC_ABSTRACT     ← メソッドにもPUBLIC・ABSTRACTが付いている
```

## ポイント

- **`interface`は、書かなくても常に`abstract`**（`abstract interface Foo {}`と書いても意味は同じで冗長なだけ）
- **`interface`の中の本体なしメソッドも、書かなくても`public abstract`が自動で付く**
- 一方**`class`の場合は真逆**：`abstract`にしたければ自分で`abstract`と明示する必要があり、クラス内の未実装メソッドにも自分で`abstract`を書く必要がある（省略すると「メソッド本体が無い」という別のエラーになる）
- つまり「`interface`＝暗黙で全部`abstract`寄りに倒れる」「`class`＝暗黙では何も`abstract`にならない」という、正反対の初期値を持っている

## abstract classの抽象メソッドに`public`は必須ではない

`class`（`abstract class`含む）のメソッドは、`interface`と違って`public`が自動で付かないだけでなく、**そもそも`public`にする義務も無い**。フィールドと同じ4段階のアクセス修飾子（無指定／`private`は不可＝オーバーライド前提なので通常使わない／`protected`／`public`）がそのまま使える。

```java
abstract class A {
    abstract void methodX();   // 無指定（package-private）でもOK
}
class B extends A {
    void methodX() {           // 無指定のままオーバーライドもOK
        System.out.println("B's methodX");
    }
}
```
→ 同じパッケージ内なら、無指定のままで普通にコンパイル・実行できる。

### オーバーライド時の制約（一方向のみ）

オーバーライドする側は、元のメソッドよりアクセス範囲を**狭める**ことはできない（**広げる**のはOK）。

| 親のアクセス修飾子 | 子で選べる範囲 |
|---|---|
| 無指定 | 無指定・`protected`・`public`のどれでもOK |
| `public` | `public`しか選べない（狭めるとエラー） |

問題53のBの選択肢は「`public abstract`が暗黙で付く」という、`interface`専用のルールを`abstract class`に誤って当てはめたものだった、という結論に直結する。
