# abstractで先送りできる時・できない時

## defaultメソッドの提供元が1つだけ → abstractで先送りできる

```java
interface X {
    default Number calculate(int price) { return price; }
}
abstract class One implements X {}   // オーバーライドせず放置
class Two extends One {}
```
→ **コンパイル成功**。曖昧さが無いので、いつオーバーライドしてもいい（`abstract`にして先送りする、というよくあるパターン）。

## defaultメソッドの提供元が2つ以上、かつ無関係、かつ衝突 → abstractでも即エラー

```java
interface X {
    default Number calculate(int price) { return (int)(price * 0.05); }
}
interface Y {
    default Number calculate(int price) { return (int)(price * 0.1); }
}
abstract class One implements X, Y {}   // ← abstractにしても
class Two extends One {
    public Number calculate(int price) {
        return Y.super.calculate(price);
    }
}
```
```
エラー: クラス Oneは型XとYからcalculate(int)の関連しないデフォルトを継承します
```
→ **`One`の宣言時点で即コンパイルエラー**。「サブクラス（`Two`）でオーバーライドするから今は待って」は通用しない。

## まとめ

| 状況 | `abstract`で先送りできるか |
|---|---|
| defaultメソッドの提供元が**1つだけ** | ✅ できる（曖昧さが無いので、いつオーバーライドしてもいい） |
| defaultメソッドの提供元が**2つ以上、かつ無関係、かつ衝突** | ❌ できない（`abstract`だろうと`One`の宣言時点で即エラー） |

「1つの継承元から抽象的に受け取って、また次の抽象クラスに渡す」という単線の流れなら、いくら先送りしても問題ない。しかし**「2つ以上の無関係な提供元から同じシグネチャのdefaultが集まってきた瞬間」に、Javaは「今すぐこの場で解決しろ」と要求してくる**——このタイミングの違いが核心。

## 「衝突の解決」と「単なる未実装の先送り」は別物（問題53）

ここまでの話は**「複数の提供元から同じシグネチャが衝突している」**ケース。一方、**「ただ1つの抽象メソッドがまだ実装されていないだけ」**（衝突ではない）なら、`abstract class`でいくらでも先送りできる——ただし、**先送りできる相手も`abstract class`である間だけ**、という点に注意。

```java
interface A {
    public void sample();
}
interface B extends A {
    public void test();
}
abstract class C implements B {
    public void test() { System.out.println("A"); }
    // sample()は実装しない（Cがabstractなので先送りOK）
}
class D extends C {
    public void test() { System.out.println("B"); }
    // sample()にまだ触れていない
}
```
```
エラー: Dはabstractでなく、A内のabstractメソッドsample()をオーバーライドしません
```
→ 検証済み。

`C`が`sample()`を実装しなかったのは合法（`C`自身が`abstract`だから）。しかし`D`は`abstract`ではない**普通のクラス**なので、継承した`sample()`も含めて**全部の抽象メソッドに具体的な中身が揃っていないと即コンパイルエラー**になる。

**まとめると先送りには2種類ある**

| 状況 | 先送りできる条件 |
|---|---|
| 単なる未実装（1本道、衝突なし） | `abstract class`である間はいくらでも先送りできる。ただし最終的に**非abstractなクラスになる地点**では必ず実装必須 |
| 複数の提供元からの衝突（ひし形継承問題） | `abstract`であっても**衝突が発生した瞬間（その`implements`/`extends`を書いた時点）に即座に解決必須**。先送り不可 |

「未実装の先送り」は“いつかは実装する”を許すが、「衝突の先送り」は“いつか”すら許されない、という強さの違いがある。

## 補足：もう1つ別の理由（構文エラー）と混同しないこと

上の例の`Two`側にはさらに別のエラーもある。
```
エラー: Yは内部クラスを囲みません
```
`Y.super`という書き方は、**`Y`を直接`implements`/`extends`しているクラス/インターフェースの中でしか使えない**。`Two`は`Y`を直接実装しておらず`One`を継承しているだけなので、`Y.super`は無効。これは「先送りの可否」の話とは別の、単純な構文ルール違反。
