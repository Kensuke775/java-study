# 抽象メソッドは「継承した具象メソッド」で間接的に満たされてもよい（問題33）

## 検証コード

```java
interface A {
    abstract void x();
}

abstract class B {
    public void x() {}          // Aとは無関係に、Bが独自に持っている具体的なx()
    public abstract void z();
}

public class C extends B implements A {
    // x()は書いていない
}
```
```
エラー: Cはabstractでなく、B内のabstractメソッドz()をオーバーライドしません
```

→ エラーになったのは`z()`だけで、`x()`は何も言われなかった（検証済み）。

## ポイント：`B`が`A`を実装していなくても関係ない

`B`は`interface A`を`implements`していない。それでも、`C`（`extends B implements A`）が持つことになる`x()`の中身は、`B`から継承した`public void x() {}`で**すでに満たされている**。

コンパイラが見ているのは「`B`が`A`を実装宣言しているかどうか」ではなく、**「`C`が最終的に`x()`という名前の具体的な中身（実装）を持っているかどうか」**だけ。継承経由であっても、具体的な中身さえ揃っていれば、それでインターフェースの要求は満たされたことになる。

## 一方、`z()`は`C`が自分で実装しないとエラーになる

`B`は`z()`を`abstract`のまま宣言している（`B`自身は`abstract class`なのでOK）。しかし`C`は`abstract`ではない普通のクラスなので、**継承したものも含めて、すべての抽象メソッドに具体的な中身を用意しなければならない**というルールがある。`z()`の実装が無いとコンパイルエラーになる。

```java
public class C extends B implements A {
    public void z() {}   // これが無いとエラー
}
```
→ これを追加すればコンパイル成功（検証済み）。

## まとめ

- インターフェースの抽象メソッドは、**実装クラス自身が直接書かなくても、継承した先（親クラス）が持つ具象メソッドで間接的に満たせる**
- ただし、**親クラス自身がまだ`abstract`のまま残しているメソッド**（今回の`z()`）は、それを継承した非abstractなクラス（`C`）が自分で実装を書かないとコンパイルエラーになる
- 「`B`が`A`を実装しているかどうか」は無関係。「最終的に`C`が持つメソッド一覧の中に、必要な中身が揃っているか」だけがチェックされる

## 応用：一番上（A）で実装すれば、下（B・C）は何もしなくてよい

```java
interface Greet {
    void hello();
}
class A implements Greet {
    public void hello() { System.out.println("hello from A"); }   // Aが実装
}
class B extends A { }   // 何もしない
class C extends B { }   // 何もしない

new C().hello();   // → "hello from A"
```
→ コンパイル・実行成功（検証済み）。

`A`・`B`・`C`と継承チェーンが続いている場合でも、**`A`が一度きちんと`hello()`を実装していれば、それがそのまま`B`にも`C`にも継承される**。「継承チェーンのどこかで実装済みなら、それ以降のクラス全部で改めて実装し直す必要はない」という理解が正しい（「`A`が実装したら`C`まで全部実装しなきゃいけない」というのは誤り＝むしろ逆で、**`A`で実装済みなら`B`・`C`は何もしなくてよい**）。

もし逆に`A`が実装せず`abstract`のまま残した場合は、実装義務は「継承チェーンの中で、`abstract`ではない最初の具象クラス」に持ち越される（`B`も`abstract`のままなら先送りでき、最終的に普通のクラスとして`new`したい地点で必ず実装しなければならない）。実装義務は**継承チェーンのどこか1箇所で果たされればよく、一度果たされればそれ以降は自動で継承される**、という一貫したルール。
