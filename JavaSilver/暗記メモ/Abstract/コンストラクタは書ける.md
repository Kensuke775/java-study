# abstractクラスの特徴

## abstractクラスでもコンストラクタは書ける

検証：abstractクラスでもコンストラクタは書けます（`new`で直接インスタンス化はできなくても、サブクラスの`super()`から呼ばれるために必要）。

```java
abstract class A {
    int value;
    public A(int value) {
        this.value = value;
        System.out.println("A's constructor: value=" + value);
    }
}
class B extends A {
    public B() {
        super(100);   // 抽象クラスAのコンストラクタを明示的に呼ぶ
        System.out.println("B's constructor");
    }
}
```

```java
B b = new B();
```

```
A's constructor: value=100
B's constructor
```

一方、`A`自身を直接`new`しようとすると:

```java
A a = new A(100);
```

```
エラー: Aはabstractです。インスタンスを生成することはできません
```



## なぜabstractなのにコンストラクタが書けるのか

「インスタンス化できないのに、なぜコンストラクタが必要なのか」という疑問はもっともだが、鍵は**「`new A(...)`で直接使えない」ことと「コンストラクタが一切呼ばれない」ことは別**という点。

- `abstract class`が禁止しているのは「`A`**単体で完成したオブジェクトとして直接生成すること**」だけ
- しかしサブクラス（`B`）をインスタンス化するときは、必ず**継承元（**`A`**）の初期化処理も実行しなければならない**（フィールドの初期値設定など、`A`が担っている責務があるため）
- そのため、`B`のコンストラクタの1行目では暗黙または明示的に`super(...)`が呼ばれ、`A`**のコンストラクタが「部品」として実行される**

つまり`abstract class`のコンストラクタは「**単体で完成品を作るため**」ではなく「**サブクラスがインスタンス化される際に、共通の初期化処理を提供するため**」に存在している。`new A(...)`という**完成品としての直接生成だけ**が禁止されており、コンストラクタという「初期化のための部品」自体は禁止されていない、という整理になる。

## イメージ

- 具象クラス（`B`）→ 完成品の設計図。実際に工場（`new`）で組み立てられる
- 抽象クラス（`A`）→ 完成品の一部を担う「共通パーツ」の設計図。単体では製品にならないが、組み立て工程（コンストラクタチェーン）の中では必ず使われる
