# テキストブロック：ダブルクォーテーションのエスケープ／インデント除去のルール

## 通常の文字列リテラルとの違い：単独・2連続の"はエスケープ不要

通常の`"..."`（1行の文字列リテラル）では、中で`"`を使う時は必ず`\"`とエスケープが必要。しかし**テキストブロック（`"""..."""`）では、単独の`"`（さらに2連続の`""`まで）はエスケープ不要**。

```java
String s1 = """
        He said "hello" to me.
        """;
// → He said "hello" to me.

String s2 = """
        She said ""quoted"" text.
        """;
// → She said ""quoted"" text.
```
→ 検証済み。どちらもコンパイル・実行成功。

## エスケープが必要になるのは「3連続」だけ

閉じ側の区切り文字`"""`と紛らわしくなる**3連続の`"""`**を本文中にそのまま書くと構文エラーになる。

```java
String s = """
        bad """ text
        """;
```
```
エラー: ';'がありません
エラー: テキスト・ブロックの開始区切り文字のシーケンスが無効です
```
→ 検証済み。このケースだけ、一部をエスケープする必要がある。

## まとめ（エスケープ）

| 連続する`"`の数 | エスケープ必要か |
|---|---|
| 1個 | ❌ 不要 |
| 2個 | ❌ 不要 |
| 3個（`"""`） | ✅ 必要（閉じ区切り文字と衝突するため） |

---

## インデント除去のルール：基準になるのは「一番浅い行」

テキストブロックは、各行の**共通する左側の余白（インデント）**を自動的に取り除く。この時の基準は「**開いた`"""`の直後の位置**」ではなく、**「本文の各行」＋「閉じの`"""`が単独で書かれている行」を全部並べた中で、一番浅い（左端に近い）行**。

## 検証コード

```java
String str = """
 A
     B
         C
        """;
```
（それぞれの行の先頭スペース数：`A`=17、`B`=21、`C`=25、閉じの`"""`=16）

出力（`_`は半角スペース）：
```
_A
_____B
_________C
```

- 閉じの`"""`（16スペース）が、本文（17・21・25スペース）より**浅い**ので、これが基準になる
- `A`は基準より1つ深い→出力は1スペース
- `B`は基準より5つ深い→出力は5スペース
- `C`は基準より9つ深い→出力は9スペース

→ 検証済み。「開いた`"""`のすぐ下から数える」のではなく、「本文＋閉じ行の中で一番浅い行」が基準、という点が核心。

## まとめ（インデント除去）

- 基準（除去される共通インデント量）は、**本文の各行と、閉じの`"""`の行を全部含めた中での最小インデント**によって決まる
- 開いている`String str = """`の行自体は（続きの文字が無ければ）計算に参加しない
- 閉じの`"""`をわざと浅い位置に置けば、本文全体をより深くインデントされたまま残せる（閉じ位置を動かすことで、出力される文字列の見た目のインデントを調整できる）
