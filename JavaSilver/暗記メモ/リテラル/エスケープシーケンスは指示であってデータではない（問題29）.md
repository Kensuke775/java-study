# エスケープシーケンス（`\"`など）は「指示」であって「データ」ではない

## 検証コード

```java
String s = "\"";
System.out.println("中身: [" + s + "]");
System.out.println("文字数: " + s.length());
```
```
中身: ["]
文字数: 1
```
→ 検証済み。ソースコード上は`\`と`"`の2文字書かれているが、実際にできる文字列の中身は`"`（1文字）だけ。

## なぜ「2文字書いて1文字になる」のか

**「ソースコードに書く文字数」と「実行時にできる文字列の中身の文字数」は別物。**

`\`（バックスラッシュ）は、それ自体が文字列の中身になる文字ではない。**「次の1文字を、特別な意味で解釈してください」とコンパイラに指示するための記号（エスケープ文字）**。`\"`を見たコンパイラは「これから来る`"`は、文字列の終わりを示す記号ではなく、文字列の中身としての`"`だよ」と解釈し、指示を実行し終わったら`\`という記号は消えて、指示された結果（`"`という1文字）だけが残る。

`\`は「データ」ではなく「指示」。指示自体は結果に残らず、指示された対象の文字だけが残る。

## `"\"" + value + "\""`の読み方（問題29：super.setValue("¥"" + value + "¥"");）

`"\""`は3パーツに分解できる。

1. 最初の`"` → 文字列リテラルの**開始**
2. `\"` → 中身として**`"`という1文字**を表す（エスケープ）
3. 最後の`"` → 文字列リテラルの**終了**

結果、この文字列の中身は`"`（1文字）だけ。`"\"" + value + "\""`は「`"` + `value`の中身 + `"`」という連結になり、`value`を前後からダブルクォートで挟んだ文字列ができる。

（原本では`\`が日本語フォントで`¥`と表示されているだけで、実体はバックスラッシュ）

## 通常の文字列リテラルとテキストブロックでエスケープの発動条件が違う

| | 通常の文字列リテラル（`"..."`） | テキストブロック（`"""..."""`） |
|---|---|---|
| `"`を1個だけ含めたい | エスケープ必須（`\"`） | エスケープ不要（そのまま`"`でOK） |
| `"`を2個連続で含めたい | エスケープ必須（`\"\"`） | エスケープ不要（そのまま`""`でOK） |
| `"`を3個連続で含めたい | エスケープ必須 | エスケープ必須（閉じの区切り文字と紛らわしくなるため） |

通常の`"..."`の中では、`"`を1文字でも含めたい場合、連続数に関わらず**常にエスケープが必須**（[[ダブルクォーテーションとインデント除去のルール]]のテキストブロックの緩いルールとは別物）。

## 同じ`"\""`が、前と後ろに2回出てくる理由（問題29）

`"\"" + value + "\""`の1つ目の`"\""`も、2つ目の`"\""`も、中身は`"`（1文字）で、**全く同じ文字列**。位置が違うだけで、前が「開き引用符」、後ろが「閉じ引用符」の役目になる。

```java
String first  = "\"";   // 1つ目
String second = "\"";   // 2つ目
// first.equals(second) → true（どちらも長さ1、文字コード34）
```
→ 検証済み。

```
"\""   +   value   +   "\""
 ↓                       ↓
  "     +   A B C    +    "     →   "A B C "
（前の引用符＝開き）         （後ろの引用符＝閉じ）
```

問題29を`java Sample A B C`で実行すると、`"A B C "`と出力される。`for`で各要素の後ろに空白を付けているので、末尾の空白も引用符の中に入る。→ 検証済み。

## `+`でつなげば、値の左右に好きな文字列を足せる

```java
String value = "value";
System.out.println("\"" + value + "\"");   // "value"
System.out.println("[" + value + "]");     // [value]
System.out.println("<<" + value + ">>");   // <<value>>
```
→ 検証済み。`"\""`は「足す文字列」の1つで、引用符1文字。引用符はそのまま`"`と書くと文字列の区切りと区別がつかないので、エスケープして書く。

書き間違いの例（`value`が2回入る）：

```java
System.out.println("\"value\"");                    // "value"
System.out.println("\"" + "value" + "value\"");     // "valuevalue"（3つ目にも value が入っている）
```
→ 検証済み。

## `\`（バックスラッシュ）と`¥`（円記号）：見た目が同じでも、別の文字のことがある

- `\`は文字コード`0x5C`（U+005C）。日本語のフォント・環境では、この文字が`¥`の形で表示されることがある。教科書や試験画面の`"¥""`は、この表示の違い（中身はバックスラッシュ）。
- 一方、**本物の円記号は別の文字**（U+00A5、文字コード165）。Javaにとってはただの文字で、エスケープにならない。

| 文字 | 文字コード | `"X?nY"`と書くと |
|---|---|---|
| バックスラッシュ（U+005C） | 92（16進 5c） | `n`と合わさって改行（長さ3、改行を含む） |
| 円記号（U+00A5） | 165（16進 a5） | ただの文字`¥n`（長さ4、改行を含まない） |

円記号（U+00A5）で`"¥""`と書くと、エスケープにならず、「文字列リテラルが閉じられていません」というコンパイルエラーになる。→ すべて検証済み。

## まとめ

- `\`は文字列データの一部として保存されない。「次の文字を特別扱いしてください」という**コンパイラへの指示記号**
- `\"`は「見た目2文字、中身1文字」になる。ソースコード上の文字数と実行時の文字列の中身の文字数は別
- 通常の文字列リテラルは`"`を1個含めるだけでも常にエスケープ必須。テキストブロックは1〜2個までエスケープ不要（3個以上で必須）という、緩さの違いがある
- `"\"" + value + "\""`の前後の`"\""`は、同じ「`"`1文字の文字列」。位置で開き・閉じの役目になる。`+`でつなげば、値の左右に好きな文字列を足せる
- 教科書・試験画面の`¥`はバックスラッシュ（U+005C）の表示。本物の円記号（U+00A5）はエスケープにならない
