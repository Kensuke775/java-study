# 配列のサイズ指定にdouble（小数）は使えない

## 検証コード

```java
int[] a = new int[2.3];
```
```
エラー: 不適合な型: 精度が失われる可能性があるdoubleからintへの変換
```
→ 検証済み。コンパイルエラー。

## ポイント：配列サイズは`int`型でなければならない

配列のサイズ指定（`new 型[サイズ]`の`サイズ`部分）には**`int`型の値**が必要。`2.3`のような小数リテラルは`double`型なので、`int`より精度が落ちる方向の変換（ナローイング）になり、暗黙の変換は許されない。これは`2.0`のような「整数に見える値」でも同様（値の中身ではなく、**型そのもの**が`double`である時点でアウト）。

## キャストすれば通る（ただし小数部分は切り捨て）

```java
double size = 2.3;
int[] a = new int[(int) size];
System.out.println(a.length);   // → 2
```
→ 検証済み。`(int)`キャストで明示的に変換すれば通る。この時、小数部分は四捨五入ではなく**単純に切り捨てられる**（`2.3`→`2`、`2.9`でも`2`になる）。

## まとめ

- 配列サイズには`int`（または`int`にキャスト可能な整数値）が必要
- `double`のような小数は、たとえ見た目が整数でもそのままでは使えず、明示的な`(int)`キャストが必須
- キャストした場合、小数部分は切り捨て（`Math.round`のような四捨五入ではない）
