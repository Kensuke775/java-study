# メソッドの曖昧な呼び出し例（オーバーロード解決）

## 基本ルール

オーバーロード解決で「どちらが優先されるか」は、**左右の位置による優先順位ではなく、全引数を1セットとして見た時に、一貫してどちらか一方が優位かどうか**で決まる。

- 全ての引数位置で、一貫してどちらか一方が優位（またはタイ）→ 曖昧にならない、優劣がはっきり付く
- 位置によって優劣の向きが逆転する（**ねじれ**）→ あいまいエラーになる

## 検証1：ねじれが無い例（あいまいにならない）

```java
public void method(double x, int y) { ... }
public void method(long x, int y) { ... }
```
呼び出し：`method(1, 2)`（int, int）

| 候補 | 1番目 | 2番目 |
|---|---|---|
| `method(long, int)` | `int→long`（widening） | 完全一致 |
| `method(double, int)` | `int→double`（widening） | 完全一致 |

→ 実行結果：**`method(long, int)`が呼ばれる**（あいまいエラーにならない）

理由：1番目も2番目も、**どちらの位置でも`method(long,int)`の方が同等以上に優位**（1番目は`long`が`double`より狭くて勝ち、2番目は引き分け）。一貫して同じ方向に優位なので、迷いようがない。

## 検証2：ねじれがある例（あいまいになる）

```java
public void method(int x, double y) { ... }
public void method(long x, int y) { ... }
```
呼び出し：`method(1, 2)`（int, int）

```
エラー: methodの参照はあいまいです
Mainのメソッド method(int,double)とMainのメソッド method(long,int)の両方が一致します
```

| 候補 | 1番目 | 2番目 |
|---|---|---|
| `method(int, double)` | 完全一致（勝ち） | `int→double`（widening、負け） |
| `method(long, int)` | `int→long`（widening、負け） | 完全一致（勝ち） |

→ **1番目では`method(int,double)`が勝つのに、2番目では逆に`method(long,int)`が勝つ**（ねじれ）。位置によって勝者が入れ替わるため、優劣を付けようとしても矛盾して付けられず、あいまいエラーになる。

## まとめ

- ❌「ワイドニングが複数箇所で起きたらあいまい」→ 不正確（検証1のように、複数箇所でwideningが起きても一貫していれば曖昧にならない）
- ✅「**全ての引数位置を通して、一貫してどちらか一方が優位（またはタイ）であれば曖昧にならない。位置によって優劣の向きが逆転する（ねじれる）場合だけ、あいまいエラーになる**」
- 「優劣が付いたのに、最終的にはあいまいになる」のではなく、「**2候補間で優劣を付けようとしたら、位置ごとに勝者が違って"付けられなかった"**」というのが正確な状態
