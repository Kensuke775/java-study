### 6.3 変更不可のコレクション

**教科書の例(**`chap1/23`**):**

```java
import java.util.List;
import java.util.Map;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        List<Integer> list = List.of(0, 1, 2, 3);
        Set<String> set = Set.of("Zero", "One", "Two");
        Map<Integer, String> map = Map.of(1, "First", 2, "Second");
        System.out.println(list);
        System.out.println(set);
        System.out.println(map);
     // list.add(4);
     // Set<Object> set1 = Set.of(null);
     // Set<String> set2 = Set.of("A", "A");
     // Map<Integer, String> map = Map.of(0, "A", 0, "B");
    }
}
```

実行結果(javacで検証済み):

```
[0, 1, 2, 3]
[Two, One, Zero]
{2=Second, 1=First}
```

コメントアウトされている各行もそれぞれ個別にjavacで検証済み:

- `list.add(4)` → `UnsupportedOperationException`
- `Set.of(null)` → `NullPointerException`
- `Set.of("A", "A")` → `IllegalArgumentException: duplicate element: A`
- `Map.of(0, "A", 0, "B")` → `IllegalArgumentException: duplicate key: 0`

**説明したポイント**

- `List`/`Set`/`Map`の各インタフェースには、要素数0〜10個の`of()`がオーバーロードされた静的メソッドとして用意されている(`Set`/`Map`はさらに可変長引数版の`of()`も別途あり)。これらは「コンストラクタを使わずに、その場でコレクションを生成する」静的ファクトリメソッド。

- `List<E>`: `static <E> List<E> of(E... elements)`。`Set<E>`: `static <E> Set<E> of(E... elements)`。`Map<K,V>`: `static <K,V> Map<K,V> of(K k1, V v1, K k2, V v2, ...)`(キーと値を交互に並べる形)。

- `of()`で生成したコレクションは**イミュータブル(変更不可)**。`add()`/`remove()`/`set()`/`put()`など、中身を変える操作は一切できず、実行するとすべて`UnsupportedOperationException`になる(前セクションの`List.of()`の話と同じ結論)。

- `of()`は`null`要素を一切扱えない。`null`を渡すと(要素として追加しようとした瞬間ではなく)**生成時点**で`NullPointerException`になる。

- `Set`は要素の重複が不可、`Map`はキーの重複が不可、という制約はもともと`HashSet`/`HashMap`などでも成り立っているルールだが、`of()`で生成する場合は重複があると`IllegalArgumentException`がスローされる。通常の`HashSet.add()`のように「黙って無視される(2個目は弾かれるだけ)」のではなく、**例外で強制的に知らされる**という違いがある点に注意。

- `set`の出力順(`[Two, One, Zero]`)は元の挿入順(`Zero, One, Two`)と一致していない。`Set.of()`が返す実装はハッシュベースで、順序を保証しない(実行のたびに順序が変わりうる)。

**セクションの核心**

`of()`は「その場でサクッと作れるが、二度と変更できないコレクション」を生成する静的ファクトリメソッド。用途は「定数的に扱いたいデータ」「うっかり変更されると困るデータ」を安全に受け渡すこと。`Arrays.asList()`(固定サイズだが中身の`set()`は可能)や`new ArrayList<>()`(完全可変)と合わせて、[[List可変性3段階]]として整理すると記憶に残りやすい。

---

**教科書の例(**`chap1/24`**): 変更不可のコレクションを可変にする**

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        List<String> list =
                new ArrayList<>(Arrays.asList("x", "y"));
        list.add("z");
        System.out.println("list : " + list);
        Set<Integer> set =
                new HashSet<>(Set.of(8, 11, 17));
        set.remove(8);
        System.out.println("set  : " + set);
        Map<Integer, String> map =
                new HashMap<>(Map.of(1, "First", 2, "Second"));
        map.put(3, "Third");
        System.out.println("map  : " + map);
    }
}
```

実行結果(javacで検証済み):

```
list : [x, y, z]
set  : [17, 11]
map  : {1=First, 2=Second, 3=Third}
```

**説明したポイント**

- `Arrays.asList()`や`Set.of()`/`Map.of()`のような「変更不可、または部分的にしか変更できない」コレクションであっても、それを**コンストラクタの引数として渡して新しいコレクションを作れば**、その新しいコレクション自体は完全に可変になる。

- `Arrays.asList("x","y")`(固定サイズ)をそのまま使わず、`new ArrayList<>(...)`のコンストラクタに渡している。これにより中身をコピーした**別の、完全可変な`ArrayList`**が作られるため、`add("z")`が問題なく成功する。

- `set`/`map`も同じパターン: `Set.of(...)`/`Map.of(...)`(イミュータブル)を`new HashSet<>(...)`/`new HashMap<>(...)`のコンストラクタに渡すことで、可変な`HashSet`/`HashMap`としてコピーし直している。

- ポイントは「元のコレクション(`Arrays.asList()`の結果や`of()`の結果)自体が可変になるわけではない」こと。あくまで**コンストラクタが中身をコピーして全く新しいコレクションを作る**ため、元のコレクションはそのままで、コピー先だけが自由に変更できる。

**セクションの核心(教科書の「ポイント」まとめ、そのまま踏襲)**

- コンストラクタを使用して生成したコレクションは変更可能
- `of()`で生成したコレクションは変更不可
- `Arrays.asList()`で生成したリストは、固定サイズ(管理する要素の変更(`set()`)は可、リストのサイズ変更(`add()`/`remove()`)は不可)

## 演習問題

<a id="問題23-1"></a>
### 問題23-1

```java
1  import java.util.List;
2
3  public class Main {
4      public static void main(String[] args) {
5          StringBuilder sb = new StringBuilder("A");
6          List<StringBuilder> list = List.of(sb);
7          list.get(0).append("B");
8          System.out.println(list);
9      }
10 }
```

7行目を実行するとどうなるか。

A. `[AB]`と出力される

B. 7行目で`UnsupportedOperationException`がスローされる

C. 6行目でコンパイルエラーになる

D. 7行目で`ClassCastException`がスローされる

**実施記録**




迷ったポイント: `List.of()`が「変更操作を一切禁止する」ことから、リストが保持しているオブジェクト自体への変更操作(`append()`)も一律にブロックされると誤って推測した。




解説(概念): `List.of()`の不変性は、あくまで**リストという入れ物の構造**(要素の追加・削除・置き換え)に対してのみ働く。`list.get(0)`は単に保持している`StringBuilder`への**参照**を返しているだけで、その先の`StringBuilder`オブジェクト自体は普通に可変なまま。`append()`は`StringBuilder`自身のメソッドであり、`List`の変更操作(`add`/`remove`/`set`)とは無関係なので、何の制約も受けずに実行できる。結果、`list`が参照している`StringBuilder`の中身が書き換わり、出力は`[AB]`になる。「`of()`の不変性は浅い(shallow)」という点がこの問題の核心。




正解: A




あなたの回答: B

<a id="問題23-2"></a>
### 問題23-2

```java
1  import java.util.Map;
2
3  public class Main {
4      public static void main(String[] args) {
5          Map<String, Integer> map = Map.of("A", 1, "B", 2, "C");
6          System.out.println(map);
7      }
8  }
```

5行目を実行するとどうなるか。

A. `{A=1, B=2, C=null}`と出力される

B. 5行目で`IllegalArgumentException`がスローされる

C. 5行目でコンパイルエラーになる

D. 5行目で`ArrayIndexOutOfBoundsException`がスローされる

**実施記録**




迷ったポイント: なし(一発正解)。




解説(概念): `Map.of()`は`List.of()`/`Set.of()`と違い、**可変長引数(`E...`)のオーバーロードを持たない**。用意されているのは`of()`(0個)から`of(K,V,K,V,...)`(10ペア=20引数)までの**固定引数個数のオーバーロード**のみ。今回の5引数はどのオーバーロードの引数個数にも一致しないため、コンパイルエラーになる。`List.of()`/`Set.of()`が可変長引数で「引数の個数が自由」なのとは対照的な点がひっかけ。




正解: C




あなたの回答: C

**疑問**:

- `of()`で作った`List`の中身も参照型? → はい。ジェネリクスは元々プリミティブ型不可なので、`List`は常に参照型のみ。

- `of()`で作った要素を別の変数へ参照コピーできる? → できる。ただの代入なら同一インスタンス共有、`new ArrayList<>(of(...))`ならコピーされた別の可変コレクションになる(要素自体は共有=浅いコピー)。

- `Set`/`Map`はクラス? インターフェース? → インターフェース(`List`と同様)。実装は`HashSet`/`TreeSet`、`HashMap`/`TreeMap`など。

- `Map.of()`に`put()`できる? → できない。`add`/`remove`/`set`と同じく`UnsupportedOperationException`(検証済み)。

- 不変にしたいだけなら`List`で済むのでは? → `Map`はキーで直接値を引く(高速検索)構造、`Set`は重複なし+高速な存在チェックが目的。`of()`(不変化)とList/Set/Mapの選択(データ構造)は別軸。

- `of()`は逐次追加できないので一括生成しかない? → その通り。逐次組み立てたい場合は可変コレクションに`add()`した後`copyOf()`で不変化する。
