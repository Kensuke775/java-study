# 2.1.4 DevOps とテスト 練習問題

## 要点

- **DevOps** ＝ Dev（Development：開発、テストを含む）＋ Ops（Operations：運用）。開発と運用が**連携**して共通のゴールを目指す
- 定義の例：「高品質を保ちつつ、変更をコミットしてから本番に組み込まれるまでの時間を短縮する一連の実践」
- 技術だけでなく、**組織内文化の転換**と**チームの自律性**も必要

### 代表的な技術


| 用語              | 英語                                   | 中身                                                                |
| --------------- | ------------------------------------ | ----------------------------------------------------------------- |
| **CI**          | Continuous Integration（継続的インテグレーション） | 開発者がソースコードを共有リポジトリに**頻繁に統合**し、**ビルドやテストを自動実行**して、コンフリクトや欠陥を早く見つける |
| **CD**          | Continuous Delivery（継続的デリバリー）        | ビルド・テスト・リリースを継続的に行い、変更を安全・効率的に本番へ届ける                              |
| **デリバリーパイプライン** | —                                    | 開発・ビルド・テスト・リリースを自動化する一連の手順やツールの流れ                                 |


### テストから見た DevOps の利点

- コード品質や、変更が既存コードに悪影響を与えるかの**迅速なフィードバック**
- CI で静的解析やコンポーネントテストが自動実行される → 開発者が高品質なコードを出すようになる → **シフトレフトを促進**
- **安定したテスト環境**の構築を助ける（CI/CD などの自動化）
- 運用からのフィードバックで、**非機能品質特性**（性能・信頼性など）の観点が増える
- 自動化で**手動テストを繰り返す必要が減る**
- 自動テストが増え、**リグレッションテストの規模と範囲**を広げられる → リグレッションを見逃すリスクが減る



### DevOps のリスク・課題

- **デリバリーパイプライン**を定義・確立する必要がある
- **CI/CD ツール**を導入・保守する必要がある
- **テスト自動化**を確立・保守する必要があり、**追加のリソース**（テスト自動化エンジニアなど）が要る

> [!IMPORTANT]
> 自動化が前提でも、**ユーザー視点のテストなど、手動テストは依然として必要**。



## 問題2-14（CI）

継続的インテグレーション（CI）の説明として、最も適切なものはどれか。

- a. リリース直前に、すべての変更を一度にまとめて統合する
- b. 開発者がソースコードを共有リポジトリに頻繁に統合し、ビルドやテストを自動実行して欠陥を早く見つける
- c. 運用担当者だけが本番環境を管理する
- d. テストを手動で月に1回まとめて実行する

b



## 問題2-15（DevOps の利点）

テストをする観点から見た DevOps の利点として、**適切ではない**ものはどれか。

- a. 変更が既存のコードに悪影響を与えるかについて、迅速なフィードバックが得られる
- b. CI により、テストのシフトレフトが促進される
- c. 自動化が進むので、ユーザー視点のテストも含めて手動テストがまったく不要になる
- d. 自動化したリグレッションテストの規模と範囲を広げられる

c

## 問題2-16（DevOps のリスク・課題）

DevOps のリスクや課題として、最も適切なものはどれか。

- a. 開発と運用が対立しやすくなる
- b. テストを早い段階で行えなくなる
- c. 非機能品質特性への観点が減る
- d. デリバリーパイプラインの確立、CI/CD ツールの導入と保守、テスト自動化の確立と保守が必要で、追加のリソースが要る

d
