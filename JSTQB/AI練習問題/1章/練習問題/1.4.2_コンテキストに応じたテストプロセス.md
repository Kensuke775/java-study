# 1.4.2 コンテキストに応じたテストプロセス 練習問題

## 要点

- 7つの活動を「いつ・どの組み合わせで」行うかは、組織の体制やプロジェクトの状況（**コンテキスト**）で変わる
- 組織ごとのテストの進め方の基本的な考え方は、**テスト計画**にまとめておく → 首尾一貫したテストプロセスになる

### テストの方法に影響を与えるコンテキストの要因（8つ）

| 要因 | 中身の例 |
| --- | --- |
| ステークホルダー | ニーズ、期待、要件、協力の意思 |
| チームメンバー | スキル、知識、経験レベル、空き状況、トレーニングの必要性 |
| ビジネスドメイン | テスト対象の重要性、識別したリスク、市場ニーズ、特定の法的規制 |
| 技術的要因 | ソフトウェアの種類、プロダクトのアーキテクチャー、利用技術 |
| プロジェクトの制約 | スコープ、時間、予算、リソース |
| 組織的要因 | 組織構造、現行のポリシー、使用する実践例（例：PMBOKのような標準的なマネジメント手法を自組織に合わせて使うか） |
| ソフトウェア開発ライフサイクル | エンジニアリングの実践例、開発手法 |
| ツール | 利用可能な状況、使用性、標準適合性 |

これらの要因は、テストプロセスだけでなく、テスト技法、テスト自動化のツールや環境、カバレッジ基準、テストドキュメントの詳細度など、幅広いテスト活動に影響する。

## 問題1-23（1.4.2）

テストを行う方法に影響を与えるコンテキストの要因として、シラバスに挙げられていないものはどれか。

- a. ツール
- b. チームメンバー
- c. テスト担当者個人の好み
- d. ビジネスドメイン

### 実施記録

- 回答：d
- 正解：c
- 解説：8つの要因は、ステークホルダー、チームメンバー、ビジネスドメイン、技術的要因、プロジェクトの制約、組織的要因、SDLC、ツール。ビジネスドメインは「テスト対象の重要性、リスク、市場ニーズ、法的規制」で、8つに入っている。個人の好みは入っていない。

## 問題1-24（1.4.2）

「テスト対象の重要性、識別したリスク、市場ニーズ、特定の法的規制」は、どのコンテキストの要因にあたるか。

- a. ビジネスドメイン
- b. 技術的要因
- c. 組織的要因
- d. プロジェクトの制約

### 実施記録

- 回答：a
- 正解：a
- 解説：テスト対象の重要性、識別したリスク、市場ニーズ、特定の法的規制はビジネスドメインの要因。

## 問題1-25（1.4.2）

組織ごとのテスト活動の進め方の基本的な考え方をとりまとめ、首尾一貫したテストプロセスを可能にするものはどれか。

- a. テスト完了レポート
- b. 欠陥レポート
- c. テストプロシジャー
- d. テスト計画

### 実施記録

- 回答：d
- 正解：d
- 解説：組織ごとのテスト活動の進め方の基本的な考え方はテスト計画にまとめる。それにより首尾一貫したテストプロセスになる。

## 疑問

- シーケンシャル開発モデルって何？ -> 要件定義 → 設計 → 実装 → テストのように、工程を1つずつ順番に終わらせて次へ進む開発の進め方（sequential ＝ 順番の）。代表はウォーターフォールモデルとV字モデル。前の工程に戻りにくく、動くものができるのは後半なので、動的テストは後半になる（前半はレビューなどの静的テストで関わる）。対になるのは、短い期間で設計〜テストを繰り返すイテレーティブ／インクリメンタル開発（アジャイルなど）。どのモデルを使うかはテストプロセスに影響する（コンテキストの要因「SDLC」）。詳しくは2章。
- ウォーターフォールとシーケンシャルは同じ意味？ -> 同じではない。シーケンシャル開発モデルは「順番に進める型」のグループ名で、ウォーターフォールはその中の1つ（V字モデルもシーケンシャル）。ウォーターフォール ⊂ シーケンシャル。試験では「シーケンシャル開発モデル（例：ウォーターフォールモデル、V字モデル）」の形で出る。
