# 1.4.1 テスト活動とタスク 練習問題

## 要点

テストプロセスは7つの活動でできています。

- 順番どおりに進めることもあれば、**並行して進める**こともある
- アジャイルでは、**イテレーションごとに7つを一通り回す**こともある
- プロジェクトの状況に合わせて、プロセスを調整（**テーラリング**）する

### 7つの活動

| 活動 | 一言で | 主な中身 |
| --- | --- | --- |
| テスト計画 | 目的を決める | **最初にテスト目的を明らかにする**。目的は状況で変わる（納期優先なら最低限の機能確認が目的になる）。テストレベルごとにも違う |
| モニタリングとコントロール | 進捗を見て手を打つ | モニタリングがないと、目的どおりに進んでいるか**客観的に分からない**。終了基準の判断につながる |
| テスト分析 | **何を**テストするか | テストベース（要件・設計書など）を集め、**テスト条件**を決める。リスクを洗い出してリスクレベルを付ける。**カバレッジ基準**も決める |
| テスト設計 | **どのように**テストするか | テスト条件から**テストケース**を作る。**カバレッジアイテム**を識別する。テストデータとテスト環境を設計する |
| テスト実装 | 実行の準備 | テストケースを**テストプロシジャー**（実行順）、テストスクリプト、テストデータに落とし込む。テスト環境を構築する |
| テスト実行 | 実行して比べる | 実行結果と期待結果を比べて記録する。不合格なら不正を分析し、欠陥レポートを書く |
| テスト完了 | 締めくくり | 終了基準を満たしたか評価し、後片付けとふりかえりをする |

### 用語

- **テスト条件**：テストできる箇所。ざっくり（「画面Aの機能性」）も具体的（「画面Aで、1桁足りないアカウント番号を拒否する」）もある
- **カバレッジアイテム**：テスト条件から導いた、テストで網羅すべき項目。多くはテスト技法で見つける（4章）
- **テストプロシジャー**：テストケースを実行する順番と手順

### テスト実行の結果の記録（3種類）

| 結果 | 意味 |
| --- | --- |
| 合格 | 期待結果と一致した |
| 不合格 | 一致しなかった → 欠陥レポートを書く |
| **ブロック** | 実行できない。前のテストケースが同じ手順で不合格になっていて結果が分かっている、または外部要因（ライセンス購入待ち、装置の順番待ちなど）で阻まれている |

記録には、テスト環境（OS・構成・ツールのバージョンなど）やテストウェアのIDも**エビデンス**として残します。

### テスト完了の活動（4つ）

1. **未解決の欠陥への対応**：解決済みはクローズ。次のテストレベルに引き継ぐか、プロダクトバックログアイテムとして記録する
2. **テスト完了レポートの作成**：終了してよいかの判定をステークホルダーに報告する
3. **テスト環境を合意した状態でシャットダウン**：維持費（電気代・クラウド料金）がかかるため、必要な分だけ残して止める
4. **テストウェアの保管と引き渡し**：再利用できるように整理し、保守部門などに引き渡す

そのあと**ふりかえり**で良かった点・悪かった点を話し合い、プロセス改善につなげる。

## 問題1-5（1.4.1）

テストベースを分析してテスト条件を明らかにし、「何をテストするか」を決め、カバレッジ基準を設ける活動はどれか。

- a. テスト計画
- b. テスト分析
- c. テスト設計
- d. テスト実装

### 実施記録

- 回答：b
- 正解：b
- 解説：「何を」テストするかを決めるのがテスト分析、「どのように」テストするか（テストケース作成）がテスト設計。テスト計画は目的を決め、テスト実装は実行の準備をする。

## 問題1-6（1.4.1）

テスト実行中、あるテストケースが不合格になった。後続のテストケースの中に、その不合格になった手順を含んでいるため、実行しても不合格になることが分かっているものがある。このテストケースの結果は何として記録するのが適切か。

- a. 合格
- b. 不合格
- c. ブロック
- d. 偽陰性

### 実施記録

- 回答：c
- 正解：c
- 解説：実行できない、または結果が分かっていて実行する意味がない状態はブロック。ライセンス購入待ちや装置の順番待ちなど外部要因で実行できない場合もブロック。

## 問題1-7（1.4.1 テスト計画）

テスト計画の策定で、最初に明らかにしなければならないものはどれか。

- a. テスト環境
- b. テストケース
- c. テストデータ
- d. テスト目的

### 実施記録

- 回答：d
- 正解：d
- 解説：テスト計画ではまずテスト目的を明らかにする。目的は納期やプロダクトの存在理由などのコンテキストで変わり、テストレベルごとにも違う。

## 問題1-8（1.4.1 モニタリングとコントロール）

テストのモニタリングを行わない場合に起きる問題として、最も適切なものはどれか。

- a. テスト活動がテスト目的に沿って進んでいるかを、客観的に判断できない
- b. テストベースからテスト条件を識別できない
- c. テスト環境を構築できない
- d. 見つかった欠陥を修正できない

### 実施記録

- 回答：a
- 正解：a
- 解説：モニタリングは進捗を把握する活動。これがないと目的どおりに進んでいるか客観的に分からず、終了基準の判断もできない。

## 問題1-9（1.4.1 テスト設計）

テスト設計の活動として、最も適切なものはどれか。

- a. テストベースを集め、テスト可能なフィーチャーとテスト条件を識別する
- b. テスト条件からカバレッジアイテムを識別し、テストデータやテスト環境を設計する
- c. テストケースを実行する順番に並べ、テストプロシジャーを作る
- d. 不合格になったテストケースの不正を分析し、欠陥レポートを書く

### 実施記録

- 回答：c
- 正解：b
- 解説：テストプロシジャー（実行順と手順）を作るのはテスト実装。設計は「どのように」テストするかを考える段階で、テストケース・カバレッジアイテム・テストデータ・テスト環境を「設計」する。実装はそれを実際に「作る・組み立てる」段階。a は分析、d は実行。

## 問題1-10（1.4.1 テスト実装）

テスト実装の活動として、最も適切なものはどれか。

- a. テストの目的と終了基準を定義する
- b. 実行結果を期待結果と比較し、結果を記録する
- c. テストプロシジャーとテストデータを作成し、テスト環境を構築する
- d. ステークホルダー全員でふりかえりを行う

### 実施記録

- 回答：c
- 正解：c
- 解説：実装は実行の準備。テストプロシジャー・テストスクリプト・テストデータを作り、テスト環境を構築する。a は計画、b は実行、d は完了。

## 問題1-11（1.4.1 テスト完了）

テスト完了の活動として、適切ではないものはどれか。

- a. 未解決の欠陥レポートを、次のテストレベルに引き継ぐ
- b. テスト環境を、合意した状態でシャットダウンする
- c. テストウェア一式を保守部門に引き渡す
- d. 新しいテストケースを設計し、追加でテストを実行する

### 実施記録

- 回答：b
- 正解：d
- 解説：テスト完了の4つの活動は「未解決の欠陥への対応」「テスト完了レポートの作成」「テスト環境を合意した状態でシャットダウン」「テストウェアの保管と引き渡し」。環境は維持費（電気代・クラウド料金）がかかるので、必要な分だけ残して止める。新しくテストを設計・実行するのは完了ではなく設計と実行の活動。

## 疑問

- テストプロシジャーって何？ -> テストケースを「どの順番で、どんな手順で」実行するかを決めたもの。テスト実装で作る。例：ログインのテストケース → 商品をカートに入れるテストケース → 購入のテストケース、のように前のテストの結果を次で使える順に並べ、準備や後片付けも含める。優先度順が基本だが、依存関係や段取りで順番が変わることもある。テストスイートは、テストプロシジャーやテストスクリプトをまとめたもの。
