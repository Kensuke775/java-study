# 1.4.3 テストウェア 練習問題

## 要点

- **テストウェア** ＝ テストの7つの活動で作られる作業成果物
- どの成果物を・いつ・どう作るか、名前の付け方は**組織によって違う**
- 一般的な成果物の参考になる標準：**ISO/IEC/IEEE 29119-3**（テスト文書の標準）
- 成果物の一貫性と整合性は、**構成管理**（5.4）で保つ

### 活動ごとの作業成果物


| 活動            | 作業成果物                                                                         | 補足                                                                                    |
| ------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| テスト計画         | **テスト計画書**、テストスケジュール、**リスクレジスター**、**開始基準と終了基準**                               | リスクレジスター ＝ リスクの一覧（可能性・影響・軽減策つき）。スケジュール・リスクレジスター・基準は、テスト計画書の一部になることが多い                 |
| モニタリングとコントロール | **テスト進捗レポート**（テストステータスレポート）、コントロールのための指示の文書、リスク情報                             | 進捗を示す主な成果物。品質やリソースの問題などリスクに関わる報告は**タイミング（適時性）**が大事                                    |
| テスト分析         | （優先順位を付けた）**テスト条件**、**テストベース内の欠陥の欠陥レポート**                                     | 例：受け入れ基準。テストベース（要件など）の記述不足・矛盾・誤字なども報告する。探索的テストでは**テストチャーター**（カバレッジアイテムなし）が成果物になることもある |
| テスト設計         | （優先順位を付けた）**テストケース**、テストチャーター、**カバレッジアイテム**、**テストデータ要件**、**テスト環境要件**          | 下の「ハイレベル／ローレベル」を参照                                                                    |
| テスト実装         | **テストプロシジャー**、**自動テストスクリプト**、**テストスイート**、**テストデータ**、**テスト実行スケジュール**、**テスト環境** | テストを実行できる状態にするための一式。テスト環境の例：スタブ、ドライバー、シミュレーター、サービス仮想化                                 |
| テスト実行         | **テスト結果記録**、**欠陥レポート**                                                        | 価値のカギは**再現性**（故障を再現・解析できる情報があるか）。テスト結果記録には合否だけでなく、進捗やカバレッジが判断できる情報も入れる                |
| テスト完了         | **テスト完了レポート**、改善のためのアクションアイテム、**教訓**の文書、**変更要求**（プロダクトバックログアイテムなど）            | 次のサイクルへ持ち越すテストケースや欠陥レポート（バックログ）、再利用できるテストデータ・テスト環境も完了時の成果物とみなせる                       |




### ハイレベルとローレベルのテストケース


|        | ハイレベルのテストケース                                                | ローレベルのテストケース               |
| ------ | ----------------------------------------------------------- | -------------------------- |
| 書くこと   | テスト条件を満たすために**どんなテストが必要か**                                  | **具体的な入力値・期待値・実行ステップ・優先度** |
| 書かないこと | 具体的な入力値・期待値                                                 | —                          |
| メリット   | テスト条件に対する過不足を確認できる。仕様変更時にどこを直すか分かる。環境やデータを変えても記述を変えずに再利用できる | そのまま実行できる                  |


- テスト設計仕様を作らず、仕様書をそのまま書き写した入力値・期待値だけのテストケースは、「本当にテスト条件を満たしているか」を**説明しにくい**ので注意



### テストチャーターの違い

- テスト分析の成果物：カバレッジアイテムの**記載がない**テストチャーター
- テスト設計の成果物：カバレッジアイテムの**識別まで行った**テストチャーター



## 問題1-26（テスト計画の作業成果物）

テスト計画の作業成果物として、最も適切なものはどれか。

- a. テストケース
- b. リスクレジスター、開始基準と終了基準
- c. 欠陥レポート
- d. テスト結果記録

### 実施記録

- 回答：d
- 正解：b
- 間違えた部分：テスト結果記録（d）を計画の成果物だと思った。
- 解説：テスト結果記録は**テスト実行**の成果物。テスト計画の成果物は、テスト計画書・テストスケジュール・リスクレジスター・開始基準と終了基準。「計画 ＝ 始める前に決めておくもの」なので、実行した結果は入らない。

## 問題1-27（モニタリングとコントロールの作業成果物）

テストの進捗状況を示す主な作業成果物はどれか。

- a. テストチャーター
- b. テストスイート
- c. テスト進捗レポート
- d. テストデータ

### 実施記録

- 回答：c
- 正解：c
- 解説：進捗を示す主な成果物はテスト進捗レポート（テストステータスレポート）。リスクに関わる報告はタイミングが大事。

## 問題1-28（テスト分析の作業成果物）

テスト分析の作業成果物として、最も適切なものはどれか。

- a. 自動テストスクリプト
- b. テスト実行スケジュール
- c. テスト結果記録
- d. 優先順位を付けたテスト条件と、テストベース内の欠陥についての欠陥レポート

### 実施記録

- 回答：d
- 正解：d
- 解説：テスト分析の成果物は、優先順位を付けたテスト条件と、テストベース内の欠陥レポート。a・b はテスト実装、c はテスト実行。

## 問題1-29（テスト設計の作業成果物）

ハイレベルのテストケースの説明として、最も適切なものはどれか。

- a. テスト条件を満たすためにどのようなテストが必要かを記載し、具体的な入力値や期待値までは記載しない
- b. 具体的な入力値、期待値、実行ステップ、実行の優先度まで記載する
- c. テスト実行した結果の合否と、進捗状況を記録する
- d. 故障を再現するための手順と、期待結果と実際の結果を記載する

### 実施記録

- 回答：b
- 正解：a
- 間違えた部分：入力値・期待値・ステップ・優先度まで書く（b）をハイレベルのテストケースだと思った。ハイレベルとローレベルが逆になっていた。
- 解説：
  - **ハイレベル**：テスト条件を満たすために「どんなテストが必要か」まで。具体的な値は書かない（テスト設計仕様に書く）。仕様変更時に直す範囲が分かり、環境やデータを変えても再利用できる
  - **ローレベル**：入力値・期待値・実行ステップ・優先度まで書く。そのまま実行できる
  - 覚え方：「ハイ ＝ 高い所から見た全体像」「ロー ＝ 地面に近い具体的な手順」

## 問題1-30（テスト実装の作業成果物）

テスト実装の作業成果物として、**適切ではない**ものはどれか。

- a. テストプロシジャー
- b. テストスイート
- c. テスト環境（スタブ、ドライバーなど）
- d. テスト完了レポート

### 実施記録

- 回答：d
- 正解：d
- 解説：テスト完了レポートはテスト完了（途中のマイルストーンならモニタリングとコントロール）の成果物。a・b・c はテスト実装の成果物。

## 問題1-31（テスト実行の作業成果物）

テスト実行の作業成果物（テスト結果記録や欠陥レポート）の価値に最もつながるものはどれか。

- a. 作成者の所属部署が書かれていること
- b. ページ数が多いこと
- c. テスト実行の再現性が確保されていること
- d. テストの実行時間が短いこと

### 実施記録

- 回答：c
- 正解：c
- 解説：テスト結果記録や欠陥レポートの価値は再現性。故障を再現・解析できる情報があることが大事。

## 問題1-32（テスト完了の作業成果物）

テスト完了時の作業成果物としてみなせるものはどれか。

- a. 次のテストレベルで使う新しいテスト条件
- b. 次のサイクルへ持ち越すテストケースや欠陥レポート、再利用できるテストデータやテスト環境
- c. 優先順位を付けたテストケースとカバレッジアイテム
- d. 開始基準とテストスケジュール

### 実施記録

- 回答：b
- 正解：b
- 解説：持ち越すテストケースや欠陥レポート（バックログ）、再利用できるテストデータ・テスト環境も完了時の成果物とみなせる。a は分析、c は設計、d は計画。
